=== intro ===
Days 9 and 10 compared **two** strings. Today there are `n` of them, and the question is what they all share at the start. The new habit is about *which direction you scan* a collection of strings.

> When every string must agree on something position by position, stack them like rows of a grid and read **down the columns**. The first column that disagrees ends the answer - and you never re-check a column you have already passed.

=== problem ===
Given an array of strings `strs`, return the **longest common prefix** - the longest string that every element starts with. If there is none, return `""`.

| strs | answer |
| :--- | :----- |
| `["flower", "flow", "flight"]` | `"fl"` |
| `["dog", "racecar", "car"]` | `""` |

### What the first example means

Write the strings one under another, aligned at the left:

```text
index:    0  1  2  3  4  5
flower    f  l  o  w  e  r
flow      f  l  o  w
flight    f  l  i  g  h  t
```

Column 0 is `f, f, f` - all agree. Column 1 is `l, l, l` - all agree. Column 2 is `o, o, i` - **disagree**. So the common prefix is columns 0 and 1: `"fl"`.

In the second example column 0 is `d, r, c`. They disagree immediately, so the answer is the empty string.

### Two ways a prefix ends

1. **A mismatch.** Some string has a different character in this column (`i` vs `o` above).
2. **A string runs out.** If `strs = ["flower", "flow"]`, column 4 exists in `flower` but not in `flow`. The prefix cannot be longer than the **shortest** string, so a string ending is just as final as a mismatch.

Forgetting the second case is the classic crash in this problem: indexing past the end of a shorter string.

### Constraints that matter

- `1 <= strs.length <= 200`.
- `0 <= strs[i].length <= 200` - **empty strings are allowed**, and any empty string forces the answer to `""`.
- Lowercase English letters only.
- The answer can be no longer than the shortest string.

=== pattern ===
**Vertical Scan** - column-by-column comparison across a set of strings.

The reframe: a common prefix is not a property of any single string. It is a property of each **column** of the grid above. Column `i` belongs to the prefix if every string has a character at index `i` and they are all the same - and the prefix is the run of such columns starting from column 0.

So the scan goes:

```text
for each column i (bounded by the first string):
    c = strs[0][i]
    for each other string s:
        if s has no index i, or s[i] != c  ->  the prefix is strs[0][0..i)
the loop finished  ->  all of strs[0] is the prefix
```

Using the first string as the reference is arbitrary but convenient: the prefix must be a prefix of `strs[0]`, so `strs[0].substring(0, i)` is always the answer the moment column `i` fails.

### Why vertical beats horizontal

The alternative is **horizontal**: compare strings one at a time - find the common prefix of `strs[0]` and `strs[1]`, then of that and `strs[2]`, and so on. It is correct, but if the very last string shares nothing with the rest, it has already done all the work on the first `n - 1` strings. Vertical scanning stops at the **first failing column**, so it never reads past the answer in any string.

### Recognising it

Reach for a vertical scan when:

- several sequences must **agree position by position** from the start
- the answer is "how far do they all match" (common prefix, aligned columns)
- reading one row fully would waste work if another row disagrees early

The mental question:

> Is the answer decided column by column? Then stop at the first column that fails, and the rows do not matter individually.

=== bruteForce ===
Without any insight, try every candidate prefix length and test it against every string.

### Step logic

1. Take candidate lengths `L = 1, 2, 3, ...` up to `strs[0].length()`.
2. For each `L`, the candidate is `strs[0].substring(0, L)`.
3. Check whether **every** other string `startsWith` the candidate.
4. If all do, record `best = L` and try the next length. If any does not, stop - a longer prefix cannot work either.

### Dry run

```text
strs = ["flower", "flow", "flight"]
```

`startsWith` compares characters from index 0 until a difference or the end of the candidate. The table counts those character comparisons.

| L | candidate | string | chars compared | starts with it? | all so far? | best |
| -: | :-------- | :----- | :------------- | :-------------- | :---------- | ---: |
| 1 | `f` | `flow` | `f=f` | yes | yes | - |
| 1 | `f` | `flight` | `f=f` | yes | yes | **1** |
| 2 | `fl` | `flow` | `f=f`, `l=l` | yes | yes | 1 |
| 2 | `fl` | `flight` | `f=f`, `l=l` | yes | yes | **2** |
| 3 | `flo` | `flow` | `f=f`, `l=l`, `o=o` | yes | yes | 2 |
| 3 | `flo` | `flight` | `f=f`, `l=l`, `o` vs `i` | **no** | **no - stop** | 2 |

Result: `strs[0].substring(0, best) = "fl"`. Correct.

Total character comparisons: `2 + 4 + 6 = 12`.

### Java

```java
class Solution {
    public String longestCommonPrefix(String[] strs) {

        if (strs == null || strs.length == 0) {
            return "";
        }

        int best = 0;
        for (int len = 1; len <= strs[0].length(); len++) {

            String candidate = strs[0].substring(0, len);
            boolean allMatch = true;

            for (int j = 1; j < strs.length; j++) {
                if (!strs[j].startsWith(candidate)) {
                    allMatch = false;
                    break;
                }
            }

            if (!allMatch) {
                break;
            }
            best = len;
        }

        return strs[0].substring(0, best);
    }
}
```

`startsWith` handles a shorter string safely: `"flow".startsWith("flowe")` is simply `false`.

### Complexity

**Time:** `O(n * P^2)` - **Space:** `O(P)` per candidate string

`n` is the number of strings and `P` is the length of the common prefix (plus one for the failing step). Each candidate of length `L` costs up to `L` comparisons in each of the `n - 1` other strings, and `1 + 2 + ... + P` is about `P^2 / 2`.

### Where it hurts

Read the "chars compared" column downward for `flight`:

```text
L = 1:  f
L = 2:  f  l
L = 3:  f  l  i
```

`f` was compared against `flight[0]` **three times**. `l` was compared twice. Every new candidate length re-verifies every column that the previous length already proved matches. The same is true for `flow`.

The waste is structural: each candidate length restarts the check from column 0. But once column `i` has matched in every string, it is settled forever - a longer candidate does not change what is in column `i`.

Also, every round allocates a fresh `substring` just to have something to pass to `startsWith`.

> If a column has been checked in every string, never check it again. Advance one column at a time.

=== optimization ===
### The observation

The brute force's candidate of length `L + 1` differs from the candidate of length `L` by exactly **one new column**. Everything else was already verified. So instead of testing whole prefixes, test **one column at a time**, and only the new one.

That is the vertical scan:

- `i` walks the columns of `strs[0]`.
- At each column, `c = strs[0].charAt(i)` is the character every string must have.
- For each other string: if it has ended (`i == strs[j].length()`) or has a different character, the prefix stops here - return `strs[0].substring(0, i)`.
- If every column of `strs[0]` survives, `strs[0]` itself is the prefix.

Each column is checked exactly once per string, and the scan stops at the first failing column.

### Dry run

```text
strs = ["flower", "flow", "flight"]
```

| i | c = strs[0][i] | j | strs[j] | strs[j] has index i? | strs[j][i] | matches? | outcome |
| -: | :-----------: | -: | :------ | :------------------- | :--------: | :------- | :------ |
| 0 | `f` | 1 | `flow` | yes (length 4) | `f` | yes | continue |
| 0 | `f` | 2 | `flight` | yes (length 6) | `f` | yes | column 0 done |
| 1 | `l` | 1 | `flow` | yes | `l` | yes | continue |
| 1 | `l` | 2 | `flight` | yes | `l` | yes | column 1 done |
| 2 | `o` | 1 | `flow` | yes | `o` | yes | continue |
| 2 | `o` | 2 | `flight` | yes | `i` | **no** | **return `strs[0].substring(0, 2)` = `"fl"`** |

Total character comparisons: **6**, against the brute force's 12. Each was a new column, never a repeat.

### When a string runs out instead

```text
strs = ["flower", "flow"]
```

| i | c | j | strs[j] | has index i? | outcome |
| -: | :-: | -: | :------ | :----------- | :------ |
| 0 | `f` | 1 | `flow` | yes, `f` | match |
| 1 | `l` | 1 | `flow` | yes, `l` | match |
| 2 | `o` | 1 | `flow` | yes, `o` | match |
| 3 | `w` | 1 | `flow` | yes, `w` | match |
| 4 | `e` | 1 | `flow` | **no** (`4 == length`) | **return `"flow"`** |

The length check fires *before* `charAt`, which is why it never throws.

### The sort-first alternative

Sort the array lexicographically. The first and last strings are then the two that differ the most, and any column shared by those two is shared by every string between them. So the answer is just the common prefix of `sorted[0]` and `sorted[n - 1]`:

```text
sorted = ["flight", "flow", "flower"]
compare "flight" with "flower":  f=f, l=l, i vs o  ->  "fl"
```

It is elegant, but the sort costs `O(n log n)` string comparisons (each up to `k` characters), which is more than the vertical scan's single pass. Good to mention, not the one to write first.

=== complexity ===
### Time

In the worst case (all strings identical) every column of every string is read once.

```text
O(S)   where S = total number of characters across all strings
```

More precisely, the scan reads at most `n * (P + 1)` characters, where `P` is the answer's length - it never looks beyond the first failing column, no matter how long the strings are.

### Space

A few integer indices. The returned `substring` is the output, not extra space.

```text
O(1) extra
```

### Comparison

| Approach | Time | Extra space | Stops at first bad column? |
| :------- | ---: | ----------: | :------------------------- |
| Every length, `startsWith` each | `O(n * P^2)` | `O(P)` per candidate | yes, but re-checks earlier columns |
| Horizontal (pairwise reduce) | `O(S)` | `O(1)` | no - finishes early strings before seeing a late mismatch |
| Sort, compare first and last | `O(n log n * k)` | `O(1)` to `O(n)` for the sort | after sorting |
| **Vertical scan** | **`O(S)`**, really `O(n * P)` | **`O(1)`** | **yes, each column once** |

`k` is the maximum string length.

=== implementation ===
```java
class Solution {
    public String longestCommonPrefix(String[] strs) {

        if (strs == null || strs.length == 0) {
            return "";
        }

        // Scan column by column, using strs[0] as the reference row.
        for (int i = 0; i < strs[0].length(); i++) {
            char c = strs[0].charAt(i);

            for (int j = 1; j < strs.length; j++) {
                // Column i fails if strs[j] has ended or disagrees.
                if (i == strs[j].length() || strs[j].charAt(i) != c) {
                    return strs[0].substring(0, i);
                }
            }
        }

        // Every column of strs[0] matched everywhere.
        return strs[0];
    }
}
```

### The lines that matter

**1.**

```java
if (i == strs[j].length() || strs[j].charAt(i) != c) {
```

Two failure conditions joined by `||`, in this order. If `strs[j]` has ended, `||` short-circuits and `charAt(i)` is never called - so `["flower", "flow"]` returns `"flow"` instead of throwing `StringIndexOutOfBoundsException`.

**2.**

```java
return strs[0].substring(0, i);
```

`substring(0, i)` is columns `0..i-1` - exactly the columns that passed. Column `i` is the one that just failed and is excluded. If column 0 fails, this returns `""`.

**3.**

```java
return strs[0];
```

Reaching here means `strs[0]` ran out first and every one of its columns matched. That covers `["a", "ab"]` (answer `"a"`) and a single-element array (the inner loop never runs).

### Java notes

- The outer bound is `strs[0].length()`. Using the first string as the reference is fine even when it is not the shortest, because the `i == strs[j].length()` check catches any shorter string.
- `substring` in modern Java (7u6 onwards) copies the characters into a new string. That copy is the return value, so it is output, not overhead.
- The `strs == null || strs.length == 0` guard is outside LeetCode's constraints (`strs.length >= 1`), but it costs nothing and is the first thing an interviewer will ask about.
- A Java `String` is immutable and `charAt` is `O(1)`, so reading columns across many strings is cheap - no need to convert anything to `char[]`.

=== edgeCases ===
### No common prefix

```text
["dog", "racecar", "car"]  ->  ""
```

Column 0 fails at `j = 1` (`r` vs `d`). `substring(0, 0)` is `""`.

### Single string

```text
["alone"]  ->  "alone"
```

The inner loop has no other strings to check, so every column passes and `strs[0]` is returned.

### An empty string anywhere

```text
["", "b"]    ->  ""
["abc", ""]  ->  ""
```

If `strs[0]` is empty, the outer loop never runs and `strs[0]` (`""`) is returned. If a later string is empty, `i == strs[j].length()` is `0 == 0` at column 0.

### First string is longer than another

```text
["ab", "a"]  ->  "a"
```

At column 1, `strs[1]` has ended: `1 == "a".length()`. Returns `"a"` without touching `"a".charAt(1)`.

### First string is the shortest

```text
["a", "ab"]  ->  "a"
```

The outer loop runs out after column 0, every column matched, return `strs[0]`.

### All identical

```text
["abc", "abc", "abc"]  ->  "abc"
```

The worst case for work: every character of every string is read once.

### Whole shorter string is the prefix

```text
["flow", "flower", "flowing"]  ->  "flow"
```

### Mismatch only in the last string

```text
["abcd", "abcd", "abxd"]  ->  "ab"
```

Vertical scan finds it at column 2. A horizontal scan would first fully compare `"abcd"` with `"abcd"` before ever looking at `"abxd"`.

### Empty array

```text
[]  ->  ""
```

Outside LeetCode's constraints; the guard returns `""` before `strs[0]` is touched.

=== takeaway ===
> When you see **"what do all these strings share from the start"**, think **vertical scan**: read column by column, stop at the first column that fails in any string.

### The core observation

Once a column has matched in every string, it is settled - a longer candidate prefix does not change it. So check each column once, in order, and stop at the first failure. The prefix can never be longer than the shortest string, which is why "string ended" is a failure just like "character differs".

### The pattern trigger

```text
            stack the strings as rows, aligned left
                              |
                              v
              for column i = 0, 1, 2, ...
                              |
              every row has index i AND same char?
                    /                    \
                  yes                     no
                   |                       |
             next column         answer = strs[0][0..i)
                              |
           reference row ran out  ->  answer = strs[0]
```

### The common mistakes

**Indexing a shorter string past its end.** `strs[j].charAt(i)` without checking `i == strs[j].length()` first crashes on `["flower", "flow"]`.

**Returning `substring(0, i + 1)`.** That includes the failing column.

**Assuming the first string is the shortest.** It often is not; the per-string length check is what makes `strs[0]` safe to use as the reference anyway.

### What to remember in six months

> Columns, not rows. Settle each position once, and the first failure is the answer.

If the follow-up is "answer many prefix queries over the same set of strings", the column-by-column idea becomes a **Trie**: every node is a column, and the common prefix is the path from the root while each node has exactly one child and is not the end of a word.
