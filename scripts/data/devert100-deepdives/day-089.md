=== intro ===
Yesterday's recurrence **added** two smaller answers, because Climbing Stairs counted ways. Today's recurrence **chooses** between two smaller answers, because House Robber optimises.

> Same shape, different operator. `dp[i]` still looks back two steps - but instead of "how many ways", it asks "which is better: take this one, or skip it?"

The habit today: for any "maximise, with a restriction on neighbours" problem, stand at one element and ask exactly two questions - *what if I take it, what if I skip it* - and let each question point at a smaller version of the same problem.

=== problem ===
Houses stand in a row. `nums[i]` is the money in house `i`. You may rob any set of houses **except two adjacent ones** (adjacent houses share an alarm). Return the maximum money you can take.

```text
nums = [2, 7, 9, 3, 1]   ->   12
```

Rob houses `0`, `2` and `4`: `2 + 9 + 1 = 12`.

### Every legal choice for the example

With 5 houses there are `2^5 = 32` subsets, but only 13 avoid adjacent pairs:

| houses robbed | money | | houses robbed | money |
| :------------ | ----: | :- | :------------ | ----: |
| none | 0 | | {0, 3} | 5 |
| {0} | 2 | | {0, 4} | 3 |
| {1} | 7 | | {1, 3} | 10 |
| {2} | 9 | | {1, 4} | 8 |
| {3} | 3 | | {2, 4} | 10 |
| {4} | 1 | | **{0, 2, 4}** | **12** |
| {0, 2} | 11 | | | |

The best is `{0, 2, 4}` with `12`.

### A second example (LeetCode)

```text
nums = [1, 2, 3, 1]   ->   4      rob houses 0 and 2: 1 + 3
```

### Constraints that matter

- `1 <= nums.length <= 100`, `0 <= nums[i] <= 400`.
- At least one house always exists, so there is always an answer.
- The total is at most `50 * 400 = 20,000` - no overflow worries.
- Money is never negative, so skipping a house never *gains* you anything by itself - but taking it can cost you its neighbours.

### What makes it non-trivial

The obvious greedy ideas all fail:

- **Take the biggest house first.** `[3, 4, 3]`: grabbing `4` blocks both `3`s, giving `4`. The answer is `6`.
- **Take every other house** (all even indices or all odd indices). `[2, 1, 1, 2]`: evens give `3`, odds give `3`. The answer is `4` (houses `0` and `3`) - which skips *two* houses in a row.

A good choice can mean skipping one house or skipping several. The decision at each house depends on what happens later, which is exactly when greedy breaks and DP takes over.

=== pattern ===
**1D Dynamic Programming - the take / skip (pick / not-pick) decision.**

### Why it is DP

Look at the **last house**, `i`. In the best plan for houses `0..i`, house `i` is either robbed or not:

- **Skip house `i`.** Then the best you can do is whatever was best for houses `0..i-1`.
- **Take house `i`.** Then house `i - 1` is forbidden, so you get `nums[i]` plus the best for houses `0..i-2`.

The best plan is whichever of those two is larger:

```text
rob(i) = max( rob(i - 1),  nums[i] + rob(i - 2) )
              \_ skip i _/  \_____ take i _____/
```

That is the same dependency shape as Climbing Stairs - `i` looks back to `i - 1` and `i - 2` - with `max` instead of `+`.

### The four steps

| Step | For House Robber |
| :--- | :--------------- |
| State | `rob(i)` = most money from houses `0..i` only |
| Recurrence | `rob(i) = max(rob(i - 1), nums[i] + rob(i - 2))` |
| Base case | `rob(-1) = 0` (no houses), `rob(0) = nums[0]` |
| Order | `i` from left to right |

### Why the state is "houses `0..i`", not "ending at house `i`"

"Best from the first `i + 1` houses, whether or not `i` is robbed" is what makes the skip option a single lookup. If the state were "best plan that robs house `i`", skipping would need a scan back over every earlier house. Choose the state so the recurrence stays small.

### Recognising it

Reach for take / skip DP when:

- you **choose a subset** of items in a sequence to maximise or minimise something
- the restriction is **local** - neighbours, a cooldown, "no two consecutive"
- greedy counterexamples are easy to build

The mental question:

> Standing at element `i`: if I take it, which earlier answer can I still combine with? If I skip it, which earlier answer do I inherit?

=== bruteForce ===
Pretend you do not know DP. The honest approach is "try every legal combination" - and the cleanest way to try them all is to decide house by house, from the last house backwards: take it or skip it.

### Step logic

`rob(i)` returns the best money from houses `0..i`.

1. If `i < 0`, there are no houses: return `0`.
2. If `i == 0`, there is one house: return `nums[0]`.
3. Otherwise compute both branches - **skip** (`rob(i - 1)`) and **take** (`nums[i] + rob(i - 2)`) - and return the larger.

Each path through this recursion is one legal subset, so it explores all 13 for the example.

### Dry run

`nums = [2, 7, 9, 3, 1]`, call `rob(4)`. Calls listed in the order they start; "result" is filled in when each call returns.

| step | depth | call | computes | result |
| ---: | ----: | :--- | :------- | -----: |
| 1 | 0 | `rob(4)` | max(skip 11, take 1 + 11) | 12 |
| 2 | 1 | `rob(3)` | max(skip 11, take 3 + 7) | 11 |
| 3 | 2 | `rob(2)` | max(skip 7, take 9 + 2) | 11 |
| 4 | 3 | `rob(1)` | max(skip 2, take 7 + 0) | 7 |
| 5 | 4 | `rob(0)` | only house 0 | 2 |
| 6 | 4 | `rob(-1)` | no houses | 0 |
| 7 | 3 | `rob(0)` | only house 0 | 2 |
| 8 | 2 | `rob(1)` | max(skip 2, take 7 + 0) | 7 |
| 9 | 3 | `rob(0)` | only house 0 | 2 |
| 10 | 3 | `rob(-1)` | no houses | 0 |
| 11 | 1 | `rob(2)` | max(skip 7, take 9 + 2) | 11 |
| 12 | 2 | `rob(1)` | max(skip 2, take 7 + 0) | 7 |

### Java

```java
class Solution {
    public int rob(int[] nums) {
        return best(nums, nums.length - 1);
    }

    // Most money from houses 0..i.
    private int best(int[] nums, int i) {
        if (i < 0) {
            return 0;               // no houses left
        }
        if (i == 0) {
            return nums[0];         // one house: take it
        }
        int skip = best(nums, i - 1);
        int take = nums[i] + best(nums, i - 2);
        return Math.max(skip, take);
    }
}
```

### Why it is correct

In the best plan for houses `0..i`, house `i` is either robbed or not - there is no third option. If it is not, the rest of the plan must be the best plan for `0..i-1` (otherwise swap in a better one). If it is, house `i - 1` is excluded and the rest must be the best plan for `0..i-2`. Taking the max of both covers every possibility.

### Complexity

**Time:** `O(2^n)` (about `O(1.618^n)`, the same Fibonacci growth as yesterday) - **Space:** `O(n)` call stack

### Where it hurts

Count each call in the table:

| call | times computed |
| :--- | -------------: |
| `rob(4)` | 1 |
| `rob(3)` | 1 |
| `rob(2)` | 2 |
| `rob(1)` | 3 |
| `rob(0)` | 5 |
| `rob(-1)` | 3 |

`rob(2) = 11` is worked out twice; `rob(1) = 7` three times. The answer to "best from houses `0..2`" does not depend on how you got there - it is a fixed number. The recursion re-derives it every time a branch reaches it.

With 100 houses that is roughly `10^21` calls - far more than could ever finish - to answer only 101 distinct questions. Same diagnosis as Climbing Stairs: few distinct subproblems, asked over and over.

=== optimization ===
**The repeated work:** `rob(i)` for a given `i` is recomputed in every branch that reaches it.

**The key observation:** `rob(i)` depends only on `i` - not on which houses were chosen on the way down. So it has exactly one value, and it only needs to be computed once. And each `rob(i)` reads only `rob(i - 1)` and `rob(i - 2)`.

### Deriving the loop

1. **Memoise:** store `rob(i)` the first time; return it on every later call. 15 calls become 9, and `O(1.618^n)` becomes `O(n)`.
2. **Tabulate:** the memo fills from `i = 0` upward, so fill a `dp[]` array left to right instead.
3. **Compress:** `dp[i]` reads only the two previous cells. Keep two variables.

```text
prev2 = rob(i - 2)        best from houses 0..i-2
prev1 = rob(i - 1)        best from houses 0..i-1

cur   = max(prev1, prev2 + nums[i])
```

Both start at `0` - "no houses yet" - so even house `0` goes through the same formula: `max(0, 0 + nums[0]) = nums[0]`. No separate base case needed.

### Dry run - same example

`nums = [2, 7, 9, 3, 1]`, start `prev2 = 0`, `prev1 = 0`.

| i | nums[i] | prev2 | prev1 | skip = prev1 | take = prev2 + nums[i] | cur = max | prev2 after | prev1 after |
| -: | ------: | ----: | ----: | -----------: | ---------------------: | --------: | ----------: | ----------: |
| 0 | 2 | 0 | 0 | 0 | 0 + 2 = 2 | 2 | 0 | 2 |
| 1 | 7 | 0 | 2 | 2 | 0 + 7 = 7 | 7 | 2 | 7 |
| 2 | 9 | 2 | 7 | 7 | 2 + 9 = 11 | 11 | 7 | 11 |
| 3 | 3 | 7 | 11 | 11 | 7 + 3 = 10 | 11 | 11 | 11 |
| 4 | 1 | 11 | 11 | 11 | 11 + 1 = 12 | **12** | 11 | 12 |

Return `prev1 = 12`.

### Reading the table

- **Row 2:** taking `9` on top of the best for houses `0..0` (`2`) beats keeping `7`. The plan is now `{0, 2}`.
- **Row 3:** taking `3` would give `7 + 3 = 10`, worse than `11`. So house 3 is skipped - and `prev1` stays `11`.
- **Row 4:** the skip at row 3 pays off. `prev2` is now `11` (the plan `{0, 2}`), and `11 + 1 = 12`.

Notice the table never commits to a plan early. Every row keeps the best answer for *each* prefix, so a decision that looked bad at house 3 can be revisited at house 4.

### The tabulated array, for comparison

```text
i        :  0   1   2   3   4
nums     :  2   7   9   3   1
dp[i]    :  2   7  11  11  12
```

`prev1` is just the last cell of this row, and `prev2` the one before it.

=== complexity ===
### Time

One pass over the houses, a constant amount of work each.

```text
O(n)
```

### Space

Two integers, `prev1` and `prev2`.

```text
O(1)
```

### Why

There are `n` distinct subproblems (`rob(0)` to `rob(n - 1)`), each answered once in `O(1)` from two earlier answers. The two-variable version keeps only the answers the next step can still read.

### Comparison

| Approach | Time | Space | 100 houses |
| :------- | ---: | ----: | :--------- |
| All subsets (bitmask) | `O(2^n * n)` | `O(1)` | ~10^30 subsets - impossible |
| Take / skip recursion | `O(1.618^n)` | `O(n)` stack | ~10^21 calls - impossible |
| Memoised recursion | `O(n)` | `O(n)` | 100 subproblems |
| `dp[]` tabulation | `O(n)` | `O(n)` | 100 cells |
| Two variables | **`O(n)`** | **`O(1)`** | 100 steps |

=== implementation ===
```java
class Solution {
    public int rob(int[] nums) {

        int prev2 = 0;   // best from houses 0..i-2
        int prev1 = 0;   // best from houses 0..i-1

        for (int num : nums) {
            int cur = Math.max(prev1, prev2 + num);   // skip vs take
            prev2 = prev1;
            prev1 = cur;
        }

        return prev1;
    }
}
```

### The lines that matter

**1.**

```java
int cur = Math.max(prev1, prev2 + num);   // skip vs take
```

The entire decision. `prev1` is "skip this house and keep the best so far". `prev2 + num` is "take this house, so the previous one must have been left alone".

**2.**

```java
int prev2 = 0;   // best from houses 0..i-2
int prev1 = 0;   // best from houses 0..i-1
```

Starting both at `0` means "before any house, you have nothing". It removes the need for a special case for `nums.length == 1` or `2` - the first two iterations reproduce `rob(0) = nums[0]` and `rob(1) = max(nums[0], nums[1])` on their own.

**3.**

```java
prev2 = prev1;
prev1 = cur;
```

The same slide as yesterday, in the same order: `prev2` takes the old `prev1` before `prev1` is overwritten.

### The tabulated version

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        if (n == 1) {
            return nums[0];
        }
        int[] dp = new int[n];
        dp[0] = nums[0];
        dp[1] = Math.max(nums[0], nums[1]);
        for (int i = 2; i < n; i++) {
            dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i]);
        }
        return dp[n - 1];
    }
}
```

Here the base cases have to be written out, and `n == 1` needs a guard because `dp[1]` would not exist. The two-variable version avoids both by starting from "no houses".

### Java notes

- The enhanced `for (int num : nums)` loop fits because the index is never needed - only the value and the two running answers.
- `Math.max` on two `int`s returns an `int`; no casting. The maximum possible total is `20,000`, so `int` never overflows.

=== edgeCases ===
### One house

```text
[5]  ->  5
```

First iteration: `max(0, 0 + 5) = 5`. Nothing to be adjacent to.

### Two houses

```text
[1, 2]  ->  2
```

Only one of them can be robbed; take the larger. The loop produces `max(1, 0 + 2) = 2`.

### Greedy "biggest first" trap

```text
[3, 4, 3]  ->  6
```

Grabbing the `4` blocks both neighbours and gives `4`. The DP takes houses `0` and `2`: `3 + 3 = 6`.

### Greedy "every other house" trap

```text
[2, 1, 1, 2]  ->  4
```

All even indices give `2 + 1 = 3`; all odd indices give `1 + 2 = 3`. The best plan robs houses `0` and `3`, skipping **two** in a row. The DP rows: `2, 2, 3, 4`.

### LeetCode's first example

```text
[1, 2, 3, 1]  ->  4
```

Houses `0` and `2`: `1 + 3`.

### All zeros

```text
[0, 0, 0]  ->  0
```

Every comparison is `max(0, 0)`. Zero is a legal answer.

### All equal values

```text
[5, 5, 5, 5, 5]  ->  15
[5, 5, 5, 5]     ->  10
```

With an odd count you take indices `0, 2, 4`; with an even count you can only fit `n / 2` houses.

### Largest possible input

```text
100 houses of 400  ->  20000
```

Fifty non-adjacent houses at `400` each. Well inside `int`.

=== takeaway ===
> When you see **"choose elements to maximise a total, but no two adjacent"**, think **take / skip DP: `dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])`**.

### The core observation

The best plan for houses `0..i` either skips house `i` (and is the best plan for `0..i-1`) or takes it (and builds on the best plan for `0..i-2`). That answer depends only on `i`, not on the path that reached it - so it is computed once, and only the last two answers are ever needed.

### The pattern trigger

```text
     pick a subset of a sequence, maximise / minimise a total
                     with a LOCAL restriction
                              |
                              v
               standing at element i, two choices:
                     /                    \
                  SKIP i                 TAKE i
           inherit dp[i - 1]     nums[i] + dp[the last index
                                   still compatible with i]
                     \                    /
                      \__ dp[i] = max __/
```

### The common mistakes

**Trusting a greedy.** "Biggest first" and "alternate houses" both pass the sample and fail `[3, 4, 3]` or `[2, 1, 1, 2]`. If you cannot prove a greedy, build the counterexample before you code it.

**Defining the state as "robbing house `i`".** Then "skip" needs a scan over all earlier houses, and the solution becomes `O(n^2)`. "Best from houses `0..i`" keeps it `O(1)` per step.

**Special-casing tiny inputs.** Starting from `prev1 = prev2 = 0` handles one and two houses automatically. Extra `if`s for `n == 1` are where bugs hide.

### What to remember in six months

> Take / skip is the shape: `dp[i] = best(skip -> dp[i-1], take -> value + dp[compatible])`.

House Robber II (LC 213) is the same loop run twice - once on houses `0..n-2` and once on `1..n-1` - because in a circle the first and last houses are neighbours. Delete and Earn (LC 740) becomes House Robber after bucketing values. And the same take / skip decision, with "compatible" meaning "fits in the remaining capacity", is 0/1 Knapsack on day 93.
