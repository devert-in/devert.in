=== intro ===
Yesterday Dijkstra worked because of one sentence: "walking further cannot make a path cheaper". Today some edges are **negative**, that sentence is false, and the greedy order collapses. What survives is the brute force from day 75 - relax every edge, pass after pass - once you can prove exactly how many passes are enough.

> When you cannot know which node is final, stop trying to pick the right order. Relax everything, and bound the number of rounds by the longest a shortest path can possibly be.

=== problem ===
You are given a **directed**, weighted graph with `V` vertices numbered `0` to `V-1`, as a list `edges[i] = [u, v, w]` (an edge `u -> v` of weight `w`). Weights **may be negative**. Given a source `src`:

- return the shortest distance from `src` to every vertex
- use `10^8` for any vertex that cannot be reached
- if the graph contains a **negative cycle** (reachable from `src`), return `[-1]` instead

This is the GeeksforGeeks practice problem "Distance from the Source (Bellman-Ford Algorithm)", with signature `int[] bellmanFord(int V, int[][] edges, int src)`.

### What a negative cycle does

```text
V = 4, src = 0
edges = [[0,1,4], [1,2,-6], [2,3,5], [3,1,-2]]

answer = [-1]
```

The loop `1 -> 2 -> 3 -> 1` costs `-6 + 5 - 2 = -3`. Every trip round it makes every distance on it 3 smaller, forever. "Shortest distance" has no value, so the problem asks you to detect this and say so.

### Constraints that matter

- `V` up to about `100`, `E` up to `V * (V - 1)`
- weights between roughly `-1000` and `1000`, so sums fit in an `int`
- the unreachable sentinel `10^8` is part of the output format - you must use exactly that value

=== pattern ===
**Bellman-Ford** - single-source shortest path when weights may be negative, with negative-cycle detection.

### Why Dijkstra fails here

```text
0 -> 1  weight 2
0 -> 2  weight 5
2 -> 1  weight -4
```

Dijkstra pops vertex 1 at distance `2` and finalises it - it is the closest unfinished vertex. Then it pops vertex 2 at `5` and finds `5 + (-4) = 1 < 2`. Too late: vertex 1 was declared final. The textbook version answers `dist[1] = 2`; the truth is `1`.

The greedy argument assumed that any route through a further vertex costs more. A negative edge can pay back more than the detour cost. So there is **no safe order** in which to finalise vertices.

### What Bellman-Ford does instead

It does not choose an order. It relaxes **every** edge, in any order, `V - 1` times.

The guarantee comes from counting edges, not from distances:

> After round `i`, `dist[v]` is at most the cost of the cheapest path to `v` that uses **at most `i` edges**.

If there is no negative cycle, every shortest path is **simple** (it never repeats a vertex - repeating one means going round a cycle, and a non-negative cycle cannot help). A simple path in a graph of `V` vertices has at most `V - 1` edges. So `V - 1` rounds are enough for every vertex.

And if after `V - 1` rounds some edge **still** improves a distance, that improvement uses a path of `V` or more edges - which must repeat a vertex, which means it goes around a cycle that makes things cheaper. A negative cycle.

### Recognising it

Reach for Bellman-Ford when:

- edges can be **negative** (debts, refunds, energy gains, exchange-rate logs)
- you need to **detect** a negative cycle (currency arbitrage is the classic disguise)
- the number of **edges** in the path is limited ("at most `K` stops") - then you run exactly `K + 1` rounds

The mental question:

> Can an edge cost be negative, or is the path length in edges capped? Then relax all edges round by round, and let the round number bound the path length.

=== bruteForce ===
Without any theory, the obvious idea is: **try every path** from the source, and keep the cheapest arrival at each vertex.

### Step logic

1. Build an adjacency list.
2. DFS from `src`, carrying the cost of the current path. At each vertex `u`, record `best[u] = min(best[u], cost)`.
3. Keep `onPath[]` so the DFS only follows **simple** paths (no vertex twice). Unmark on the way back so other paths can use the vertex.
4. If an edge `u -> v` leads to a vertex `v` that is **already on the current path**, it closes a cycle. Its total weight is `cost + w - costAt[v]`, where `costAt[v]` is what the path cost when it was at `v`. If that is negative, flag a negative cycle.
5. Return `[-1]` if flagged, otherwise `best`.

Why simple paths are enough: without a negative cycle, the cheapest path to any vertex is simple. And every reachable cycle is closed by some simple path - the DFS enumerates all of them - so step 4 cannot miss one.

### Java

```java
class Solution {
    private List<List<int[]>> graph;
    private int[] best;
    private int[] costAt;          // cost of the current path when it stood on each vertex
    private boolean[] onPath;
    private boolean negativeCycle;

    public int[] bellmanFord(int V, int[][] edges, int src) {

        graph = new ArrayList<>();
        for (int i = 0; i < V; i++) graph.add(new ArrayList<>());
        for (int[] e : edges) graph.get(e[0]).add(new int[] {e[1], e[2]});

        best = new int[V];
        Arrays.fill(best, (int) 1e8);
        costAt = new int[V];
        onPath = new boolean[V];
        negativeCycle = false;

        onPath[src] = true;
        dfs(src, 0);

        return negativeCycle ? new int[] {-1} : best;
    }

    private void dfs(int u, int cost) {

        best[u] = Math.min(best[u], cost);
        costAt[u] = cost;

        for (int[] e : graph.get(u)) {
            int v = e[0], w = e[1];

            if (onPath[v]) {                                  // edge closes a cycle
                if (cost + w - costAt[v] < 0) negativeCycle = true;
                continue;
            }

            onPath[v] = true;
            dfs(v, cost + w);
            onPath[v] = false;
        }
    }
}
```

### Complexity

**Time:** `O(number of simple paths)` - exponential, up to `O(V!)` - **Space:** `O(V + E)`

### Where it hurts

The work is one DFS call per **simple path** from the source. On a complete directed graph, that count is `1 + (V-1) + (V-1)(V-2) + ... + (V-1)!`:

| V | simple paths from the source (DFS calls) |
| -: | ---------------------------------------: |
| 5 | 65 |
| 10 | 986,410 |
| 12 | 108,505,112 |
| 15 | 236,975,164,805 |

`V` goes up to about 100. This is hopeless past `V = 12`.

The waste is visible even in the 5-vertex dry run. Vertex 3 was settled at `7`, then reached again at `6`. In a dense graph, every vertex is reached along a huge number of paths, and the DFS re-explores everything **beyond** it each time - even when the new arrival is more expensive than one already seen.

What we actually need from each vertex is not every path through it but one number: the cheapest cost so far. And paths are made of edges, so:

> Instead of extending one path at a time, can we extend **all** cheapest-known paths by one edge at a time, and stop once no shortest path can be longer?

=== optimization ===
### The key observation

Relaxing **every edge once** extends every cheapest-known path by one more edge. Formally, after round `i`:

```text
dist[v] <= cost of the cheapest path from src to v with at most i edges
```

Round 1 gets every path of 1 edge right. Round 2, relaxing every edge again, extends each of those by one - so every path of up to 2 edges is right. And so on.

Without a negative cycle, every shortest path is simple, so it has at most `V - 1` edges. **`V - 1` rounds are enough**, no matter what order the edges are listed in.

Then one more round decides the cycle question: if any edge can **still** relax, some cheapest path wants `V` edges - it must revisit a vertex - so there is a cycle that lowers the cost. A negative cycle.

### Step logic

1. `dist[src] = 0`, every other `dist = 10^8`.
2. Repeat `V - 1` times: for each edge `u -> v (w)`, if `dist[u]` is not `10^8` and `dist[u] + w < dist[v]`, set `dist[v] = dist[u] + w`.
3. If a whole round changed nothing, stop early - nothing will ever change again.
4. One extra pass over all edges: if any edge still relaxes, return `[-1]`.
5. Otherwise return `dist`.

### Dry run - the negative cycle

```text
V = 4, src = 0

```

| round | e0: 0->1 (4) | e1: 1->2 (-6) | e2: 2->3 (5) | e3: 3->1 (-2) | dist after |
| ----: | :----------- | :------------ | :----------- | :------------ | :--------- |
| start | | | | | 0, INF, INF, INF |
| 1 | 0+4 = 4, update | 4-6 = -2, update | -2+5 = 3, update | 3-2 = 1 < 4, update | 0, 1, -2, 3 |
| 2 | 4, no | 1-6 = -5, update | -5+5 = 0, update | 0-2 = -2, update | 0, -2, -5, 0 |
| 3 | 4, no | -2-6 = -8, update | -8+5 = -3, update | -3-2 = -5, update | 0, -5, -8, -3 |
| check | 4, no | -5-6 = **-11 < -8** | - | - | return `[-1]` |

Every round drops vertices 1, 2 and 3 by exactly `3` - the cycle's weight. The `V - 1 = 3` rounds are used up and an edge still relaxes, so a negative cycle exists.

=== complexity ===
### Time

`V - 1` rounds plus one check, each scanning all `E` edges once.

```text
O(V * E)
```

On a dense graph (`E` close to `V^2`) that is `O(V^3)`. The early exit often cuts it to a few rounds in practice, but the worst case stays `O(V * E)` - the worked example is that worst case.

### Space

One `dist` array. The edge list is the input, and no adjacency list is needed.

```text
O(V)
```

### Comparison

| Approach | Time | Space | Negative edges | Detects negative cycle |
| :------- | ---: | ----: | :------------- | :--------------------- |
| DFS over every simple path | up to `O(V!)` | `O(V + E)` | yes | yes |
| Dijkstra | `O((V + E) log V)` | `O(V + E)` | **no** | no |
| Bellman-Ford | **`O(V * E)`** | **`O(V)`** | yes | yes |

Bellman-Ford is slower than Dijkstra, so it is only the right tool when negative weights or an edge-count limit make Dijkstra unusable. With all weights non-negative, use Dijkstra.

=== implementation ===
```java
class Solution {
    public int[] bellmanFord(int V, int[][] edges, int src) {

        final int INF = (int) 1e8;             // the problem's "unreachable" value
        int[] dist = new int[V];
        Arrays.fill(dist, INF);
        dist[src] = 0;

        // V - 1 rounds: enough for any simple path.
        for (int round = 1; round <= V - 1; round++) {
            boolean changed = false;
            for (int[] e : edges) {
                int u = e[0], v = e[1], w = e[2];
                if (dist[u] == INF) continue;  // cannot relax out of an unreached vertex
                if (dist[u] + w < dist[v]) {
                    dist[v] = dist[u] + w;
                    changed = true;
                }
            }
            if (!changed) break;               // fixed point reached early
        }

        // One more pass: anything that still relaxes sits on or behind a negative cycle.
        for (int[] e : edges) {
            int u = e[0], v = e[1], w = e[2];
            if (dist[u] != INF && dist[u] + w < dist[v]) return new int[] {-1};
        }

        return dist;
    }
}
```

### The lines that matter

**1.**

```java
for (int round = 1; round <= V - 1; round++) {
```

`V - 1` is the maximum number of edges in a simple path. That bound is the entire correctness argument - not a tuning constant.

**2.**

```java
if (dist[u] == INF) continue;  // cannot relax out of an unreached vertex
```

Without it, an unreached vertex with an outgoing negative edge would "improve" its neighbour from `10^8` to `10^8 - 5`, and an unreachable vertex would end up with a distance that is not `10^8`. It also keeps negative cycles that the source cannot reach from being reported.

**3.**

```java
if (dist[u] != INF && dist[u] + w < dist[v]) return new int[] {-1};
```

The `V`-th pass. It uses the same relax condition, but instead of updating it reports. Any edge that still improves after `V - 1` rounds can only do so because of a negative cycle.

**4.**

```java
if (!changed) break;               // fixed point reached early
```

Safe because relaxation only depends on `dist`: if a whole round changed nothing, the next round would see the same values and change nothing either - including the check pass, which then correctly finds no cycle.

### The follow-up: Cheapest Flights Within K Stops (LC 787)

"At most `K` stops" means at most `K + 1` edges. Bellman-Ford's round number already **is** the edge count, so run exactly `K + 1` rounds - with one change:

```java
class Solution {
    public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {

        final int INF = Integer.MAX_VALUE;
        int[] dist = new int[n];
        Arrays.fill(dist, INF);
        dist[src] = 0;

        for (int round = 0; round <= k; round++) {     // k stops = k + 1 edges
            int[] next = dist.clone();                 // read last round, write this one
            for (int[] f : flights) {
                int u = f[0], v = f[1], w = f[2];
                if (dist[u] == INF) continue;
                if (dist[u] + w < next[v]) next[v] = dist[u] + w;
            }
            dist = next;
        }

        return dist[dst] == INF ? -1 : dist[dst];
    }
}
```

The copy is the whole point. Plain Bellman-Ford updates `dist` in place, so in one round an edge can use a value set **earlier in the same round** - a path can grow by several edges per round. That never hurts the `V - 1` bound (it only converges faster), but it breaks "at most `k + 1` edges". With `flights = [[0,1,100],[1,2,100],[0,2,500]]`, `src = 0`, `dst = 2`, `k = 0`, the in-place version relaxes `0 -> 1` and then `1 -> 2` in the same round and answers `200` - a path with one stop. Reading from `dist` and writing to `next` gives the correct `500`.

### Java notes

- `(int) 1e8` - `1e8` is a `double` literal, so it needs the cast. It is the problem's sentinel; do not use `Integer.MAX_VALUE` here, both because the output format demands `10^8` and because `Integer.MAX_VALUE + w` overflows.
- No adjacency list: Bellman-Ford iterates over the edge list directly, which is exactly the input format.
- `new int[] {-1}` is a fresh one-element array - the problem's agreed signal for "negative cycle".

=== edgeCases ===
### The worked example

```text
V = 5, src = 0, edges = [[1,3,2],[4,3,-1],[2,4,1],[1,2,1],[0,1,5]]  ->  [0, 5, 6, 6, 7]
```

### Negative cycle reachable from the source

```text
V = 4, src = 0, edges = [[0,1,4],[1,2,-6],[2,3,5],[3,1,-2]]  ->  [-1]
```

### Unreachable vertex

```text
V = 3, src = 0, edges = [[0,1,2]]  ->  [0, 2, 100000000]
```

Vertex 2 is never relaxed and keeps the sentinel.

### Negative cycle the source cannot reach

```text
V = 4, src = 0, edges = [[0,1,1],[2,3,-5],[3,2,1]]  ->  [0, 1, 100000000, 100000000]
```

The cycle `2 -> 3 -> 2` costs `-4`, but neither vertex is reachable, so the `dist[u] == INF` guard never lets them relax. The distances from `src` are perfectly well defined, so they are returned. (If a problem asks whether the graph has a negative cycle **anywhere**, start every `dist` at `0` instead - equivalent to a virtual source joined to every vertex.)

### Negative edge, no cycle - the Dijkstra-breaker

```text
V = 3, src = 0, edges = [[0,1,2],[0,2,5],[2,1,-4]]  ->  [0, 1, 5]
```

Textbook Dijkstra answers `dist[1] = 2` here. Bellman-Ford gets `1`.

### Negative self-loop

```text
V = 2, src = 0, edges = [[0,1,3],[1,1,-1]]  ->  [-1]
```

A one-edge cycle. `dist[1] + (-1) < dist[1]` is true on every pass, so it is caught.

### Zero-weight cycle

```text
V = 3, src = 0, edges = [[0,1,1],[1,2,0],[2,1,0]]  ->  [0, 1, 1]
```

Going round costs `0`, which never makes anything **strictly** cheaper. The check uses `<`, so this is correctly not a negative cycle.

### Undirected negative edge

```text
V = 2, src = 0, edges = [[0,1,-1],[1,0,-1]]  ->  [-1]
```

An undirected edge with negative weight is two directed edges, and together they form a cycle of weight `-2`. In an undirected graph, **any** negative edge is a negative cycle.

### Single vertex

```text
V = 1, src = 0, edges = []  ->  [0]
```

`V - 1 = 0` rounds, an empty check, and the source's own `0`.

=== takeaway ===
> When you see **negative edge weights**, a request to **detect a negative cycle**, or a **cap on the number of edges** in a path, think **Bellman-Ford**: relax every edge, `V - 1` rounds (or `K + 1`), then one round to check.

### The core observation

After round `i`, every path of at most `i` edges has been accounted for. A shortest path without a negative cycle is simple, so it has at most `V - 1` edges - that bounds the rounds. Anything that still improves afterwards needs a path of `V` edges, which must loop, which means a negative cycle.

### The pattern trigger

```text
        shortest path, single source
                    |
           any negative weight?   or   "at most K edges/stops"?
                    |                            |
                   yes                          yes
                    |                            |
        Bellman-Ford, V-1 rounds       Bellman-Ford, K+1 rounds
        then 1 check round             with a copy per round
                    |
     still relaxes on check?  ->  negative cycle
```

### The common mistakes

**Relaxing out of an unreached vertex.** `INF + w` with negative `w` invents distances for vertices the source cannot reach. Always guard with `dist[u] == INF`.

**Running `V` rounds instead of `V - 1` and then checking.** It still works, but it wastes a round and blurs the reason the bound is `V - 1`.

**Forgetting the copy in the K-stops version.** In-place relaxation lets one round extend a path by several edges, which silently allows more stops than `K`.

**Using `Integer.MAX_VALUE` as infinity and adding to it.** It overflows to a negative number and looks like a great path.

### What to remember in six months

> Bellman-Ford = "relax everything, `V - 1` times". The round number is the number of edges. That is both why it handles negative weights and why it answers K-stops questions.
