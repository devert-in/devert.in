=== intro ===
Day 5 tracked a running balance. Today tracks a running **best**, and introduces the single most reusable idea in the whole run.

> At every position, ask one question: is it better to extend what I have, or to start over from here? That question is the seed of dynamic programming.

=== problem ===
Find the contiguous subarray with the largest sum, and return that sum.

```text
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
```

The best contiguous run is `[4, -1, 2, 1]`:

```text
4 + (-1) + 2 + 1 = 6
```

So the answer is `6`.

### "Contiguous" is doing a lot of work

You may not cherry-pick. `[4, 2, 1, 4]` sums to `11` but those elements are not adjacent, so it is not a candidate. Only unbroken runs count.

If cherry-picking *were* allowed, the problem would be trivial - add up every positive number. The difficulty is entirely in being forced to take the negatives that sit between the positives you want.

### The all-negative case

```text
nums = [-3, -1, -2]
```

You must pick **at least one** element - an empty subarray is not allowed. So the answer is `-1`, the least bad single element, not `0`. This one line is where most first attempts fail, and section 7 shows exactly how.

=== pattern ===
**Kadane's Algorithm**, which is the simplest possible dynamic program.

Here is the reframe. Instead of asking "what is the best subarray in this whole array?", ask a smaller, local question at every index:

> What is the best subarray that **ends exactly here**?

Call that `cur`. Standing at index `i`, there are only two possibilities for the best run ending at `i`:

1. It extends the best run ending at `i - 1`, giving `cur + nums[i]`.
2. It is just `nums[i]` on its own, because everything before it was a net drag.

So:

```text
cur = max(nums[i], cur + nums[i])
```

And the answer to the real question is the largest `cur` we ever see:

```text
best = max(best, cur)
```

### Why two variables and not one

`cur` is the best run **ending here** - it can go down. `best` is the best run **seen anywhere** - it never goes down. Collapsing them into one variable is the most common way to break this.

### Recognising it

Reach for Kadane-shaped thinking when:

- you want the best contiguous run of something
- the decision at each step is "extend or restart"
- a running value can be carried forward in `O(1)`

The mental question:

> Is the thing I accumulated so far helping me, or would I be better off starting fresh from this element?

=== bruteForce ===
Try every subarray. A subarray is fixed by a start and an end, so two nested loops enumerate all of them, with a running sum in the inner loop so we do not re-add from scratch.

### Dry run

Take a short array so the whole table fits:

```text
nums = [-2, 1, -3, 4]
```

| start | end | subarray | sum | best after |
| ----: | --: | :------- | --: | ---------: |
| 0 | 0 | `[-2]` | -2 | -2 |
| 0 | 1 | `[-2, 1]` | -1 | -1 |
| 0 | 2 | `[-2, 1, -3]` | -4 | -1 |
| 0 | 3 | `[-2, 1, -3, 4]` | 0 | 0 |
| 1 | 1 | `[1]` | 1 | 1 |
| 1 | 2 | `[1, -3]` | -2 | 1 |
| 1 | 3 | `[1, -3, 4]` | 2 | 2 |
| 2 | 2 | `[-3]` | -3 | 2 |
| 2 | 3 | `[-3, 4]` | 1 | 2 |
| 3 | 3 | `[4]` | **4** | **4** |

Answer `4`, found on the last of 10 rows.

### Java

```java
class Solution {
    public int maxSubArray(int[] nums) {

        int best = nums[0];

        for (int start = 0; start < nums.length; start++) {

            int sum = 0;

            for (int end = start; end < nums.length; end++) {
                sum += nums[end];
                best = Math.max(best, sum);
            }
        }

        return best;
    }
}
```

### Complexity

For `n` elements there are `n(n+1)/2` subarrays, and the running sum means each costs `O(1)`.

**Time:** `O(n^2)` — **Space:** `O(1)`

### Where it hurts

Look at rows 1-4 in the table. The `start = 0` block computes the sums of every run beginning at index 0. Then the `start = 1` block does the same work all over again, just without the first element.

Every time we advance `start`, we throw away the entire accumulation and rebuild it. But the useful information from the previous block was only ever **one number** - the best run ending at each position. We recomputed a whole row to rediscover it.

=== optimization ===
Walk the array once, carrying the answer to the local question: *what is the best run ending here?*

### The key observation

Suppose the best run ending at `i - 1` sums to `cur`. Now step to `i`. Any run ending at `i` either includes `nums[i-1]` - in which case its best version is `cur + nums[i]` - or it starts fresh at `i`, giving `nums[i]`.

There is no third option, and both are `O(1)` to evaluate. So:

```text
cur  = max(nums[i], cur + nums[i])
best = max(best, cur)
```

### The intuition in one sentence

> If what you are carrying is negative, it can only hurt whatever comes next - drop it.

`max(nums[i], cur + nums[i])` is exactly that rule. When `cur` is negative, `nums[i]` alone wins.

### Dry run

```text
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
```

Initialise `cur = best = nums[0] = -2`.

| i | nums[i] | cur + nums[i] | nums[i] alone | cur = max | best after | extend or restart? |
| -: | ------: | ------------: | ------------: | --------: | ---------: | :----------------- |
| 0 | -2 | - | - | -2 | -2 | start |
| 1 | 1 | -1 | **1** | 1 | **1** | restart |
| 2 | -3 | **-2** | -3 | -2 | 1 | extend |
| 3 | 4 | 2 | **4** | 4 | **4** | restart |
| 4 | -1 | **3** | -1 | 3 | 4 | extend |
| 5 | 2 | **5** | 2 | 5 | **5** | extend |
| 6 | 1 | **6** | 1 | 6 | **6** | extend |
| 7 | -5 | **1** | -5 | 1 | 6 | extend |
| 8 | 4 | **5** | 4 | 5 | 6 | extend |

Answer: `6`.

### Three rows worth reading twice

**Row 1.** `cur` was `-2`. Extending gives `-1`; starting fresh gives `1`. Restart wins - the `-2` behind us was pure drag.

**Row 3.** Same situation: `cur` was `-2`, and `4` alone beats `-2 + 4 = 2`. This restart is what begins the winning subarray `[4, -1, 2, 1]`.

**Row 7.** `cur` drops from `6` to `1` because of the `-5`, but `best` **stays at 6**. This is exactly why two variables are needed: the run got worse, but the best run we ever saw did not disappear.

### Where the answer actually lives

`best` peaked at `i = 6`, and the loop kept going for two more steps without improving. The algorithm never knows it is finished - it just carries the maximum to the end.

=== complexity ===
### Time

One pass, two comparisons and one addition per element.

```text
O(n)
```

### Space

Two integers.

```text
O(1)
```

### Comparison

| Approach | Time | Space | Work per element |
| :------- | ---: | ----: | :--------------- |
| All subarrays | `O(n^2)` | `O(1)` | rebuilt every time |
| Kadane | **`O(n)`** | `O(1)` | constant, carried forward |

### Why this counts as dynamic programming

The textbook DP formulation would define `dp[i]` = the best subarray sum ending at index `i`, with:

```text
dp[i] = max(nums[i], dp[i-1] + nums[i])
```

That is an `O(n)` array. But `dp[i]` only ever reads `dp[i-1]`, so the whole table collapses to one variable. Kadane *is* that DP with the space optimised away - which is why recognising it here makes the space optimisation on harder DP problems feel familiar later.

=== implementation ===
```java
class Solution {
    public int maxSubArray(int[] nums) {

        // Both start at nums[0], NOT at 0 - an all-negative array must be able
        // to answer with its least-bad element.
        int cur = nums[0];
        int best = nums[0];

        for (int i = 1; i < nums.length; i++) {

            // Extend the run ending at i-1, or abandon it and start at i.
            cur = Math.max(nums[i], cur + nums[i]);

            // best never decreases; cur can.
            best = Math.max(best, cur);
        }

        return best;
    }
}
```

### The lines that matter

**1.**

```java
int cur = nums[0];
int best = nums[0];
```

Initialising to `0` is the classic bug. On `[-3, -1, -2]` a zero start returns `0`, which is not a valid subarray sum because the empty subarray is not allowed. Starting at `nums[0]` guarantees the answer is always a real element.

**2.**

```java
cur = Math.max(nums[i], cur + nums[i]);
```

The extend-or-restart decision, in one line. Note the order of the arguments does not matter to `max`, but reading `nums[i]` first is a reminder that restarting is always available.

**3.**

```java
best = Math.max(best, cur);
```

Runs **after** `cur` is updated, every iteration. Putting it before would record the previous position's value and miss the final element.

### Why the loop starts at `i = 1`

Index `0` is already accounted for by the initialisers. Starting at `0` would evaluate `max(nums[0], nums[0] + nums[0])`, which double-counts the first element - for `nums[0] = 5` it would produce `10`.

### Java notes

- `Math.max` on `int` is a single comparison; no boxing.
- `nums[0]` assumes a non-empty array. LeetCode guarantees `n >= 1`; in production code that is a precondition worth asserting.

=== edgeCases ===
### All negative - the case that breaks naive code

```text
[-3, -1, -2]  ->  -1
```

| i | nums[i] | cur + nums[i] | nums[i] | cur | best |
| -: | ------: | ------------: | ------: | --: | ---: |
| 0 | -3 | - | - | -3 | -3 |
| 1 | -1 | -4 | **-1** | -1 | **-1** |
| 2 | -2 | -3 | **-2** | -2 | -1 |

Answer `-1`. Every step restarts, because carrying a negative forward is never worth it. With `best` initialised to `0`, this would wrongly return `0`.

### Single element

```text
[1]   ->  1
[-1]  ->  -1
```

The loop never runs; the initialisers are the answer.

### All positive

```text
[1, 2, 3, 4]  ->  10
```

`cur` never restarts, because extending is always better when nothing is negative. The answer is the whole array.

### All zeros

```text
[0, 0, 0]  ->  0
```

`max(0, 0 + 0) = 0` every time. Fine.

### A single positive among negatives

```text
[-5, 9, -6]  ->  9
```

The restart at `i = 1` finds it; the `-6` then drags `cur` to `3` while `best` stays `9`.

### Two equal maxima

```text
[2, -1, 2]  ->  3
```

| i | cur | best |
| -: | --: | ---: |
| 0 | 2 | 2 |
| 1 | 1 | 2 |
| 2 | **3** | **3** |

Crossing the `-1` is worth it because `2 + (-1) + 2 = 3` beats either `2` alone. Kadane finds this without any special handling - the dip is absorbed because `cur` stayed positive.

### Overflow

With `n = 10^5` and values up to `10^4`, the maximum possible sum is `10^9`, which fits in an `int` (max `~2.1 x 10^9`). Widen the accumulator to `long` if the constraints ever grow.

=== takeaway ===
> When you see **"maximum/minimum contiguous subarray"**, think **extend or restart** - one running value, one running best.

### The core observation

A negative accumulated prefix can only hurt whatever comes next. The moment carrying it forward is worse than starting fresh, drop it. `max(nums[i], cur + nums[i])` is that sentence written as code.

### The pattern trigger

```text
             at each element
                    |
                    v
      is (cur + nums[i]) better than nums[i]?
             /                    \
           yes                     no
            |                       |
     extend the run          restart here
            \                     /
             \                   /
              v                 v
            best = max(best, cur)
```

### The common mistakes

**Initialising `best = 0`.** Passes every array containing a positive number and fails silently on all-negative input.

**Using one variable instead of two.** `cur` must be allowed to fall (row 7 of the dry run) while `best` holds its peak. Merging them loses the answer the moment the array dips.

**Starting the loop at `i = 0`** after initialising from `nums[0]`, which double-counts the first element.

### What to remember in six months

> "Best thing ending exactly here" is a question you can often answer in `O(1)` from the previous position's answer - and when you can, the outer problem is one pass away.

That reframe is the whole of dynamic programming in one sentence, and Kadane is its smallest possible instance. You will use it again on Maximum Product Subarray (where you must also track the minimum, because a negative flips the sign), on House Robber, on Best Time to Buy and Sell Stock II, and on most of the DP block later in this run.
