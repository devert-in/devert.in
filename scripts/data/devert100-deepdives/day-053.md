=== intro ===
Yesterday each node **returned a number** built from its children's numbers: `1 + max(L, R)`. Today each node returns a **subtree**, and the work done at the node is not arithmetic but rewiring two pointers. Same recursive shape, different payload.

> A global-looking transformation of a tree is often a tiny local change applied at every node. Before you build anything new, ask: what would this look like if I only had to fix one node and trust the recursion with the rest?

=== problem ===
Given the `root` of a binary tree, **invert** it - mirror it left to right - and return its root.

```text
        4                      4
      /   \                  /   \
     2     7       ->       7     2
    / \   / \              / \   / \
   1   3 6   9            9   6 3   1

root = [4, 2, 7, 1, 3, 6, 9]   ->   [4, 7, 2, 9, 6, 3, 1]
```

Hold the tree up to a mirror: whatever was on the left is now on the right, at every level, all the way down.

### What "mirror" means precisely

It is not "swap the root's two children". That alone would give:

```text
        4
      /   \
     7     2          <- subtrees swapped
    / \   / \
   6   9 1   3        <- but their insides are NOT mirrored
```

Level 3 reads `6, 9, 1, 3`, not `9, 6, 3, 1`. The mirror has to be applied inside every subtree too. Equivalently: **every node's left and right children are exchanged**.

### Read the levels

```text
level 1:  4              ->  4
level 2:  2, 7           ->  7, 2
level 3:  1, 3, 6, 9     ->  9, 6, 3, 1
```

Each level comes out **reversed**. That observation is the brute force, and it turns out to be the key to the optimal solution too.

### The constraints that matter

| constraint | value | what it means |
| :--------- | ----: | :------------ |
| nodes | 0 to 100 | empty tree is a real input - return `null` |
| values | -100 to 100 | irrelevant - inversion never compares values |

=== pattern ===
**DFS - apply a local operation at every node.**

The mirror of a tree is:

```text
mirror(null) = null
mirror(node) = node, with
                 left  = mirror(old right)
                 right = mirror(old left)
```

Read it as a sentence: "to mirror a tree, mirror both subtrees and put them on opposite sides". The global transformation is one swap per node, repeated by recursion.

### Why it fits the DFS template

It is the same shape as yesterday's `1 + max(L, R)`: get the answer for the left subtree, get the answer for the right subtree, combine. Here the "answer" for a subtree is its mirrored root, and "combine" is attaching the two answers in swapped positions.

And because the swap at a node does not depend on anything below it, the swap can happen **before** the recursion (preorder), **after** it (postorder), or level by level with a queue (BFS). Every node gets swapped exactly once; the order does not matter.

### Recognising it

Reach for "one local operation per node" when:

- the requested change is uniform - the same thing happens to every node
- the change at a node only touches that node and its direct pointers
- the problem says "return the root" (so modifying in place is allowed)

The mental question:

> If I fix just this one node and trust the recursion for both subtrees, is the whole tree fixed?

=== bruteForce ===
Take the level observation literally: record every level, reverse it, and build a new tree from the reversed levels.

### Step logic

1. **Record** each level left to right, keeping a `null` slot for every missing child of a real node (so the shape is preserved). Stop when a level has no real nodes.
2. **Reverse** each level, creating a fresh node for every real entry.
3. **Wire** the new tree: the slots of level `k + 1`, in order, are the (left, right) children of the real nodes of level `k`, in order.

### Dry run

```text
root = [4, 2, 7, 1, 3, 6, 9]
```

**Phase 1 - record levels**

| level | nodes recorded | next level's slots (left, right of each real node) | any real? |
| ----: | :------------- | :------------------------------------------------- | :-------- |
| 0 | `4` | `2, 7` | yes |
| 1 | `2, 7` | `1, 3, 6, 9` | yes |
| 2 | `1, 3, 6, 9` | `null` x 8 | no - stop |

**Phase 2 - reverse each level into new nodes**

| level | recorded | reversed (new nodes) |
| ----: | :------- | :------------------- |
| 0 | `4` | `4'` |
| 1 | `2, 7` | `7', 2'` |
| 2 | `1, 3, 6, 9` | `9', 6', 3', 1'` |

**Phase 3 - wire the new levels**

| parent (level k) | slot taken from level k+1 | sets |
| :--------------- | :------------------------ | :--- |
| `4'` | slots 0, 1 | `4'.left = 7'`, `4'.right = 2'` |
| `7'` | slots 0, 1 | `7'.left = 9'`, `7'.right = 6'` |
| `2'` | slots 2, 3 | `2'.left = 3'`, `2'.right = 1'` |
| `9'`, `6'`, `3'`, `1'` | no level 3 | children stay `null` |

Result `[4, 7, 2, 9, 6, 3, 1]`. Correct.

### Why reversing a level with its null slots is right

Level `k + 1`'s slots are "left of the first parent, right of the first parent, left of the second parent, ...". Mirror the parents' order and swap each pair and you get exactly that list read backwards. The `null` slots must be kept for this to hold - drop them and a missing child shifts every slot after it.

### Java

```java
class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) return null;

        // Phase 1: record every level, with a null slot for each missing child.
        List<List<TreeNode>> levels = new ArrayList<>();
        List<TreeNode> level = new ArrayList<>();
        level.add(root);
        while (!level.isEmpty()) {
            levels.add(level);
            List<TreeNode> next = new ArrayList<>();
            boolean anyReal = false;
            for (TreeNode node : level) {
                if (node == null) continue;
                next.add(node.left);
                next.add(node.right);
                if (node.left != null || node.right != null) anyReal = true;
            }
            level = anyReal ? next : new ArrayList<>();
        }

        // Phase 2: reverse each level into brand-new nodes.
        List<List<TreeNode>> built = new ArrayList<>();
        for (List<TreeNode> lv : levels) {
            List<TreeNode> copy = new ArrayList<>();
            for (int i = lv.size() - 1; i >= 0; i--) {
                TreeNode old = lv.get(i);
                copy.add(old == null ? null : new TreeNode(old.val));
            }
            built.add(copy);
        }

        // Phase 3: level k+1's slots are the children of level k's real nodes.
        for (int k = 0; k + 1 < built.size(); k++) {
            int slot = 0;
            for (TreeNode parent : built.get(k)) {
                if (parent == null) continue;
                parent.left = built.get(k + 1).get(slot++);
                parent.right = built.get(k + 1).get(slot++);
            }
        }
        return built.get(0).get(0);
    }
}
```

### Complexity

**Time:** `O(n)` - **Space:** `O(n)` (the level lists, the null slots, and `n` new nodes)

### Where it hurts

The time is already linear, so the waste is not speed. It is everything else:

- **Three passes** over the tree where one would do.
- **`n` brand-new nodes** allocated, plus up to `n + 1` `null` slots stored just to remember the shape.
- **The original tree is untouched**, so the caller now holds two trees and the old one is garbage.
- **About forty lines** with an index-juggling wiring phase that is easy to get subtly wrong.

Now look back at the Phase 3 table. `4'` got its children as `(7', 2')` - its old children, swapped. `7'` got `(9', 6')` - its old children `(6, 9)`, swapped. `2'` got `(3', 1')` - swapped. **Every row of the wiring is just "the old children, swapped".** Reversing every level was never really about levels; it is what you see from outside when every node swaps its own two children.

So skip the levels, skip the copies, and swap the two pointers at every node of the original tree.

=== optimization ===
### Key observation

Mirroring a whole level is the same as swapping the children of every node in the level above, all the way down. So the transformation is one local operation - swap `left` and `right` - applied once at every node, in place.

### Step logic (recursive, postorder)

1. If the node is `null`, return `null`.
2. Invert the left subtree, invert the right subtree, keep both results.
3. Attach the inverted right subtree on the left and the inverted left subtree on the right.
4. Return the node.

### Dry run - same tree

| order | call | inverted left returned | inverted right returned | after the swap | returns |
| ----: | :--- | :--------------------- | :---------------------- | :------------- | ------: |
| 1 | `invert(1)` | null | null | `1(null, null)` | 1 |
| 2 | `invert(3)` | null | null | `3(null, null)` | 3 |
| 3 | `invert(2)` | 1 | 3 | `2(3, 1)` | 2 |
| 4 | `invert(6)` | null | null | `6(null, null)` | 6 |
| 5 | `invert(9)` | null | null | `9(null, null)` | 9 |
| 6 | `invert(7)` | 6 | 9 | `7(9, 6)` | 7 |
| 7 | `invert(4)` | 2 | 7 | `4(7, 2)` | 4 |

Rows are in the order calls **finish** - postorder, `1, 3, 2, 6, 9, 7, 4`. A leaf's "swap" exchanges two `null`s and changes nothing; the visible work happens at rows 3, 6 and 7.

```text
after row 3:      4            after row 6:      4            after row 7:      4
                /   \                          /   \                          /   \
               2     7                        2     7                        7     2
              / \   / \                      / \   / \                      / \   / \
             3   1 6   9                    3   1 9   6                    9   6 3   1
```

No new node was created. The same seven nodes were rewired, and the method returns the same `root` object it was given.

### Preorder works too

Swap first, then recurse into the (already swapped) children:

| step | call | children before | children after swap |
| ---: | :--- | :-------------- | :------------------ |
| 1 | `invert(4)` | `(2, 7)` | `(7, 2)` |
| 2 | `invert(7)` | `(6, 9)` | `(9, 6)` |
| 3 | `invert(9)` | `(null, null)` | unchanged |
| 4 | `invert(6)` | `(null, null)` | unchanged |
| 5 | `invert(2)` | `(1, 3)` | `(3, 1)` |
| 6 | `invert(3)` | `(null, null)` | unchanged |
| 7 | `invert(1)` | `(null, null)` | unchanged |

Same final tree. The only thing that matters is that every node is swapped **exactly once**.

### The trap that looks like a one-liner

The tempting compact version is:

```text
root.left  = invertTree(root.right);
root.right = invertTree(root.left);     // BUG: root.left was just overwritten
```

The second line reads `root.left` **after** the first line replaced it, so both sides of the root are built from the old **right** subtree, and the old left subtree is never reached again. Because the bug runs at every level, it repeats inside: node `7` ends up with `9` on both sides too. On the example:

```text
[4, 2, 7, 1, 3, 6, 9]  ->  [4, 7, 7, 9, 9, 9, 9]
```

The same `7` node hangs off both sides of the root, the same `9` node hangs off both sides of `7`, and `2`, `1`, `3` and `6` have vanished. Save both results in local variables first - which is exactly what the implementation does.

=== complexity ===
### Time

Each node is visited once and does a constant amount of work (one swap).

```text
O(n)
```

### Space

No new nodes. The recursion holds one frame per level of the current path.

```text
O(h)    balanced: log n     skewed (a chain): n
```

The BFS version uses a queue instead, `O(w)` for the widest level.

### Comparison

| Approach | Time | Extra space | New nodes | Passes |
| :------- | ---: | ----------: | --------: | -----: |
| Record, reverse and rebuild levels | `O(n)` | `O(n)` | `n` | 3 |
| Recursive swap (pre or post) | **`O(n)`** | **`O(h)`** | **0** | 1 |
| BFS swap with a queue | `O(n)` | `O(w)` | 0 | 1 |

=== implementation ===
```java
class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) {
            return null;                            // nothing to mirror
        }

        TreeNode left = invertTree(root.left);      // mirror both subtrees first,
        TreeNode right = invertTree(root.right);    // saving BOTH results

        root.left = right;                          // then attach them swapped
        root.right = left;

        return root;                                // same node, rewired
    }
}
```

### The lines that matter

**1.**

```java
TreeNode left = invertTree(root.left);      // mirror both subtrees first,
TreeNode right = invertTree(root.right);    // saving BOTH results
```

Both recursive results are captured in locals before either pointer on `root` is touched. This is the line that avoids the overwrite trap: once `root.left` is reassigned, the old left subtree is reachable only through `left`.

**2.**

```java
root.left = right;                          // then attach them swapped
root.right = left;
```

The swap. It is the whole transformation, applied at one node; recursion applies it at every other node.

**3.**

```java
return root;                                // same node, rewired
```

The method returns the node it was given. That is what makes the recursion compose: a parent receives each child's mirrored subtree as a `TreeNode` it can attach directly. And at the top level, LeetCode receives the original root, now mirrored in place.

### The BFS version

The same swap, applied level by level with a queue - useful when the tree may be too deep for recursion:

```java
class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) return null;

        Queue<TreeNode> queue = new ArrayDeque<>();
        queue.offer(root);

        while (!queue.isEmpty()) {
            TreeNode node = queue.poll();

            TreeNode temp = node.left;              // classic three-step swap
            node.left = node.right;
            node.right = temp;

            if (node.left != null) queue.offer(node.left);
            if (node.right != null) queue.offer(node.right);
        }
        return root;
    }
}
```

Enqueuing after the swap or before it makes no difference: each node is swapped once, whichever side it ends up on.

### Java notes

- `TreeNode` is supplied by LeetCode; do not declare it. Assigning `root.left = right` copies a **reference**, not a subtree - no node is duplicated, which is why the space is `O(h)`, not `O(n)`.
- Java has no tuple swap like Python's `a, b = b, a`. Either use a `temp` variable (BFS version) or capture both values first (recursive version).
- `ArrayDeque` rejects `null`, so children are checked before `offer`.

=== edgeCases ===
### Empty tree

```text
root = null  ->  null
```

The base case returns `null` immediately. Returning anything else (or throwing) fails LeetCode's empty test.

### Single node

```text
[1]  ->  [1]
```

Its two `null` children are swapped with each other. Nothing visible changes.

### LeetCode's second example

```text
[2, 1, 3]  ->  [2, 3, 1]
```

One swap at the root. The two leaves swap `null`s.

### One-sided chain

```text
[1, 2, null, 3]  ->  [1, null, 2, null, 3]

      1            1
     /              \
    2       ->       2
   /                  \
  3                    3
```

A left chain becomes a right chain. Every node had one real child and one `null`; each swap moves the real child across.

### A symmetric tree

```text
[1, 2, 2, 3, 4, 4, 3]  ->  [1, 2, 2, 3, 4, 4, 3]
```

A tree that is its own mirror inverts to the same values. That is exactly the definition used by **Symmetric Tree (LC 101)**: a tree is symmetric when it equals its inversion.

### Inverting twice

```text
invert(invert(t))  ==  t
```

Swapping each node's children twice restores them. A handy self-check in tests, and the reason "invert" is called an involution.

### A 100,000-node chain

The BFS version inverts it with a queue that never holds more than one node. The recursive version needs 100,000 nested calls and can throw `StackOverflowError` on a default JVM stack - outside LeetCode's 100-node limit, but worth knowing.

=== takeaway ===
> When you see **"transform the whole tree"** (mirror, flip, clear, relabel), think **"what is the one-node version, and can recursion do the rest?"** - one local operation at every node, in place.

### The core observation

Every level of the mirror is reversed, and a reversed level is nothing more than every node above it having swapped its two children. So the global mirror is one pointer swap per node. No new nodes, no level lists - just `left` and `right` exchanged everywhere.

### The pattern trigger

```text
     same change at every node?
                |
               yes
                v
     does the change touch only this node's own pointers/value?
                |
               yes
                v
     f(null) = null
     f(node) = do the local change, recurse into both children, return node
                |
                v
     order (pre / post / BFS) usually does not matter -
     only that every node is handled exactly once
```

### The common mistakes

**`root.left = invertTree(root.right); root.right = invertTree(root.left);`** The second line reads the pointer the first line just overwrote; on the example it returns `[4, 7, 7, 9, 9, 9, 9]`. Capture both results first.

**Swapping only the root.** Mirrors the top level and leaves every subtree's inside unchanged.

**Swapping twice.** Calling the swap in both a pre position and a post position (or visiting a node twice in BFS) undoes it.

**Building a copy when in place was fine.** The brute force is correct but allocates `n` nodes for a problem that needs zero.

### What to remember in six months

> A tree transformation is usually "fix this node, trust the recursion for the children". Write the one-node fix, guard `null`, and return the node.

**Symmetric Tree (LC 101)** asks whether the left subtree is the mirror of the right - the same recursion, comparing instead of swapping. **Same Tree (LC 100)** is that comparison without the mirror. **Flip Equivalent Binary Trees (LC 951)** combines both.
