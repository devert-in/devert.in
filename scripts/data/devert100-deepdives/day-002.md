=== intro ===
Today we move from **Hashing** to **One-Pass / Greedy thinking**.

This problem matters because it teaches a powerful interview habit:

> Don't try to remember everything about the past. Find the smallest piece of information from the past that is enough to make the current decision.

=== problem ===
You are given an array:

```text
prices[i] = stock price on day i
```

You need to:

1. Choose **one day to buy**
2. Choose **one later day to sell**
3. Maximize your profit

The profit is:

```text
profit = selling price - buying price
```

### Example

```text
prices = [7, 1, 5, 3, 6, 4]
```

| Day | Price |
| --: | ----: |
|   0 |     7 |
|   1 |     1 |
|   2 |     5 |
|   3 |     3 |
|   4 |     6 |
|   5 |     4 |

We could buy at `1` and sell at `6`:

```text
Profit = 6 - 1
       = 5
```

So the answer is `5`.

### The condition that makes this a real problem

You **must buy before you sell**. You cannot buy on day 4 and sell on day 1.

This is exactly why you cannot just take the global minimum and the global maximum - their **order** matters.

### Another example

```text
prices = [7, 6, 4, 3, 1]
```

The price only falls. There is no profitable transaction, so the answer is `0`. We never return a negative profit.

=== pattern ===
**One Pass / Greedy.**

Don't memorise "stock problem equals greedy". Understand why.

Stand on a particular day. Today's price is `5`. To get the maximum profit by selling today, what do you actually need to know?

> What is the cheapest price at which I could have bought before today?

That's all. You do not need to remember every previous price. You need one number:

```text
minimum price seen so far
```

Then:

```text
today's profit = today's price - minPrice
```

and you keep the largest profit you have seen.

### Recognising it

Whenever you see:

- "maximum profit"
- "buy before sell"
- "best value so far"
- "choose an earlier minimum and a later maximum"
- a single left-to-right traversal looks possible

ask yourself:

> Can I summarise everything from the past using one variable?

Here that variable is `minPrice`. Getting into this habit is worth more than the answer to this one problem.

=== bruteForce ===
Forget optimisation for a moment. The obvious solution is to try every possible buying day against every possible selling day after it.

For every `i`, take `buy = prices[i]`. For every `j` after `i`, take `sell = prices[j]`, compute `prices[j] - prices[i]`, and keep the maximum.

### On our example

```text
[7, 1, 5, 3, 6, 4]
```

We would examine:

```text
7 -> 1, 7 -> 5, 7 -> 3, 7 -> 6, 7 -> 4
1 -> 5, 1 -> 3, 1 -> 6, 1 -> 4
5 -> 3, 5 -> 6, 5 -> 4
...
```

Eventually `1 -> 6 = 5`, so the answer is `5`.

### Java

```java
class Solution {
    public int maxProfit(int[] prices) {

        int maxProfit = 0;

        for (int buy = 0; buy < prices.length; buy++) {

            for (int sell = buy + 1; sell < prices.length; sell++) {

                int profit = prices[sell] - prices[buy];

                maxProfit = Math.max(maxProfit, profit);
            }
        }

        return maxProfit;
    }
}
```

### Complexity

There are roughly `n x n` pairs to check.

**Time:** `O(n^2)` — **Space:** `O(1)`

For `n = 100,000` this is far too expensive. So ask the question that unlocks almost every optimisation:

> Are we repeating work?

Yes.

=== optimization ===
Take the same array and walk it **once**.

```text
prices = [7, 1, 5, 3, 6, 4]
```

### Day 0 - price 7

First price we have seen, so it is the cheapest so far. No profit yet.

```text
minPrice  = 7
maxProfit = 0
```

### Day 1 - price 1

Is `1` cheaper than `7`? Yes. We have found a better buying opportunity.

```text
minPrice  = 1
maxProfit = 0
```

### Day 2 - price 5

Suppose we sell today. The best price we could have bought at is `minPrice = 1`.

```text
profit = 5 - 1 = 4
maxProfit = 4
```

### Day 3 - price 3

```text
3 - 1 = 2
```

`2 < 4`, so `maxProfit` stays `4`.

### Day 4 - price 6

```text
6 - 1 = 5
```

Better. `maxProfit = 5`.

### Day 5 - price 4

```text
4 - 1 = 3
```

Not better. Final answer: `5`.

### The big observation

Brute force asks: "for every selling day, which buying day gives the best profit?"

We can answer that without checking every previous day, because:

```text
best buying price = minimum price seen before today
```

So we maintain exactly two things - `minPrice` and `maxProfit`. That is the entire optimisation.

=== complexity ===
We traverse the array once, and for each price we do a constant amount of work: one `min`, one subtraction, one `max`.

### Time

```text
O(n)
```

Each element is processed once.

### Space

Two variables, `minPrice` and `maxProfit`. No extra array, HashMap or Stack.

```text
O(1)
```

### Comparison

| Approach    |    Time |  Space |
| ----------- | ------: | -----: |
| Brute Force | `O(n^2)` | `O(1)` |
| One Pass    | **`O(n)`** | **`O(1)`** |

A good example of going from quadratic to linear **without** reaching for an extra data structure.

=== implementation ===
```java
class Solution {
    public int maxProfit(int[] prices) {

        int minPrice = Integer.MAX_VALUE;
        int maxProfit = 0;

        for (int price : prices) {

            // Best buying price seen so far
            minPrice = Math.min(minPrice, price);

            // Profit if we sell today
            int currentProfit = price - minPrice;

            // Best profit found so far
            maxProfit = Math.max(maxProfit, currentProfit);
        }

        return maxProfit;
    }
}
```

Three lines carry the whole idea.

### 1

```java
minPrice = Math.min(minPrice, price);
```

"Is today's price cheaper than anything I have seen before?" If so, today becomes our new potential buying day.

### 2

```java
int currentProfit = price - minPrice;
```

"What if I sell today?" Since `minPrice` is the cheapest price seen up to and including now, this is the best possible profit for selling at this point.

### 3

```java
maxProfit = Math.max(maxProfit, currentProfit);
```

Maybe today's profit is the best we have ever seen. If not, keep the previous maximum.

### One subtle point

What if `minPrice` is updated to today's price and *then* we compute the profit?

```text
price = 1, minPrice = 1
currentProfit = 1 - 1 = 0
```

That is fine. We are not inventing an invalid same-day transaction - we are saying buying and selling at the same price earns nothing. On the next day, `minPrice` correctly represents the cheapest price available so far.

=== edgeCases ===
### Prices continuously decrease

```text
[7, 6, 5, 4, 3]
```

Every new price becomes the minimum, but no profitable sale exists. Answer: `0`.

### Only one day

```text
[5]
```

You cannot buy and sell on different days. Answer: `0`.

### Two days

```text
[1, 5]
```

Buy at `1`, sell at `5`. Answer: `4`.

### All prices the same

```text
[5, 5, 5, 5]
```

Answer: `0`.

### Best buy is at the very start

```text
[1, 2, 3, 4, 5]
```

The minimum stays `1` while profit keeps growing. Answer: `4`.

### Best buy is in the middle

```text
[7, 6, 4, 1, 5]
```

The algorithm finds `minPrice = 1`, then `5 - 1 = 4`. Answer: `4`.

This last one is the case that proves you cannot simply take the global minimum and the global maximum. Order matters.

=== takeaway ===
This is the part worth remembering months from now.

> When you see "buy before sell" plus "maximise profit", think: **minimum so far + current profit**.

The mental model:

```text
              Current Day
                   |
                   v
          +------------------+
          |  Current Price   |
          +--------+---------+
                   |
                   v
        What is the cheapest
        price I have seen?
                   |
                   v
         current profit =
         current - minimum
                   |
                   v
         update maximum profit
```

The two variables:

```text
minPrice  -> best buying opportunity so far
maxProfit -> best transaction found so far
```

### The real lesson

Today's problem is not about stocks. It is about **compressing the past**.

Instead of remembering `7, 1, 5, 3, ...` we summarise everything seen so far into a single number, `minimum = 1`. That is what lets the next decision cost `O(1)`.

### The rule to carry forward

When a problem says "for each position, find the best previous value", immediately ask:

> Can I maintain that best previous value while traversing once?

If yes, you probably have an `O(n)` one-pass solution.
