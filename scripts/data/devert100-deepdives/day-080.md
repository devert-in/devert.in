=== intro ===
Yesterday's DFS found the **edges** that hold a network together. Today the same DFS, with one comparison loosened and one special case added, finds the **vertices**.

> When two problems share a definition shape - "remove one thing, does the graph fall apart?" - expect them to share an algorithm. The work is in finding the exact place they differ, and here that is one character (`>` versus `>=`) and one node (the root).

=== problem ===
Given an undirected graph with `V` vertices (`0..V-1`) as an adjacency list, return every **articulation point** in ascending order. A vertex is an articulation point (also called a **cut vertex**) if removing it - together with every edge touching it - increases the number of connected components. If there are none, return `[-1]`.

```text
V = 5
edges = [[0,1], [1,2], [2,0], [1,3], [3,4], [4,1]]
answer = [1]
```

Draw it - two triangles that share one corner, a "bowtie":

```text
    0           3
    | \       / |
    |   \   /   |
    |     1     |
    |   /   \   |
    | /       \ |
    2           4
```

Check each vertex by hand:

| removed | what is left | components | articulation point? |
| ------: | :----------- | ---------: | :------------------ |
| 0 | `1-2`, `1-3`, `3-4`, `4-1` | 1 | no |
| 1 | `0-2` and `3-4`, nothing between them | 2 | **yes** |
| 2 | `0-1`, `1-3`, `3-4`, `4-1` | 1 | no |
| 3 | `0-1`, `1-2`, `2-0`, `4-1` | 1 | no |
| 4 | `0-1`, `1-2`, `2-0`, `1-3` | 1 | no |

### The detail that makes this example worth studying

This graph has an articulation point but **no bridges**. Every edge is on a triangle, so yesterday's algorithm would return nothing. Yet vertex `1` is a single point of failure: both triangles pass **through** it.

That is the difference between the two problems in one picture. A cycle through `(u, v)` saves the **edge**. It does not save the **vertex** `u` if the cycle has to pass through `u` itself.

### What the constraints tell you

- GFG allows `V` and `E` up to around `10^4` to `10^5`. Removing each vertex and re-checking connectivity is `O(V * (V + E))` - too slow at the top end.
- The expected complexity is `O(V + E)`, which again means **one** DFS.
- Ascending order and `[-1]` for "none" are output-format rules. They are easy to forget and they fail the judge just as surely as a wrong answer.

=== pattern ===
**Tarjan's algorithm** - the same `disc` / `low` DFS as Day 79.

- `disc[u]` - when `u` was first discovered.
- `low[u]` - the earliest discovery time reachable from `u`'s DFS subtree, using tree edges down and at most one back edge up.

The articulation-point tests:

```text
non-root u:  u is a cut vertex if some DFS child v has   low[v] >= disc[u]
root:        u is a cut vertex if it has more than one DFS child
```

### Why `>=` and not `>`

Removing **vertex** `u` destroys every edge touching `u`, including any back edge that lands **on** `u`.

- `low[v] > disc[u]` - `v`'s subtree cannot even reach `u`. Removing `u` cuts it off. (Also a bridge.)
- `low[v] == disc[u]` - the subtree's best escape is a back edge **to `u` itself**. That saves the edge `(u, v)`, but if `u` is deleted, the back edge is deleted with it. The subtree is still cut off.
- `low[v] < disc[u]` - the subtree reaches something **above** `u`. It survives `u`'s removal.

So "cannot get strictly above `u`" is the condition, and that is `low[v] >= disc[u]`.

### Why the root needs its own rule

The root has `disc = 0`, the smallest possible, so `low[v] >= disc[root]` is **always** true. The general test would mark every root as a cut vertex - wrong for any root inside a cycle.

The root's real situation is simpler. In an undirected DFS there are no cross edges, so the root's DFS children are subtrees with **no edges between them** - if there were one, the DFS would have walked it and they would be one subtree. So:

- one child: removing the root leaves that one subtree intact - not a cut vertex
- two or more children: those subtrees can only talk through the root - cut vertex

### Recognising it

Reach for this when the question is about **vertices** as single points of failure: "critical router", "cut vertex", "which city, if closed, splits the map", "biconnected". If the question is about **edges**, it is yesterday's bridge test instead.

The mental question:

> Can this child's subtree reach something strictly **above** `u` without passing through `u`?

=== bruteForce ===
Take the definition literally. Count connected components once. Then, for each vertex, pretend it does not exist and count again. If the count went up, the vertex is an articulation point.

Counting components is the standard loop: walk every vertex, and each time you find an unvisited one, start a DFS from it and add one to the count. To "remove" a vertex, simply never visit it and never step onto it.

### Dry run

```text
V = 5
adjacency:  0: [1, 2]
            1: [0, 2, 3, 4]
            2: [1, 0]
            3: [1, 4]
            4: [3, 1]
```

Baseline (nothing removed): one DFS from `0` reaches everything, so `base = 1`.

| removed | DFS starts from | each DFS reaches | components | `> base`? | result after |
| ------: | :-------------- | :--------------- | ---------: | :-------- | :----------- |
| 0 | 1 | `{1, 2, 3, 4}` | 1 | no | `[]` |
| 1 | 0, then 3 | `{0, 2}`, then `{3, 4}` | 2 | **yes** | `[1]` |
| 2 | 0 | `{0, 1, 3, 4}` | 1 | no | `[1]` |
| 3 | 0 | `{0, 1, 2, 4}` | 1 | no | `[1]` |
| 4 | 0 | `{0, 1, 2, 3}` | 1 | no | `[1]` |

Result `[1]`. Correct.

Row 1 shows the mechanism: with `1` gone, the DFS from `0` reaches only `2`, the outer loop moves on, finds `3` unvisited, and has to start a **second** DFS. That second start is the component count going up.

### Java

```java
class Solution {
    public ArrayList<Integer> articulationPoints(int V, ArrayList<ArrayList<Integer>> adj) {

        ArrayList<Integer> result = new ArrayList<>();
        int base = countComponents(V, adj, -1);

        // Pretend each vertex is gone; did the graph split into more pieces?
        for (int removed = 0; removed < V; removed++) {
            if (countComponents(V, adj, removed) > base) {
                result.add(removed);
            }
        }

        if (result.isEmpty()) {
            result.add(-1);
        }
        return result;
    }

    private int countComponents(int V, ArrayList<ArrayList<Integer>> adj, int removed) {

        boolean[] seen = new boolean[V];
        int components = 0;

        for (int start = 0; start < V; start++) {
            if (start == removed || seen[start]) continue;

            components++;
            Deque<Integer> stack = new ArrayDeque<>();
            stack.push(start);
            seen[start] = true;

            while (!stack.isEmpty()) {
                int u = stack.pop();
                for (int v : adj.get(u)) {
                    if (v != removed && !seen[v]) {
                        seen[v] = true;
                        stack.push(v);
                    }
                }
            }
        }

        return components;
    }
}
```

Because `removed` goes from `0` up to `V - 1`, the result is already in ascending order.

### Complexity

**Time:** `O(V * (V + E))` - **Space:** `O(V)` extra

### Where it hurts

Every row walks the **entire graph** to learn about **one** vertex. Rows 0, 2, 3 and 4 each rediscover that the two triangles hang together through `1` - and then forget it.

The question each row asks is local:

> If `u` disappears, is some part of the graph below it left with no other way out?

A single DFS already knows, for each subtree, how far back up the tree it can escape. That is `low`. Record it once, and every vertex can be tested from its children's `low` values with no extra traversal.

=== optimization ===
### The key observation

Run one DFS from any start vertex, which becomes the root. Look at a non-root vertex `u` and one of its DFS children `v`:

```text
        (ancestors of u)
              |
              u          disc[u]
              |
              v
            / | \
        (v's subtree)
```

If `u` is deleted, `v`'s subtree stays connected to the rest of the graph only if it has a back edge to a **strict ancestor** of `u`. That is exactly `low[v] < disc[u]`. If even one child fails that - `low[v] >= disc[u]` - its subtree is stranded, and `u` is a cut vertex.

The root is tested separately: it is a cut vertex exactly when it has two or more DFS children.

### Dry run

```text
adjacency:  0: [1, 2]
            1: [0, 2, 3, 4]
            2: [1, 0]
            3: [1, 4]
            4: [3, 1]
```

`disc` starts as `-1` everywhere, `timer = 0`. Arrays are written for vertices `0 1 2 3 4`.

| step | event | disc | low | cut vertices |
| ---: | :---- | :--- | :-- | :----------- |
| 1 | enter `0` (root), time 0, `children = 0` | `0 - - - -` | `0 - - - -` | |
| 2 | at `0`: neighbour `1` unvisited, `children = 1`, recurse | | | |
| 3 | enter `1` (parent 0), time 1 | `0 1 - - -` | `0 1 - - -` | |
| 4 | at `1`: neighbour `0` is the parent, skip | | | |
| 5 | at `1`: neighbour `2` unvisited, recurse | | | |
| 6 | enter `2` (parent 1), time 2 | `0 1 2 - -` | `0 1 2 - -` | |
| 7 | at `2`: `1` is the parent, skip; `0` visited - back edge, `low[2] = min(2, disc[0]=0) = 0` | `0 1 2 - -` | `0 1 0 - -` | |
| 8 | back at `1`: `low[1] = min(1, low[2]=0) = 0`; is `low[2]=0 >= disc[1]=1`? no | `0 1 2 - -` | `0 0 0 - -` | |
| 9 | at `1`: neighbour `3` unvisited, recurse | | | |
| 10 | enter `3` (parent 1), time 3 | `0 1 2 3 -` | `0 0 0 3 -` | |
| 11 | at `3`: `1` is the parent, skip; `4` unvisited, recurse | | | |
| 12 | enter `4` (parent 3), time 4 | `0 1 2 3 4` | `0 0 0 3 4` | |
| 13 | at `4`: `3` is the parent, skip; `1` visited - back edge, `low[4] = min(4, disc[1]=1) = 1` | `0 1 2 3 4` | `0 0 0 3 1` | |
| 14 | back at `3`: `low[3] = min(3, low[4]=1) = 1`; is `low[4]=1 >= disc[3]=3`? no | `0 1 2 3 4` | `0 0 0 1 1` | |
| 15 | back at `1`: `low[1] = min(0, low[3]=1) = 0`; is `low[3]=1 >= disc[1]=1`? **yes** | `0 1 2 3 4` | `0 0 0 1 1` | `{1}` |
| 16 | at `1`: `4` visited - back edge, `low[1] = min(0, disc[4]=4) = 0` | | | `{1}` |
| 17 | back at `0`: `low[0] = min(0, low[1]=0) = 0`; root, so no `>=` test | | | `{1}` |
| 18 | at `0`: `2` visited - back edge, no change; root has `children = 1`, so not a cut vertex | `0 1 2 3 4` | `0 0 0 1 1` | `{1}` |

Result `[1]`. Correct.

### The two rows that are the whole lesson

**Step 15.** `low[3] = 1` and `disc[1] = 1`. They are **equal**. The right-hand triangle's only escape is the back edge `4 -> 1`, which lands on `1` itself. Delete `1` and that escape is gone. The `>=` fires.

With yesterday's `>`, `1 > 1` is false and `1` would be missed - which is exactly why yesterday found no bridges here.

**Step 18.** Had we applied the non-root test to the root, step 17 would ask `low[1]=0 >= disc[0]=0` - true - and wrongly mark `0`. The root rule asks the right question instead: does `0` have more than one DFS child? It has one (`1`; `2` was reached through `1`), so no.

### Final arrays

```text
vertex   0  1  2  3  4
disc     0  1  2  3  4
low      0  0  0  1  1
```

The left triangle (`0, 1, 2`) reaches time `0`. The right triangle's subtree (`3, 4`) reaches only time `1` - vertex `1` - and nothing above it.

=== complexity ===
### Time

One DFS: every vertex entered once, every edge examined twice. Collecting the answer is one more `O(V)` scan.

```text
O(V + E)
```

### Space

`disc`, `low` and `isAP` are `O(V)`. The recursion depth can reach `V` on a path. The adjacency list is input, not extra.

```text
O(V)
```

### Comparison

| Approach | Time | Extra space | Handles the root by |
| :------- | ---: | ----------: | :------------------ |
| Remove each vertex, count components | `O(V * (V + E))` | `O(V)` | treating it like any other vertex |
| **Tarjan disc/low DFS** | **`O(V + E)`** | **`O(V)`** | counting its DFS children |

### Day 79 versus Day 80, side by side

| | Bridges (edges) | Articulation points (vertices) |
| :- | :- | :- |
| test | `low[v] > disc[u]` | `low[v] >= disc[u]` |
| why | a back edge to `u` saves the edge `(u, v)` | a back edge to `u` dies with `u` |
| root | no special case | cut vertex iff `> 1` DFS child |
| bowtie example | none | `[1]` |
| a single edge `0-1` | `[[0,1]]` | none |

Every bridge endpoint with degree at least 2 is an articulation point; the reverse is not true, as the bowtie shows.

=== implementation ===
```java
class Solution {

    private int[] disc;        // discovery time, -1 if unvisited
    private int[] low;         // earliest discovery time the subtree can reach
    private boolean[] isAP;    // a vertex can qualify via several children; mark once
    private int timer;

    public ArrayList<Integer> articulationPoints(int V, ArrayList<ArrayList<Integer>> adj) {

        disc = new int[V];
        low = new int[V];
        isAP = new boolean[V];
        timer = 0;
        Arrays.fill(disc, -1);

        for (int i = 0; i < V; i++) {
            if (disc[i] == -1) {
                dfs(i, -1, adj);
            }
        }

        ArrayList<Integer> result = new ArrayList<>();
        for (int i = 0; i < V; i++) {
            if (isAP[i]) {
                result.add(i);         // ascending by construction
            }
        }
        if (result.isEmpty()) {
            result.add(-1);
        }
        return result;
    }

    private void dfs(int u, int parent, ArrayList<ArrayList<Integer>> adj) {

        disc[u] = low[u] = timer++;
        int children = 0;

        for (int v : adj.get(u)) {
            if (v == parent) continue;

            if (disc[v] == -1) {                           // tree edge
                children++;
                dfs(v, u, adj);
                low[u] = Math.min(low[u], low[v]);
                if (parent != -1 && low[v] >= disc[u]) {   // non-root test
                    isAP[u] = true;
                }
            } else {                                       // back edge
                low[u] = Math.min(low[u], disc[v]);
            }
        }

        if (parent == -1 && children > 1) {                // root test
            isAP[u] = true;
        }
    }
}
```

### The lines that matter

**1.**

```java
if (parent != -1 && low[v] >= disc[u]) {   // non-root test
```

Two conditions, both essential. `>=` is the vertex version of yesterday's `>`. `parent != -1` keeps the root out, because for the root this test is always true.

**2.**

```java
if (parent == -1 && children > 1) {                // root test
```

`children` counts only **tree** edges - neighbours that were unvisited when the loop reached them. A neighbour reached later through another child is not a separate child, which is why the bowtie's root `0` has `children = 1` despite having two neighbours.

**3.**

```java
low[u] = Math.min(low[u], disc[v]);
```

For a back edge, `disc[v]`, never `low[v]`. Here it genuinely matters - see the "low versus disc" edge case below, where `low[v]` lets a subtree pretend it can escape through the very vertex being removed.

### Java notes

- `isAP` is a `boolean[]`, not a list. A vertex like the centre of a "flower" of triangles satisfies the test once **per child**; adding to a list directly would report it several times.
- Building the answer by scanning `isAP` from `0` to `V - 1` gives ascending order without a sort.
- Some GFG versions pass `int[][] edges` instead of an adjacency list. Build the list first: `V` empty `ArrayList`s, then for each edge add both directions.
- Skipping the parent **by vertex** is safe here even if the input has parallel edges: a duplicate edge back to the parent would only lower `low[v]` to `disc[u]`, and `>=` still fires. (For bridges it is not safe - that is the Day 79 note.)
- Recursion depth can reach `V`. For very large path-shaped inputs, run in a thread with a bigger stack or switch to an explicit stack.

=== edgeCases ===
### No articulation point - a cycle

```text
V = 3, [[0,1], [1,2], [2,0]]  ->  [-1]
```

Every vertex has a detour around it. The root has one DFS child, and `low[2] = 0` keeps every non-root test false. Return `[-1]`, not `[]`.

### The root mistake

```text
V = 3, [[0,1], [1,2], [2,0]]   with the root rule removed  ->  [0]   (wrong)
```

Applying `low[v] >= disc[u]` to the root asks `0 >= 0`, which is true. This is the most common bug in the algorithm, and the triangle is the smallest input that exposes it.

### A path

```text
V = 4, [[0,1], [1,2], [2,3]]  ->  [1, 2]
```

Both inner vertices split the path. The ends do not: `0` is the root with one child, and `3` has no children to test.

### A star, rooted at the centre

```text
V = 4, [[0,1], [0,2], [0,3]]  ->  [0]
```

The root rule fires: `0` has three DFS children, and none of them can reach another except through `0`.

### A star, NOT rooted at the centre

```text
V = 4, [[0,2], [1,2], [2,3]]  ->  [2]
```

The DFS starts at leaf `0`, so the centre `2` is a non-root vertex. Children `1` and `3` each have `low = disc`, which is `>= disc[2]`, so the general test fires. Same answer, different rule - which is why both rules are needed.

### Two vertices, one edge

```text
V = 2, [[0,1]]  ->  [-1]
```

Removing either vertex leaves one vertex alone - still one component. The edge is a bridge, but neither endpoint is an articulation point.

### Single vertex

```text
V = 1, no edges  ->  [-1]
```

### The bowtie - articulation point with no bridges

```text
V = 5, [[0,1], [1,2], [2,0], [1,3], [3,4], [4,1]]  ->  [1]
```

The worked example. With `>` instead of `>=`, the answer would wrongly be `[-1]`.

### Low versus disc - the subtle trap

```text
V = 5, [[0,1], [1,2], [2,0], [2,3], [3,4], [4,2]]  ->  [2]
```

Two triangles sharing vertex `2`, with the DFS starting at `0`. At vertex `4`, the back edge goes to `2`. Using `disc[2] = 2` gives `low[4] = 2`, then `low[3] = 2 >= disc[2] = 2`, and `2` is correctly marked.

Using `low[2]` instead - which is already `0` from the back edge `2 -> 0` - gives `low[3] = 0`, and the test `0 >= 2` fails. The right triangle "escapes" through `2`'s own back edge, which disappears when `2` is removed. The answer would wrongly be `[-1]`.

### A disconnected graph

```text
V = 4, [[0,1], [2,3]]  ->  [-1]
```

The outer loop starts a fresh DFS (with a fresh root) in each component. Each component is a single edge, so nothing qualifies.

=== takeaway ===
> When you see **"which vertex, if removed, disconnects the graph"**, think **disc/low DFS with `low[child] >= disc[u]`**, plus a separate rule for the root: more than one DFS child.

### The core observation

Removing a vertex removes every edge touching it, including back edges that land on it. So a child's subtree survives `u`'s removal only if it can reach strictly **above** `u` - `low[v] < disc[u]`. The root has nothing above it, so its test becomes "are there two subtrees that only meet here?"

### The pattern trigger

```text
           DFS enters u:  disc[u] = low[u] = timer++
                              |
                 for each tree child v of u
                              |
               low[u] = min(low[u], low[v])
                              |
          u is root?  ---- yes ---->  count children; > 1 -> cut vertex
              |
              no
              |
       low[v] >= disc[u] ?  -> cut vertex
```

### The common mistakes

**Using `>` (the bridge test).** Misses every vertex whose subtree escapes only by a back edge landing on the vertex itself - the bowtie's centre.

**Applying the general test to the root.** It is always true there, so every root gets marked.

**Using `low[v]` for a back edge.** Lets a subtree borrow an escape route that passes through the vertex being removed.

**Adding to a list instead of marking a boolean.** Duplicates when a vertex qualifies through several children.

**Returning `[]` for "none".** GFG expects `[-1]`.

### What to remember in six months

> Bridges: `low[v] > disc[u]`. Articulation points: `low[v] >= disc[u]`, and the root is a cut vertex only if it has more than one DFS child.

One DFS, two arrays, two tests. Together with yesterday, this is the complete toolkit for single points of failure in an undirected graph, and the foundation for biconnected components and block-cut trees.
