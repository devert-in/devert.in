=== intro ===
Yesterday (Number of Provinces) used DFS for one job: walk outward from a vertex and mark everything you can reach. A visited neighbour meant nothing - you just skipped it.

Today the same traversal is asked a sharper question, and the visited neighbour becomes the whole answer.

> In an undirected graph, every edge looks like a way back to where you came from. The habit this day teaches: before you treat "already visited" as a signal, subtract the one edge that was always going to lead somewhere visited - the edge you arrived on.

=== problem ===
You are given an **undirected** graph with `V` vertices numbered `0` to `V - 1`, as an adjacency list `adj`, where `adj.get(u)` lists every neighbour of `u`. Return `true` if the graph contains a **cycle**, otherwise `false`.

A cycle is a path that starts and ends at the same vertex, uses at least one edge, and never reuses an edge.

### The example used all day

```text
V = 5
edges: 0-1, 1-2, 1-3, 2-3, 3-4

adj:
  0 -> [1]
  1 -> [0, 2, 3]
  2 -> [1, 3]
  3 -> [1, 2, 4]
  4 -> [3]
```

```text
        0
        |
        1
       / \
      2 - 3
          |
          4
```

| vertex | neighbours | degree |
| -----: | :--------- | -----: |
| 0 | 1 | 1 |
| 1 | 0, 2, 3 | 3 |
| 2 | 1, 3 | 2 |
| 3 | 1, 2, 4 | 3 |
| 4 | 3 | 1 |

Answer: `true`. The triangle `1 - 2 - 3 - 1` is a cycle.

Remove the edge `2-3` and the same picture is a **tree** - five vertices, four edges, no cycle - so the answer becomes `false`. Keep both versions in mind; the brute force behaves very differently on them.

### Why "undirected" makes this harder than it sounds

Every undirected edge `u-v` is stored **twice**: `v` is in `adj.get(u)` and `u` is in `adj.get(v)`. So the moment you step from `0` to `1`, vertex `1`'s neighbour list contains `0` - a vertex you have already visited.

If "I found a visited neighbour" meant "cycle", then the two-vertex graph `0 - 1` would be reported as cyclic. It is not. That single false alarm is the reason this problem exists.

### Constraints that matter

- The graph may be **disconnected**. A cycle can sit in a component you never reach from vertex `0`.
- The graph is **simple**: no two edges join the same pair of vertices. The brute force below relies on that; the optimal solution does not (see the Java notes).
- `V` and `E` go up to around `10^5`, so anything quadratic in `V` or `E` is out.

=== pattern ===
**Graph traversal (DFS or BFS) with a parent pointer.** The Union-Find alternative is covered in the implementation.

The reframe is about what a "visited neighbour" means during a traversal of an undirected graph. When DFS stands at vertex `node` and looks at a neighbour `next` that is already visited, there are exactly two possibilities:

1. `next` is the vertex we just came from (`parent`). We are looking at the very edge we walked in on, from the other end. That is not a second route - it is the same route.
2. `next` is anything else. Then there are **two different ways** to connect `node` and `next`: the traversal path that already reached `next`, and this edge. Two different routes between the same pair of vertices is precisely a cycle.

```text
    case 1: next == parent           case 2: next != parent

      parent                            next  <- visited earlier
        |                              /    \
        |  same edge, seen twice    path     this edge
        |                              \    /
      node                              node
```

So the whole rule fits on one line:

> A visited neighbour that is not my parent closes a cycle.

### Why it is enough to check the parent

In a DFS of an undirected graph, every edge is either a tree edge (it discovered a new vertex) or it leads back to an **ancestor** on the current path. There are no "cross edges" between separate branches - if the other branch could reach us, DFS would have walked into us from there first. So a visited non-parent neighbour is always an ancestor, and ancestor-to-here along the tree plus this edge is a cycle you can actually point at.

### Recognising it

Reach for traversal-with-parent when:

- the graph is **undirected**
- the question is about loops, redundancy, "is this a tree?", or "would adding this edge create a loop?"
- you need a yes/no, not the cycle itself (though the parent pointers can rebuild it)

The mental question:

> When I reach something I have seen before, is it only because I am looking back down the edge I arrived on?

For **directed** graphs this rule is wrong - a visited vertex there can be a finished side branch, not a loop. That needs a recursion-stack or Kahn's algorithm, which is exactly tomorrow's problem.

=== bruteForce ===
Pretend the parent trick is unknown. What is a definition of "cycle" you could check directly?

> An edge `u-v` lies on a cycle exactly when `u` can still reach `v` **after that edge is deleted**.

If there is another route, that route plus the edge is a cycle. If there is not, the edge is a bridge and no cycle uses it. So: for every edge, pretend it is gone and run a BFS from `u` looking for `v`. Any success means the graph has a cycle.

### Step logic

1. Walk every undirected edge once (from `adj.get(u)`, keep only `u < v` so each edge is checked once).
2. For edge `u-v`, BFS from `u`, refusing to use the step `u -> v`.
3. If the BFS ever sees `v` as a neighbour, return `true`.
4. If every edge fails, return `false`.

A self-loop `u-u` is a cycle on its own, so it returns `true` immediately.

### Dry run on the example

Edges in the order the loop meets them: `(0,1)`, `(1,2)`, `(1,3)`, `(2,3)`, `(3,4)`.

| check | edge removed | poll `x` | neighbour `y` | action | queue after | seen after |
| ----: | :----------- | -------: | ------------: | :----- | :---------- | :--------- |
| 1 | 0-1 | - | - | start at 0 | `[0]` | `{0}` |
| 1 | 0-1 | 0 | 1 | removed edge, skip | `[]` | `{0}` |
| 1 | 0-1 | - | - | queue empty, 1 not reached | - | - |
| 2 | 1-2 | - | - | start at 1 | `[1]` | `{1}` |
| 2 | 1-2 | 1 | 0 | new, enqueue | `[0]` | `{1, 0}` |
| 2 | 1-2 | 1 | 2 | removed edge, skip | `[0]` | `{1, 0}` |
| 2 | 1-2 | 1 | 3 | new, enqueue | `[0, 3]` | `{1, 0, 3}` |
| 2 | 1-2 | 0 | 1 | seen, ignore | `[3]` | `{1, 0, 3}` |
| 2 | 1-2 | 3 | 1 | seen, ignore | `[]` | `{1, 0, 3}` |
| 2 | 1-2 | 3 | 2 | **`y == v`, return `true`** | - | - |

Check 1 fails: `0-1` is a bridge. Check 2 succeeds: `1` reaches `2` the long way round, through `3`. The route `1 -> 3 -> 2` plus the deleted edge `2-1` is the triangle.

### The same brute force on the tree version

Drop edge `2-3`. Now every check must fail before we may answer `false`:

| check | edge removed | vertices the BFS explores | target reached? |
| ----: | :----------- | :------------------------ | :-------------- |
| 1 | 0-1 | `0` | no |
| 2 | 1-2 | `1, 0, 3, 4` | no |
| 3 | 1-3 | `1, 0, 2` | no |
| 4 | 3-4 | `3, 1, 0, 2` | no |

Answer `false`, after four full searches.

### Java

```java
class Solution {
    public boolean isCycle(int V, ArrayList<ArrayList<Integer>> adj) {

        for (int u = 0; u < V; u++) {
            for (int v : adj.get(u)) {
                if (v == u) return true;          // a self-loop is a cycle on its own
                if (u < v && reachableWithout(u, v, V, adj)) {
                    return true;
                }
            }
        }
        return false;
    }

    // Can u reach v without walking the edge u-v itself?
    private boolean reachableWithout(int u, int v, int V, ArrayList<ArrayList<Integer>> adj) {

        boolean[] seen = new boolean[V];
        Deque<Integer> queue = new ArrayDeque<>();
        queue.offer(u);
        seen[u] = true;

        while (!queue.isEmpty()) {
            int x = queue.poll();
            for (int y : adj.get(x)) {
                if (x == u && y == v) continue;   // the deleted edge
                if (y == v) return true;          // reached v another way
                if (!seen[y]) {
                    seen[y] = true;
                    queue.offer(y);
                }
            }
        }
        return false;
    }
}
```

Only one direction of the deleted edge needs skipping: the search returns the instant it sees `v`, so it never stands on `v` and never looks back along `v -> u`.

### Complexity

**Time:** `O(E * (V + E))` - **Space:** `O(V)`

### Where it hurts

Look at the tree table. Check 2 explored `1, 0, 3, 4`. Check 4 explored `3, 1, 0, 2`. They walked almost the same vertices along the same edges, each time starting from scratch with a fresh `seen[]`.

Every check re-answers the same underlying question - "what is connected to what?" - and throws the answer away. On a graph with no cycle, which is the worst case, all `E` checks run to completion, each one costing a full traversal. With `V` and `E` near `10^5` that is around `10^10` steps.

And here is the waste that matters: a single traversal *already* discovers "I can reach this vertex by a second route". It is the moment it bumps into a vertex it has already seen. The brute force has to delete an edge to notice that only because it never kept track of which edge it came in on.

=== optimization ===
### The observation

Run one DFS over the whole graph and remember, for each call, the vertex it came from. When the DFS at `node` meets a visited neighbour `next`:

- if `next == parent`, it is the arrival edge seen from the other side - ignore it
- otherwise, `next` was reached by an earlier route, and this edge is a **second** route - cycle

That is the brute force's "reachable after deleting the edge" test, done for every edge at once, inside a single traversal. The parent check *is* the edge deletion: it removes exactly the arrival edge from consideration, and nothing else.

### Step by step

1. `visited[]` all false.
2. For each vertex `start` that is still unvisited, call `dfs(start, -1)`. (`-1` means "no parent", because the root arrived from nowhere.)
3. `dfs(node, parent)`: mark `node`; for each neighbour `next`:
   - unvisited: recurse `dfs(next, node)`; if it found a cycle, pass `true` up
   - visited and `next != parent`: return `true`
   - visited and `next == parent`: skip
4. If every start finishes, return `false`.

### Dry run on the same example

| step | current call | neighbour | visited? | `== parent`? | action | visited after |
| ---: | :----------- | --------: | :------- | :----------- | :----- | :------------ |
| 1 | `dfs(0, -1)` | - | - | - | mark 0 | `{0}` |
| 2 | `dfs(0, -1)` | 1 | no | - | recurse `dfs(1, 0)` | `{0}` |
| 3 | `dfs(1, 0)` | - | - | - | mark 1 | `{0, 1}` |
| 4 | `dfs(1, 0)` | 0 | yes | yes | skip - arrival edge | `{0, 1}` |
| 5 | `dfs(1, 0)` | 2 | no | - | recurse `dfs(2, 1)` | `{0, 1}` |
| 6 | `dfs(2, 1)` | - | - | - | mark 2 | `{0, 1, 2}` |
| 7 | `dfs(2, 1)` | 1 | yes | yes | skip - arrival edge | `{0, 1, 2}` |
| 8 | `dfs(2, 1)` | 3 | no | - | recurse `dfs(3, 2)` | `{0, 1, 2}` |
| 9 | `dfs(3, 2)` | - | - | - | mark 3 | `{0, 1, 2, 3}` |
| 10 | `dfs(3, 2)` | 1 | yes | **no** | **return `true`** | `{0, 1, 2, 3}` |

`true` then bubbles out through `dfs(2, 1)`, `dfs(1, 0)` and `dfs(0, -1)`.

Read row 10 against the call stack at that moment:

```text
call stack:   dfs(0,-1) -> dfs(1,0) -> dfs(2,1) -> dfs(3,2)
tree path:        0     ->    1     ->    2     ->    3
edge found:                               3 - 1
cycle:        1 -> 2 -> 3 -> 1
```

`1` is an ancestor of `3` on the current path. The tree path `1 -> 2 -> 3` plus the edge `3 - 1` is the triangle. Rows 4 and 7 are the false alarms that a naive "visited means cycle" rule would have reported.

### The same DFS on the tree version

Without edge `2-3`, vertex `2`'s list is just `[1]` and vertex `3`'s is `[1, 4]`:

| step | current call | neighbour | visited? | `== parent`? | action |
| ---: | :----------- | --------: | :------- | :----------- | :----- |
| 1 | `dfs(0, -1)` | 1 | no | - | recurse `dfs(1, 0)` |
| 2 | `dfs(1, 0)` | 0 | yes | yes | skip |
| 3 | `dfs(1, 0)` | 2 | no | - | recurse `dfs(2, 1)` |
| 4 | `dfs(2, 1)` | 1 | yes | yes | skip, return `false` |
| 5 | `dfs(1, 0)` | 3 | no | - | recurse `dfs(3, 1)` |
| 6 | `dfs(3, 1)` | 1 | yes | yes | skip |
| 7 | `dfs(3, 1)` | 4 | no | - | recurse `dfs(4, 3)` |
| 8 | `dfs(4, 3)` | 3 | yes | yes | skip, return `false` |

Every visited neighbour was a parent. All five vertices visited once, every edge looked at twice (once from each end), answer `false` - one traversal instead of the brute force's four.

### Why the outer loop is not optional

`dfs(0, -1)` only reaches vertex `0`'s component. If the cycle lives in a component with no path from `0`, a single call returns `false` and the answer is wrong. The loop over every unvisited `start` is what makes the check cover the whole graph, and it costs nothing extra: each vertex is still visited exactly once in total.

=== complexity ===
### Time

Each vertex is marked once. Each undirected edge appears twice in the adjacency list and each appearance is looked at once.

```text
O(V + E)
```

### Space

`visited[]` is `V` booleans. The recursion can go `V` calls deep on a path-shaped graph.

```text
O(V)
```

The adjacency list itself is input, not extra space.

### Comparison

| Approach | Time | Extra space | Notes |
| :------- | ---: | ----------: | :---- |
| Delete each edge, BFS for its ends | `O(E * (V + E))` | `O(V)` | re-explores the graph per edge |
| DFS with parent | **`O(V + E)`** | **`O(V)`** | recursion depth up to `V` |
| BFS with parent array | **`O(V + E)`** | **`O(V)`** | no recursion |
| Union-Find over edges | `O(V + E log V)` | `O(V)` | no traversal at all |

The Union-Find bound is for path halving alone, as written below. Add union by rank (Day 68) and it drops to `O(V + E * α(V))`, where `α` is the inverse Ackermann function - at most 4 for any realistic input - so in practice it is linear too.

=== implementation ===
```java
class Solution {
    public boolean isCycle(int V, ArrayList<ArrayList<Integer>> adj) {

        boolean[] visited = new boolean[V];

        // The graph may be disconnected: start a DFS from every unvisited vertex.
        for (int start = 0; start < V; start++) {
            if (!visited[start] && dfs(start, -1, adj, visited)) {
                return true;
            }
        }
        return false;
    }

    private boolean dfs(int node, int parent,
                        ArrayList<ArrayList<Integer>> adj, boolean[] visited) {

        visited[node] = true;

        for (int next : adj.get(node)) {
            if (!visited[next]) {
                if (dfs(next, node, adj, visited)) return true;
            } else if (next != parent) {
                return true;        // visited, and not the edge we arrived on
            }
        }
        return false;
    }
}
```

### The lines that matter

**1.**

```java
} else if (next != parent) {
    return true;        // visited, and not the edge we arrived on
```

The entire algorithm. `else` means `next` is already visited; `next != parent` rules out the arrival edge. What is left is a genuine second route.

**2.**

```java
if (!visited[start] && dfs(start, -1, adj, visited)) {
```

Two things at once. The loop covers disconnected components, and `-1` as the root's parent is safe because no vertex is numbered `-1`, so the root never skips a real neighbour.

**3.**

```java
if (dfs(next, node, adj, visited)) return true;
```

`node` becomes the child's parent. Forgetting to propagate the `true` upward is a classic bug: the deep call finds the cycle, returns `true`, and the caller ignores it and keeps going.

### The BFS version - no recursion

Same rule, with the parent stored in an array because there is no call stack to carry it:

```java
class Solution {
    public boolean isCycle(int V, ArrayList<ArrayList<Integer>> adj) {

        boolean[] visited = new boolean[V];
        int[] parent = new int[V];

        for (int start = 0; start < V; start++) {
            if (visited[start]) continue;

            Deque<Integer> queue = new ArrayDeque<>();
            visited[start] = true;
            parent[start] = -1;
            queue.offer(start);

            while (!queue.isEmpty()) {
                int node = queue.poll();
                for (int next : adj.get(node)) {
                    if (!visited[next]) {
                        visited[next] = true;
                        parent[next] = node;
                        queue.offer(next);
                    } else if (next != parent[node]) {
                        return true;    // reached by two different routes
                    }
                }
            }
        }
        return false;
    }
}
```

### The Union-Find version - from yesterday's toolkit

Add edges one at a time. If an edge joins two vertices that are **already** in the same set, they were connected before this edge arrived, so this edge closes a loop.

```java
class Solution {
    public boolean isCycle(int V, ArrayList<ArrayList<Integer>> adj) {

        int[] root = new int[V];
        for (int i = 0; i < V; i++) root[i] = i;

        for (int u = 0; u < V; u++) {
            for (int v : adj.get(u)) {
                if (u > v) continue;                // each undirected edge once
                int ru = find(root, u), rv = find(root, v);
                if (ru == rv) return true;          // already connected: this edge closes a loop
                root[ru] = rv;
            }
        }
        return false;
    }

    private int find(int[] root, int x) {
        while (root[x] != x) {
            root[x] = root[root[x]];    // path halving
            x = root[x];
        }
        return x;
    }
}
```

On the example: `(0,1)` joins `{0}` and `{1}`; `(1,2)` joins in `2`; `(1,3)` joins in `3`; `(2,3)` finds `2` and `3` share a root - `true`. Note `u > v` skips the second copy of each edge but lets a self-loop `u == u` through, where `find(u) == find(u)` correctly reports a cycle.

### Java notes

- `for (int next : adj.get(node))` auto-unboxes each `Integer` to `int`, so `next != parent` compares values. With two `Integer` objects, `!=` would compare references - keep at least one side `int`.
- Recursion depth equals the longest DFS path. A path graph with `V = 10^5` can overflow Java's default stack; the BFS or Union-Find version has no such limit.
- Parallel edges, if they ever appear, are still caught. With `0-1` stored twice, vertex `1` skips `0` both times as its parent - but back in `dfs(0, -1)`, the second copy of `1` is visited and is not `0`'s parent, so it returns `true`. The brute force is the one that breaks there: deleting `u-v` skips both copies.

=== edgeCases ===
### Two vertices, one edge - the false alarm

```text
V = 2, edges: 0-1  ->  false
```

`dfs(1, 0)` sees `0`, which is visited - but it is the parent. This is the case a "visited means cycle" rule gets wrong.

### A tree

```text
V = 5, edges: 0-1, 1-2, 1-3, 3-4  ->  false
```

Every visited neighbour is a parent. A connected graph with `V - 1` edges is always a tree.

### Smallest real cycle - a triangle

```text
V = 3, edges: 0-1, 1-2, 2-0  ->  true
```

`dfs(2, 1)` sees `0`: visited, not the parent.

### A longer cycle

```text
V = 4, edges: 0-1, 1-2, 2-3, 3-0  ->  true
```

The square. Length does not matter; the visited non-parent neighbour is found at the last vertex.

### The cycle is in another component

```text
V = 6, edges: 0-1, 2-3, 3-4, 4-2   (vertex 5 isolated)  ->  true
```

`dfs(0, -1)` explores only `{0, 1}` and returns `false`. Without the outer loop over every start vertex, the answer would be wrong.

### No edges at all

```text
V = 3, no edges  ->  false
```

Every `dfs` call marks one vertex and has no neighbours to look at.

### A single vertex

```text
V = 1, no edges  ->  false
```

### A self-loop, if the input allows one

```text
V = 2, edges: 0-1, 1-1  ->  true
```

`dfs(1, 0)` sees `1` in its own list: visited, and `1 != 0`. All three versions return `true`.

### Many cycles

```text
V = 4, every pair connected (6 edges)  ->  true
```

The algorithm stops at the first cycle it closes; it does not count them.

=== takeaway ===
> When you see **"cycle in an undirected graph"**, think **traversal with a parent**: a visited neighbour that is not the parent closes a loop. Or think **Union-Find**: an edge whose ends already share a root closes a loop.

### The core observation

In an undirected graph, the edge you arrived on always leads back to a visited vertex, so it says nothing. Every *other* edge to a visited vertex is a second route between two connected vertices, and two routes make a cycle. Ignoring exactly the arrival edge turns one traversal into "delete each edge and re-check" for every edge at once.

### The pattern trigger

```text
        undirected graph, "is there a loop?"
                       |
                       v
       for every unvisited vertex: dfs(start, -1)
                       |
                       v
              look at neighbour `next`
             /           |              \
      unvisited    visited, ==parent   visited, !=parent
          |              |                    |
   dfs(next, node)     skip              CYCLE - true
```

### The common mistakes

**"Visited means cycle."** Reports a cycle on every graph with at least one edge, because every edge is seen from both ends.

**Starting only at vertex 0.** Misses any cycle in another component.

**Dropping the recursive result.** Calling `dfs(next, node, ...)` without `if (...) return true` throws the discovery away.

**Using this on a directed graph.** `A -> B`, `A -> C`, `C -> B` has no directed cycle, yet a DFS from `A` meets `B` again from `C`. Directed graphs need tomorrow's tools.

### What to remember in six months

> Undirected cycle = a second route. Subtract the edge you came in on; anything visited that is left is the second route.

The same question shows up as "Graph Valid Tree" (LC 261: connected and no cycle), "Redundant Connection" (LC 684: the first edge Union-Find finds already connected), and Kruskal's minimum spanning tree, which is nothing but "add edges cheapest-first, skipping the ones Union-Find says would close a loop".
