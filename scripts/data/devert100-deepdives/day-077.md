=== intro ===
Days 74 to 76 were all about **one source**: the cheapest way from a start node to every other node. Today there is no source. The question becomes "what is the cheapest set of edges that connects **everyone** to everyone?" - a minimum spanning tree. It closes week 11 and introduces the second big family of graph algorithms: greedy over edges.

> When you need to connect everything as cheaply as possible, you never have to search over combinations. The cheapest edge that crosses between "already connected" and "not yet connected" is always safe to take.

=== problem ===
You are given `n` points on a 2D plane, `points[i] = [x, y]`. Connecting two points costs their **Manhattan distance**:

```text
cost(a, b) = |xa - xb| + |ya - yb|
```

Return the minimum total cost to make all points connected - every point reachable from every other through the connections you chose.

### The worked example used all day

```text
points = [[0,0], [2,2], [3,10], [5,2]]
            P0     P1     P2      P3
```

There is an edge between **every** pair of points (the graph is complete). With 4 points that is 6 edges:

| edge | between | cost |
| :--- | :------ | ---: |
| e0 | P0 - P1 | 2 + 2 = 4 |
| e1 | P0 - P2 | 3 + 10 = 13 |
| e2 | P0 - P3 | 5 + 2 = 7 |
| e3 | P1 - P2 | 1 + 8 = 9 |
| e4 | P1 - P3 | 3 + 0 = 3 |
| e5 | P2 - P3 | 2 + 8 = 10 |

The cheapest way to connect all four:

```text
           P2
           |
           | 9
           |
  P0 --4-- P1 --3-- P3

total = 4 + 9 + 3 = 16
```

```text
answer = 16
```

### What "connected" requires

With `n` points, you need **exactly `n - 1`** connections, and they must not form a cycle:

- fewer than `n - 1` edges cannot connect `n` points
- any cycle contains an edge you could remove without disconnecting anything, so a cheapest answer never has one

`n - 1` edges, connected, no cycle - that is a **tree** that spans every point. The cheapest one is the **minimum spanning tree (MST)**.

### What makes it non-trivial

The obvious greedy - "take the 3 cheapest edges" - fails. The three cheapest here are `e4 (3)`, `e0 (4)` and `e2 (7)`, totalling `14`, but they are `P1-P3`, `P0-P1` and `P0-P3`: a triangle. `P2` is left out. You need cheap edges **that also make progress**.

### Constraints that matter

- `1 <= n <= 1000`
- coordinates between `-10^6` and `10^6`
- the edges are implicit: `n(n-1)/2`, up to about **500,000** of them. The graph is as **dense** as a graph can be, and that decides which MST algorithm wins.

=== pattern ===
**Minimum Spanning Tree** - Prim's or Kruskal's algorithm.

### The one fact both algorithms rest on: the cut property

Split the points into any two non-empty groups - call it a **cut**. Some edges cross between the groups. The **cheapest crossing edge** belongs to some minimum spanning tree.

Why: every spanning tree must cross the cut somewhere, or the two groups would be disconnected. If a tree crosses with a more expensive edge, swap it for the cheapest crossing edge. The result is still a spanning tree, and no more expensive. So the cheapest crossing edge is always safe to take.

The two algorithms are two ways of choosing which cut to look at:

| | Kruskal | Prim |
| :- | :------ | :--- |
| grows | a forest of pieces that merge | one tree from a start point |
| looks at | edges in sorted order, globally | the cheapest edge leaving the current tree |
| needs | sort + Disjoint Set Union | min-heap, or a plain array for dense graphs |
| skips an edge when | its ends are already in the same piece | its far end is already in the tree |

### MST is not a shortest-path tree

Yesterday's algorithms minimised the distance **from a source** to each node. An MST minimises the **total weight of edges used**. In the example, the MST path from `P0` to `P3` is `P0 - P1 - P3` costing `7` - the same as the direct edge, but that is luck; in general the MST path between two nodes can be far longer than their shortest path. Different question, different algorithm.

### Recognising it

Reach for MST when:

- "connect all", "minimum cost to connect", "minimum wiring / cabling / roads"
- every node must end up reachable, and you pay per edge used
- there is no source and no destination

The mental question:

> Am I paying for edges to connect everything, rather than finding a route? Then it is an MST, and the cheapest edge that joins two separate pieces is always safe.

=== bruteForce ===
Without the cut property, the honest approach is: a spanning tree has exactly `n - 1` edges, so **try every set of `n - 1` edges**, keep those that connect everything, and take the cheapest.

### Step logic

1. Build every edge `(i, j, cost)` for `i < j`.
2. Recursively choose `n - 1` edges out of them (combinations, in index order).
3. For each chosen set, check it is a spanning tree. With exactly `n - 1` edges, "connects everything" is the same as "has no cycle" - check by merging endpoints into groups and failing if an edge joins two points already in the same group.
4. Track the minimum cost among the sets that pass.

### Java

```java
class Solution {
    private int[][] edges;          // {i, j, cost}
    private int n;
    private int best;

    public int minCostConnectPoints(int[][] points) {

        n = points.length;
        List<int[]> list = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                int cost = Math.abs(points[i][0] - points[j][0]) + Math.abs(points[i][1] - points[j][1]);
                list.add(new int[] {i, j, cost});
            }
        }
        edges = list.toArray(new int[0][]);

        best = Integer.MAX_VALUE;
        choose(0, new ArrayList<>(), 0);
        return best;
    }

    // Try every combination of n - 1 edges, starting from index `start`.
    private void choose(int start, List<Integer> picked, int cost) {

        if (picked.size() == n - 1) {
            if (isSpanningTree(picked)) best = Math.min(best, cost);
            return;
        }

        for (int e = start; e < edges.length; e++) {
            picked.add(e);
            choose(e + 1, picked, cost + edges[e][2]);
            picked.remove(picked.size() - 1);
        }
    }

    // n - 1 edges with no cycle connect all n points.
    private boolean isSpanningTree(List<Integer> picked) {

        int[] group = new int[n];
        for (int i = 0; i < n; i++) group[i] = i;

        for (int e : picked) {
            int a = root(group, edges[e][0]);
            int b = root(group, edges[e][1]);
            if (a == b) return false;       // this edge closes a cycle
            group[a] = b;
        }
        return true;
    }

    private int root(int[] group, int x) {
        while (group[x] != x) x = group[x];
        return x;
    }
}
```

### Complexity

**Time:** `O(C(E, n-1) * n)` where `E = n(n-1)/2` - **Space:** `O(E)`

### Where it hurts

The number of sets to try is "choose `n - 1` out of `n(n-1)/2`":

| points | edges | sets tried | of which are spanning trees |
| -----: | ----: | ---------: | --------------------------: |
| 4 | 6 | 20 | 16 |
| 6 | 15 | 3,003 | 1,296 |
| 8 | 28 | 1,184,040 | 262,144 |
| 10 | 45 | 886,163,135 | 100,000,000 |

(The last column is Cayley's formula, `n^(n-2)` spanning trees in a complete graph.) `n` goes up to `1000`. This dies at `n = 10`.

Look at the table for where the work goes. Edge `e4` (cost 3) is the cheapest edge in the whole graph, yet half of the 20 sets **leave it out** - and every one of those sets is more expensive than the best one that includes it. Edge `e1` (cost 13) is the most expensive, can always be replaced, and still appears in 10 sets.

We are re-deciding the same question - "should this edge be in?" - in millions of combinations, when some edges are obviously in (the cheapest one) and some are obviously out (one that closes a cycle). So:

> Is there a rule that tells me, edge by edge, whether an edge is safe to take - so I decide each edge once instead of once per combination?

=== optimization ===
### The key observation - the cut property

Split the points into two groups. The **cheapest edge crossing between them** is in a minimum spanning tree. (Swap argument: any spanning tree must cross somewhere; replacing its crossing edge with the cheapest one keeps it a tree and cannot raise the cost.)

That turns a search into a sequence of safe greedy decisions. Each decision is final, so each edge is looked at a bounded number of times.

### First derivation: Kruskal - sort all edges, take each one that joins two pieces

Sort every edge by cost. Walk them in order. If an edge joins two points that are **not yet connected**, take it - it is the cheapest edge crossing the cut between "that point's piece" and "everything else", so it is safe. If its ends are already connected, it would close a cycle - skip it. Stop after `n - 1` edges.

Same example, edges sorted:

| step | edge | cost | already connected? | action | pieces after | total |
| ---: | :--- | ---: | :----------------- | :----- | :----------- | ----: |
| 1 | P1-P3 | 3 | no | **take** | {P0} {P1,P3} {P2} | 3 |
| 2 | P0-P1 | 4 | no | **take** | {P0,P1,P3} {P2} | 7 |
| 3 | P0-P3 | 7 | **yes** (via P1) | skip - would close a cycle | {P0,P1,P3} {P2} | 7 |
| 4 | P1-P2 | 9 | no | **take** - 3 edges, done | {P0,P1,P2,P3} | 16 |

Answer `16`, deciding 4 edges once each instead of trying 20 sets. Step 3 is exactly set 6 of the brute force, rejected in one check.

But on this problem Kruskal has to **build and sort all `n(n-1)/2` edges** first: 500,000 edges, `O(n^2 log n)` time and `O(n^2)` memory. On a complete graph, we can do better.

### The better fit: Prim - grow one tree, keep one number per point

Prim uses the cut "points in the tree" vs "points not in the tree". Start the tree with any point. Repeatedly add the outside point that is **cheapest to attach**, using the cheapest edge from it into the tree.

The trick for dense graphs: keep `minDist[v]` = the cheapest edge from `v` to **any** point already in the tree. Then:

1. pick the outside point with the smallest `minDist` - a plain scan over `n` points
2. add it to the tree and add its `minDist` to the total
3. it is a new tree member, so every outside point gets one more candidate edge: `minDist[v] = min(minDist[v], cost(u, v))`

Every edge is computed on the fly, at most once in each direction - no edge list, no sort, no heap.

### Dry run - same example

```text
minDist = [0, inf, inf, inf]      start from P0 (minDist 0 = free to add)
inTree  = [F, F, F, F]
```

| round | outside points' `minDist` | pick | total | update from the picked point | `minDist` after |
| ----: | :------------------------ | :--- | ----: | :--------------------------- | :-------------- |
| 1 | P0 0, P1 inf, P2 inf, P3 inf | P0 (0) | 0 | P1: min(inf, 4) = 4, P2: min(inf, 13) = 13, P3: min(inf, 7) = 7 | -, 4, 13, 7 |
| 2 | P1 4, P2 13, P3 7 | P1 (4) | 4 | P2: min(13, 9) = 9, P3: min(7, **3**) = 3 | -, -, 9, 3 |
| 3 | P2 9, P3 3 | P3 (3) | 7 | P2: min(9, 10) = 9 | -, -, 9, - |
| 4 | P2 9 | P2 (9) | 16 | nothing left outside | -, -, -, - |

```text
answer = 16
```

Same tree as Kruskal - edges `P0-P1`, `P1-P3`, `P1-P2` - found in a different order. Watch row 2: adding `P1` dropped `P3`'s cost from `7` to `3`, because `P3` is closer to `P1` than to `P0`. That one update is the whole algorithm: each round, the outside points learn about the newest tree member, and nothing else needs revisiting.

=== complexity ===
### Time

Prim, array version: `n` rounds. Each round scans `n` points to pick the minimum and updates up to `n` points.

```text
O(n^2)
```

For `n = 1000` that is about 2 million steps. It is linear in the number of edges, `n(n-1)/2`, and you cannot do better on a complete graph, because every edge is a candidate and has to be looked at at least once.

### Space

`minDist` and `inTree`, one slot per point. No edge list.

```text
O(n)
```

### Comparison

| Approach | Time | Space | Best when |
| :------- | ---: | ----: | :-------- |
| Try every set of `n - 1` edges | `O(C(n^2/2, n-1) * n)` | `O(n^2)` | never |
| Kruskal (sort + DSU) | `O(E log E) = O(n^2 log n)` | `O(n^2)` | sparse graphs, edges given as a list |
| Prim with a min-heap | `O(E log V) = O(n^2 log n)` | `O(n^2)` heap entries | sparse graphs, adjacency list |
| Prim with an array | **`O(n^2)`** | **`O(n)`** | **dense graphs - like this one** |

The general rule: on a sparse graph (`E` close to `V`), Kruskal or heap Prim. On a dense graph (`E` close to `V^2`), array Prim - the `log` factor from sorting or the heap costs more than the plain scan saves.

=== implementation ===
```java
class Solution {
    public int minCostConnectPoints(int[][] points) {

        int n = points.length;

        // minDist[v] = cheapest edge from v to any point already in the tree.
        int[] minDist = new int[n];
        Arrays.fill(minDist, Integer.MAX_VALUE);
        boolean[] inTree = new boolean[n];

        minDist[0] = 0;                     // start the tree at point 0, for free
        int total = 0;

        for (int added = 0; added < n; added++) {

            // 1. Pick the outside point that is cheapest to attach.
            int u = -1;
            for (int v = 0; v < n; v++) {
                if (!inTree[v] && (u == -1 || minDist[v] < minDist[u])) u = v;
            }

            // 2. Attach it.
            inTree[u] = true;
            total += minDist[u];

            // 3. Every outside point gets one new candidate edge: to u.
            for (int v = 0; v < n; v++) {
                if (inTree[v]) continue;
                int cost = Math.abs(points[u][0] - points[v][0]) + Math.abs(points[u][1] - points[v][1]);
                if (cost < minDist[v]) minDist[v] = cost;
            }
        }

        return total;
    }
}
```

### The lines that matter

**1.**

```java
if (!inTree[v] && (u == -1 || minDist[v] < minDist[u])) u = v;
```

The `O(n)` scan that replaces a heap. On a complete graph a heap would hold up to `n^2` entries; this holds none.

**2.**

```java
if (cost < minDist[v]) minDist[v] = cost;
```

The only update Prim needs. A point's cheapest connection to the tree can only change when a new point joins the tree, and only to an edge touching that new point - so comparing against `u` alone is enough.

**3.**

```java
minDist[0] = 0;                     // start the tree at point 0, for free
```

Any start point gives the same total, because every MST has the same weight. Setting its `minDist` to `0` makes round 1 pick it without a special case, and adds `0` to the total.

### The Kruskal version, for comparison

```java
class Solution {
    private static class DSU {
        private final int[] parent;
        private final int[] rank;

        DSU(int n) {
            parent = new int[n];
            rank = new int[n];
            for (int i = 0; i < n; i++) parent[i] = i;
        }

        int find(int x) {
            while (parent[x] != x) {
                parent[x] = parent[parent[x]];   // path halving
                x = parent[x];
            }
            return x;
        }

        boolean union(int a, int b) {
            int ra = find(a), rb = find(b);
            if (ra == rb) return false;          // already connected
            if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
            parent[rb] = ra;
            if (rank[ra] == rank[rb]) rank[ra]++;
            return true;
        }
    }

    public int minCostConnectPoints(int[][] points) {

        int n = points.length;
        List<int[]> edges = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                int cost = Math.abs(points[i][0] - points[j][0]) + Math.abs(points[i][1] - points[j][1]);
                edges.add(new int[] {cost, i, j});
            }
        }
        edges.sort((a, b) -> Integer.compare(a[0], b[0]));

        DSU dsu = new DSU(n);
        int total = 0, used = 0;
        for (int[] e : edges) {
            if (used == n - 1) break;            // a spanning tree has exactly n - 1 edges
            if (dsu.union(e[1], e[2])) {
                total += e[0];
                used++;
            }
        }
        return total;
    }
}
```

Correct and accepted, but it materialises all `n(n-1)/2` edges and sorts them. Disjoint Set Union gets its own day tomorrow (Redundant Connection) - for now, `union` returning `false` means "this edge would close a cycle".

### Java notes

- `Integer.MAX_VALUE` as the starting `minDist` is safe here because it is only ever **compared**, never added to. `total += minDist[u]` happens only after `u` was picked, and from round 2 on every outside point has a real cost (the graph is complete).
- Manhattan distance between coordinates in `[-10^6, 10^6]` is at most `4 * 10^6`, so each cost fits in an `int`. LeetCode guarantees the total fits as well.
- `boolean[] inTree` defaults to all `false` - no fill needed.

### The worked example

### Single point

```text
[[0,0]]  ->  0
```

Nothing to connect. Prim runs one round, picks point 0 at cost `0`, and returns `0`. The brute force chooses `0` edges - one empty set, trivially a tree.

### Two points

```text
[[0,0],[1,1]]  ->  2
```

Exactly one edge, which is the whole tree.

### LeetCode's first example

```text
[[0,0],[2,2],[3,10],[5,2],[7,0]]  ->  20
```

Our example plus `P4 = (7,0)`, attached by `P3-P4` at cost `2 + 2 = 4`: `16 + 4 = 20`.

### LeetCode's second example, negative coordinates

```text
[[3,12],[-2,5],[-4,1]]  ->  18
```

Costs `12`, `18` and `6`; the tree takes `6 + 12`. `Math.abs` handles the signs.

### Points on a line

```text
[[0,0],[1,0],[2,0],[3,0]]  ->  3
```

The MST is the chain of neighbours, three edges of cost `1`.

### Ties - many MSTs, one cost

```text
[[0,0],[0,1],[1,0],[1,1]]  ->  3
```

Four edges of cost `1` around the square, two of cost `2` across it. Any three of the unit edges form an MST. Prim and Kruskal may pick different trees, but the **total** is unique - which is all the problem asks for.

### Duplicate points

```text
[[1,1],[1,1],[4,5]]  ->  7
```

The problem says points are distinct, but the algorithm does not care: two identical points connect at cost `0`, and the third attaches at `3 + 4 = 7`.

=== takeaway ===
> When you see **"connect all of them at minimum total cost"**, think **minimum spanning tree**: the cheapest edge joining two separate pieces is always safe. On a dense or complete graph, use **array Prim**, `O(n^2)`.

### The core observation

The cut property: across any split of the points, the cheapest crossing edge belongs to an MST. So the MST can be built by safe greedy steps - Kruskal by taking globally cheapest edges that join two pieces, Prim by repeatedly attaching the outside point closest to the tree.

### The pattern trigger

```text
     "connect all", pay per edge, no source
                    |
                    v
                   MST
            /              \
   edges given,        complete / dense graph,
   sparse              edges implicit
       |                      |
   Kruskal:              Prim (array):
   sort edges,           minDist[] to the tree,
   DSU skips cycles      pick min, update from it
   O(E log E)            O(n^2)
                    |
                    v
          always exactly n - 1 edges
```

### The common mistakes

**Taking the `n - 1` cheapest edges.** They can form a cycle and leave a point out - set 6 in the dry run.

**Confusing MST with shortest paths.** Dijkstra minimises distance from one source; an MST minimises total edge weight. Running Dijkstra and summing the distances does not give this answer.

**Building all edges for Prim with a heap on a complete graph.** It works, but it is `O(n^2 log n)` time and `O(n^2)` memory for nothing. The array version is simpler and faster.

**Forgetting to stop Kruskal at `n - 1` edges.** Not wrong, just wasted iterations over the remaining sorted edges.

### What to remember in six months

> MST = cut property + greedy. Kruskal picks edges globally with a DSU; Prim grows one tree with a `minDist` array. Dense graph, array Prim.
