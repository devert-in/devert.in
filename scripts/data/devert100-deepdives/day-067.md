=== intro ===
Yesterday's graph was hidden in a grid, and the visited set was the grid itself - a sunk cell. Today the graph is explicit, made of real node objects, and the visited set has to do a second job: it must also remember **what you built** for each node you visited.

> When you traverse a graph to **build** something per node, the visited set should be a map from each original node to the thing you built for it. "Have I seen this?" and "what did I make for it?" are then the same `O(1)` lookup.

=== problem ===
You are given a reference to one node of a **connected, undirected** graph. Return a **deep copy** of the whole graph: brand-new node objects, with the same values and the same connections, sharing nothing with the original.

LeetCode defines the node like this (it is provided - you do not declare it):

```text
class Node {
    public int val;
    public List<Node> neighbors;
}
```

### The example

```text
adjList = [[2,4],[1,3],[2,4],[1,3]]

    1 --- 2
    |     |
    4 --- 3
```

Row `i` lists the neighbours of the node with value `i + 1`.

| node | neighbours |
| ---: | :--------- |
| 1 | 2, 4 |
| 2 | 1, 3 |
| 3 | 2, 4 |
| 4 | 1, 3 |

You receive node `1`. You return a new node `1'` whose neighbours are new nodes `2'` and `4'`, and so on - the same square, built from fresh objects.

### Constraints that matter

- `0` to `100` nodes. Zero nodes means the input is `null`.
- Values are `1..n` and unique, but that is a convenience of the test format. A good solution never relies on it.
- No self-loops or repeated edges. The graph is connected, so every node is reachable from the one you are given.

### What makes it non-trivial

**Undirected means every edge is stored twice.** Node `1` lists `2`, and node `2` lists `1`. So the graph always contains cycles, and any traversal that does not remember where it has been walks `1 -> 2 -> 1 -> 2 ...` forever.

**A deep copy must preserve identity.** Node `1'` and node `3'` both connect to `2'` - they must point to the **same** `2'` object, not two different copies that happen to hold the value `2`. Creating a fresh copy every time you meet a node produces a tree of duplicates, not a copy of the graph.

The tempting first attempt fails on both counts:

```text
clone(node):
    copy = new Node(node.val)
    for each neighbour: copy.neighbors.add(clone(neighbour))
    return copy

clone(1) -> clone(2) -> clone(1) -> clone(2) -> ...   StackOverflowError
```

=== pattern ===
**Graph traversal (DFS or BFS) with a HashMap from original node to its clone.**

The map is doing two jobs at once:

1. **Visited set.** If a node is already a key, we have reached it before - do not traverse it again. That breaks the cycles.
2. **Identity table.** The value is the one clone for that original. Every edge that points at the original must point at this exact object in the copy.

```text
map:   original 1  ->  clone 1'
       original 2  ->  clone 2'
       ...

edge 3 -- 2 in the original   becomes   3'.neighbors.add( map.get(2) )
```

### Recognising it

Reach for "traverse + map old to new" when:

- the task says **deep copy**, **clone** or **duplicate** a structure with **shared references** or **cycles** (graphs, linked lists with random pointers, object graphs)
- several parts of the structure can point at the same object, and the copy must keep that sharing

Same skeleton: Copy List with Random Pointer (LC 138), Clone Binary Tree With Random Pointer (LC 1485), Clone N-ary Tree (LC 1490), and serialisation of any object graph.

The mental question:

> When I meet this node again through a different edge, do I need the **same** object I built the first time?

If yes, you need a map from original to copy, not just a visited flag.

=== bruteForce ===
Assume we know we must not loop forever, but have not yet thought of a map. Break the job into three separate phases, each using only lists:

1. **Collect** every original node with a DFS. Use a list as the "seen" set - `contains` scans it.
2. **Create** one clone per original, stored at the same index in a parallel list.
3. **Wire** the edges: for every original node `i` and every neighbour, find the neighbour's index with `indexOf` (another scan), and add the clone at that index to clone `i`'s neighbours.

### Dry run - phase 1, collecting

The stack top is written last.

| step | pop | neighbour | `contains` result | action | `originals` | stack |
| ---: | --: | --------: | :---------------- | :----- | :---------- | :---- |
| 0 | - | - | - | start at 1 | `[1]` | `[1]` |
| 1 | 1 | 2 | not found (scanned 1) | add, push | `[1, 2]` | `[2]` |
| 2 | 1 | 4 | not found (scanned 2) | add, push | `[1, 2, 4]` | `[2, 4]` |
| 3 | 4 | 1 | found | skip | `[1, 2, 4]` | `[2]` |
| 4 | 4 | 3 | not found (scanned 3) | add, push | `[1, 2, 4, 3]` | `[2, 3]` |
| 5 | 3 | 2 | found | skip | `[1, 2, 4, 3]` | `[2]` |
| 6 | 3 | 4 | found | skip | `[1, 2, 4, 3]` | `[2]` |
| 7 | 2 | 1 | found | skip | `[1, 2, 4, 3]` | `[]` |
| 8 | 2 | 3 | found | skip | `[1, 2, 4, 3]` | `[]` |

### Phase 2, creating

```text
index:      0    1    2    3
originals: [1,   2,   4,   3 ]
clones:    [1',  2',  4',  3']     no edges yet
```

### Dry run - phase 3, wiring

| `i` | original | neighbour | `indexOf` result | edge added | clone's neighbours after |
| --: | -------: | --------: | ---------------: | :--------- | :----------------------- |
| 0 | 1 | 2 | 1 | `1' -> 2'` | `[2']` |
| 0 | 1 | 4 | 2 | `1' -> 4'` | `[2', 4']` |
| 1 | 2 | 1 | 0 | `2' -> 1'` | `[1']` |
| 1 | 2 | 3 | 3 | `2' -> 3'` | `[1', 3']` |
| 2 | 4 | 1 | 0 | `4' -> 1'` | `[1']` |
| 2 | 4 | 3 | 3 | `4' -> 3'` | `[1', 3']` |
| 3 | 3 | 2 | 1 | `3' -> 2'` | `[2']` |
| 3 | 3 | 4 | 2 | `3' -> 4'` | `[2', 4']` |

Return `clones[0]`, which is `1'`. Every clone's neighbour list matches the original's, in the same order, and every edge points at the single shared clone. Correct.

### Java

```java
class Solution {
    public Node cloneGraph(Node node) {
        if (node == null) {
            return null;
        }

        // Phase 1: collect every original node, using a list as the seen-set.
        List<Node> originals = new ArrayList<>();
        Deque<Node> stack = new ArrayDeque<>();
        originals.add(node);
        stack.push(node);
        while (!stack.isEmpty()) {
            Node cur = stack.pop();
            for (Node next : cur.neighbors) {
                if (!originals.contains(next)) {   // linear scan
                    originals.add(next);
                    stack.push(next);
                }
            }
        }

        // Phase 2: one clone per original, at the same index.
        List<Node> clones = new ArrayList<>();
        for (Node original : originals) {
            clones.add(new Node(original.val));
        }

        // Phase 3: wire edges, finding each neighbour's index by scanning.
        for (int i = 0; i < originals.size(); i++) {
            for (Node next : originals.get(i).neighbors) {
                int j = originals.indexOf(next);   // linear scan
                clones.get(i).neighbors.add(clones.get(j));
            }
        }
        return clones.get(0);
    }
}
```

### Complexity

**Time:** `O(V * E)` - **Space:** `O(V)`

### Where it hurts

Every row of both tables that says "scanned" or "`indexOf`" is a linear search through a list of up to `V` nodes, and there is one such search per **adjacency entry** - `2E` of them in an undirected graph. So the work is `O(V * E)`. On a dense graph of `V` nodes, `E` is about `V^2 / 2`, and this becomes `O(V^3)`.

Two separate wastes are visible:

- **The same question is answered by scanning, over and over.** "Have I seen this node?" in phase 1 and "where is this node's clone?" in phase 3 are both lookups keyed by a node - exactly what a hash map does in `O(1)`.
- **The graph is walked twice.** Phase 1 visits every edge to discover nodes; phase 3 visits every edge again to wire them. If the clone of a node existed the moment we discovered it, we could wire each edge on the first visit.

=== optimization ===
### Name the repeated work

Two lists searched linearly by node, and two full passes over the edges.

### The key observation

Replace both lists with one `HashMap<Node, Node>` from original to clone, and create the clone **the moment the original is first discovered**. Then:

- "Have I seen it?" is `cloneOf.containsKey(node)` - `O(1)`.
- "Which clone is it?" is `cloneOf.get(node)` - `O(1)`.
- Because the clone already exists when we look at an edge, the edge can be wired immediately. One traversal does everything.

### The rule that makes cycles safe

Put the clone into the map **before** visiting its neighbours. In the square, cloning `1` leads to `2`, which leads straight back to `1`. At that moment `1'` is unfinished - it has no neighbours yet - but it **exists** and is in the map. So the call for `1` returns the existing `1'` instead of recursing again. The unfinished clone gets its remaining edges when the outer call resumes.

### Dry run on the same square

`clone(x)` is the recursive helper. Indentation in the "call" column shows depth.

| step | call | in map? | action | map keys after | edge added on return |
| ---: | :--- | :------ | :----- | :------------- | :------------------- |
| 1 | `clone(1)` | no | create `1'`, register, visit `[2, 4]` | 1 | - |
| 2 | `. clone(2)` | no | create `2'`, register, visit `[1, 3]` | 1, 2 | - |
| 3 | `. . clone(1)` | **yes** | return existing `1'` | 1, 2 | `2' -> 1'` |
| 4 | `. . clone(3)` | no | create `3'`, register, visit `[2, 4]` | 1, 2, 3 | - |
| 5 | `. . . clone(2)` | **yes** | return existing `2'` | 1, 2, 3 | `3' -> 2'` |
| 6 | `. . . clone(4)` | no | create `4'`, register, visit `[1, 3]` | 1, 2, 3, 4 | - |
| 7 | `. . . . clone(1)` | **yes** | return existing `1'` | 1, 2, 3, 4 | `4' -> 1'` |
| 8 | `. . . . clone(3)` | **yes** | return existing `3'` | 1, 2, 3, 4 | `4' -> 3'` |
| - | `clone(4)` returns `4'` | | | | `3' -> 4'` |
| - | `clone(3)` returns `3'` | | | | `2' -> 3'` |
| - | `clone(2)` returns `2'` | | | | `1' -> 2'` |
| 9 | `. clone(4)` | **yes** | return existing `4'` | 1, 2, 3, 4 | `1' -> 4'` |
| - | `clone(1)` returns `1'` | | | | |

Nine calls: one to start, plus one for each of the eight adjacency entries. Four clones created, eight edges wired, and every "in map? yes" row is a cycle being closed instead of followed.

Look at steps 3 and 7: `1'` was handed out twice while it still had **no neighbours** - it only gained `2'` at the end of step 2's return and `4'` at step 9. That is safe because Java references point at the object, not at a snapshot of it. Everyone who holds `1'` sees its neighbour list once it is filled in.

=== complexity ===
### Time

Each node is created once. Each adjacency entry triggers exactly one call, which is `O(1)` apart from its recursion. With `V` nodes and `E` edges, there are `2E` adjacency entries.

```text
O(V + E)
```

### Space

The map holds `V` entries. The recursion stack can reach depth `V` on a long path; the BFS version's queue is also bounded by `V`. The cloned graph itself is the output, not extra space.

```text
O(V)
```

### Comparison

| Approach | Time | Extra space | Passes over edges |
| :------- | ---: | ----------: | ----------------: |
| Naive recursion, no memory | never terminates | - | - |
| Three phases with lists | `O(V * E)` | `O(V)` | 2 |
| DFS + HashMap | **`O(V + E)`** | **`O(V)`** | 1 |
| BFS + HashMap | **`O(V + E)`** | **`O(V)`** | 1 |

=== implementation ===
```java
class Solution {
    public Node cloneGraph(Node node) {
        return clone(node, new HashMap<>());
    }

    private Node clone(Node node, Map<Node, Node> cloneOf) {
        if (node == null) {
            return null;
        }
        if (cloneOf.containsKey(node)) {
            return cloneOf.get(node);          // seen before: reuse the same clone
        }
        Node copy = new Node(node.val);
        cloneOf.put(node, copy);               // register BEFORE visiting neighbours
        for (Node next : node.neighbors) {
            copy.neighbors.add(clone(next, cloneOf));
        }
        return copy;
    }
}
```

### The lines that matter

**1.**

```java
cloneOf.put(node, copy);               // register BEFORE visiting neighbours
```

The whole correctness argument is the position of this line. Move it below the loop and the first cycle recurses forever - the neighbour calls back into this node, finds no entry, and starts cloning it again.

**2.**

```java
if (cloneOf.containsKey(node)) {
    return cloneOf.get(node);          // seen before: reuse the same clone
}
```

This is both the visited check and the identity guarantee. A node reached through a second edge gets the **same** clone object as the first time.

**3.**

```java
return clone(node, new HashMap<>());
```

A fresh map per call to `cloneGraph`. Storing the map in a field also works on a single call, but it leaks state: call `cloneGraph` twice on the same `Solution` and the second call returns clones from the first.

### BFS, for very deep graphs

```java
class Solution {
    public Node cloneGraph(Node node) {
        if (node == null) {
            return null;
        }
        Map<Node, Node> cloneOf = new HashMap<>();
        cloneOf.put(node, new Node(node.val));
        Deque<Node> queue = new ArrayDeque<>();
        queue.offer(node);
        while (!queue.isEmpty()) {
            Node cur = queue.poll();
            for (Node next : cur.neighbors) {
                if (!cloneOf.containsKey(next)) {
                    cloneOf.put(next, new Node(next.val));   // clone on discovery
                    queue.offer(next);
                }
                cloneOf.get(cur).neighbors.add(cloneOf.get(next));
            }
        }
        return cloneOf.get(node);
    }
}
```

Same map, same rule - a clone is created and registered the moment its original is discovered, before it is processed. The edge is wired whether or not the neighbour was new.

### Java notes

- LeetCode provides `Node` with `val`, `neighbors`, and constructors `Node()`, `Node(int)` and `Node(int, ArrayList<Node>)`. `new Node(val)` already initialises `neighbors` to an empty `ArrayList`, so there is no need to create one.
- `Node` does not override `equals` or `hashCode`, so `HashMap<Node, Node>` keys by **object identity**. That is exactly what we want: two different nodes that happen to share a value are still different nodes.
- Keying the map by `node.val` (or using an array indexed by value) works on LeetCode because values are unique `1..n`, but it is relying on the test format. Keying by the node object works for any graph.
- Recursion depth is at most `V = 100` here, so the DFS is safe. The BFS version exists for graphs where that is not true.

=== edgeCases ===
### Empty graph

```text
adjList = []   (input node is null)  ->  null
```

The first check returns `null` immediately.

### A single node with no neighbours

```text
adjList = [[]]  ->  [[]]
```

One clone is created and registered; the neighbour loop runs zero times.

### Two nodes

```text
adjList = [[2],[1]]  ->  [[2],[1]]
```

The smallest cycle: `1 -> 2 -> 1`. The second visit to `1` is answered from the map, which is the first time the "register before recursing" rule actually matters.

### A path (no cycle beyond the back-edges)

```text
adjList = [[2],[1,3],[2]]  ->  [[2],[1,3],[2]]
```

### A triangle (every node connected to every other)

```text
adjList = [[2,3],[1,3],[1,2]]  ->  [[2,3],[1,3],[1,2]]
```

Every node is reached through two different edges, so every clone is handed out more than once - the identity check is exercised on every node.

### Deep-copy check

For any input, no node reachable from the returned clone is an original node, and the clones have the same values and the same neighbour order as the originals. Returning `node` itself, or reusing any original node inside the copy, is wrong even though the values would all match.

### A self-loop

```text
node 1 lists itself:  1.neighbors = [1]  ->  1'.neighbors = [1']
```

LeetCode rules this out, but the solution handles it for free: `1'` is registered before the loop, so the self-edge resolves to `1'` itself.

=== takeaway ===
> When you see **"deep copy" of anything with shared references or cycles**, think **traverse + `HashMap<original, copy>`**, and register the copy **before** you visit its neighbours.

### The core observation

The map is the visited set and the identity table at the same time. Creating and registering a clone the moment its original is discovered means every later edge to that node - including the one that closes a cycle - finds the same clone in `O(1)`. One traversal, `O(V + E)`.

### The pattern trigger

```text
                  visit(node)
                       |
                       v
             node already in map?
               /              \
             yes               no
              |                 |
     return map.get(node)   copy = new Node(node.val)
                            map.put(node, copy)      <-- BEFORE neighbours
                                    |
                                    v
                     for each neighbour:
                         copy.neighbors.add( visit(neighbour) )
                                    |
                                    v
                               return copy
```

### The common mistakes

**Registering after the neighbour loop.** Infinite recursion on the first cycle - and an undirected graph always has one.

**A boolean visited set instead of a map.** It stops the infinite loop, but when you meet a visited node you no longer know which clone to link to.

**Keying by value.** Works on LeetCode, breaks on any graph with duplicate values.

**Returning the original, or mixing originals into the copy.** The values all match, so it looks right in a printout; it is not a deep copy.

### What to remember in six months

> Copying a graph is a traversal whose visited set remembers what it built. Register before you recurse.

Deep-copy a connected undirected graph. Two things make it harder than it sounds:
- Undirected means every edge is stored twice, so the graph always has cycles. A naive recursive copy never terminates.
