=== intro ===
Day 18's window had a fixed size `k`: every step, one element in and one element out. Today nobody tells you the size. The window **grows** while it is valid and **shrinks** the moment it is not - and its size at its best moment is the answer.

> A variable window is a contract: everything between `left` and `right` satisfies the rule. `right` breaks the contract by reaching forward; `left` restores it by letting go.

=== problem ===
Given a string `s`, return the **length** of the longest substring that contains no repeated character.

```text
s = "abcabcbb"   ->  3     ("abc")
s = "bbbbb"      ->  1     ("b")
s = "pwwkew"     ->  3     ("wke")
```

We will use `"pwwkew"` as the worked example throughout, because it contains both kinds of trouble: a repeat right next to itself (`ww`) and a repeat far apart (`w ... w`).

### Substring, not subsequence

A **substring** is contiguous. `"pwke"` has four distinct characters, but in `"pwwkew"` those letters are not adjacent - you would have to skip the second `w`. Skipping is not allowed. That is why the answer is `3`, not `4`.

```text
p w w k e w
    [w k e]       substring, distinct, length 3   <- valid
p w   k e         skips index 2 - a subsequence   <- not allowed
```

### What we return

Only the **length**. We never need to build or return the substring itself, which matters for the implementation: no `substring()` calls, no string building, just indices.

### Constraints that matter

- `0 <= s.length <= 5 * 10^4` - the empty string is legal, answer `0`.
- `s` contains English letters, digits, symbols **and spaces**. All of them are ASCII, so a 128-slot array can stand in for a hash map. A space is a character like any other.

=== pattern ===
**Variable-size Sliding Window + Hashing.**

The window `[left, right]` is the current candidate substring. It obeys one rule - **no character appears twice inside it** - and two pointers maintain that rule:

- `right` walks forward one character at a time, always. Each new character is offered to the window.
- `left` moves forward only when the new character would break the rule, and only far enough to fix it.

```text
p w w k e w
[   ]                 window "pw" - valid
[     ]               add w: "pww" - INVALID, w twice
    [ ]               move left past the first w: "w" - valid again
```

The hashing half answers the question the window keeps asking - "is this character already inside?" - in `O(1)`, instead of rescanning the window.

### Why it is a sliding window and not two nested loops

The rule is **monotonic under shrinking**: if a window has no repeats, every smaller window inside it has no repeats either. And it is **monotonic under growing** the other way: once a window contains a repeat, every larger window containing it does too. That two-way monotonicity is what lets both pointers move forward only - neither ever has to step back.

### Recognising it

Reach for a variable window when the problem says:

- "longest / shortest **substring** or **subarray** such that ..."
- the condition is about **what is inside** the range (distinct characters, counts, sum with non-negative values)
- adding an element can only make the condition **harder** to satisfy, removing one can only make it **easier**

The mental question:

> If this window is invalid, will a longer window that contains it ever be valid? If not, I should move `left`, not keep growing.

=== bruteForce ===
Without the window idea, the natural plan is: pick each starting index, extend to the right one character at a time, and stop at the first repeat.

1. For each start `i`, make an empty set `seen`.
2. For `j = i, i+1, ...`: if `s[j]` is already in `seen`, this start is finished - break.
3. Otherwise add `s[j]` and record the length `j - i + 1`.

(The even more naive version checks every one of the `n^2 / 2` substrings for uniqueness from scratch, costing `O(n^3)`. Stopping at the first repeat is the obvious first improvement, so we start there.)

### Java

```java
class Solution {
    public int lengthOfLongestSubstring(String s) {

        int n = s.length();
        int best = 0;

        for (int i = 0; i < n; i++) {

            Set<Character> seen = new HashSet<>();

            for (int j = i; j < n; j++) {
                char c = s.charAt(j);
                if (seen.contains(c)) {
                    break;              // this start can grow no further
                }
                seen.add(c);
                best = Math.max(best, j - i + 1);
            }
        }

        return best;
    }
}
```

### Complexity

**Time:** `O(n * min(n, sigma))` - at most `sigma` distinct characters fit before a repeat, so each start scans at most `sigma + 1` positions. With `sigma = 128` that bound helps, but on a string with many distinct characters it is still quadratic in practice - **Space:** `O(min(n, sigma))` for the set.

### Where it hurts

Look at rows `i = 2` and `i = 3`:

```text
i = 2:  w k e | w   <- repeat found at j = 5
i = 3:    k e   w   <- rescans k and e from scratch
```

At `i = 2` we already learned that `k` and `e` are distinct. Then `i = 3` throws the set away and re-adds them. Worse, look at rows `i = 0` and `i = 1`: both broke on the **same** repeat - the second `w` at index 2. Starting at `i = 1` was hopeless before we tried it: the window from 1 still contains index 1's `w`, so it was always going to collide at index 2.

Two kinds of waste:

1. **Hopeless starts.** When `s[j]` collides with a copy at position `p`, every start from `i` to `p` contains both copies. None of them can get past `j`. The next start worth trying is `p + 1`.
2. **Rescanning.** The characters between `p + 1` and `j - 1` are already known to be distinct. There is no need to re-check them.

> When a repeat appears, don't restart. Drop just enough from the left to remove the old copy, and keep going from where you are.

=== optimization ===
### The key observation

When `right` reaches a character that is already in the window at position `p`, the only fix is to move `left` to `p + 1`. Anything less still contains both copies; anything more throws away valid characters for no reason. And `right` never needs to go back, because everything in `[p + 1, right - 1]` was already checked.

So both pointers only move forward. Each index enters the window once and leaves at most once.

### Version 1 - shrink with a set

Keep a set of the characters currently in the window. Before adding `s[right]`, remove `s[left]` and advance `left` until `s[right]` is no longer in the set.

| right | s[right] | in set? | shrink steps | left | set after | window | length | best |
| ----: | :------- | :------ | :----------- | ---: | :-------- | :----- | -----: | ---: |
| 0 | p | no | - | 0 | {p} | `p` | 1 | 1 |
| 1 | w | no | - | 0 | {p, w} | `pw` | 2 | 2 |
| 2 | w | yes | remove p (left 0 -> 1), remove w (left 1 -> 2) | 2 | {w} | `w` | 1 | 2 |
| 3 | k | no | - | 2 | {w, k} | `wk` | 2 | 2 |
| 4 | e | no | - | 2 | {w, k, e} | `wke` | 3 | 3 |
| 5 | w | yes | remove w (left 2 -> 3) | 3 | {k, e, w} | `kew` | 3 | 3 |

```text
best = 3
```

Every character was added once and removed at most once: 6 adds, 3 removes. Linear.

### Version 2 - jump with last-seen indices

The shrink loop walks `left` forward one step at a time until it passes the old copy. But we could know **exactly** where the old copy is if we remembered the last index of every character. Then `left` can **jump** there in one step:

```text
left = max(left, last[c] + 1)
```

The `max` matters, and the dry run after this one shows why. `last[]` starts at `-1` for every character, so for a never-seen character `last[c] + 1 = 0`, which is never larger than `left` - no special case needed.

### Dry run on the same example

```text
s = "pwwkew",  left = 0,  best = 0,  last[*] = -1
```

| right | c | last[c] before | `last[c] + 1` | left after `max` | last[c] after | length `right - left + 1` | best |
| ----: | :- | -------------: | ------------: | ---------------: | ------------: | ------------------------: | ---: |
| 0 | p | -1 | 0 | 0 | 0 | 1 | 1 |
| 1 | w | -1 | 0 | 0 | 1 | 2 | 2 |
| 2 | w | 1 | 2 | **2** | 2 | 1 | 2 |
| 3 | k | -1 | 0 | 2 | 3 | 2 | 2 |
| 4 | e | -1 | 0 | 2 | 4 | 3 | 3 |
| 5 | w | 2 | 3 | **3** | 5 | 3 | 3 |

```text
best = 3
```

The two bold cells are the jumps. At `right = 2`, `left` skips straight over the hopeless start at index 1 - exactly the waste the brute force paid for.

### Why `max(left, ...)` and not just `last[c] + 1`

`last[]` remembers characters that may have **already left** the window. Jumping back to them would re-admit characters we threw out. The smallest example:

```text
s = "abba"
```

| right | c | last[c] before | `last[c] + 1` | left WITH max | left WITHOUT max | length with max | length without |
| ----: | :- | -------------: | ------------: | ------------: | ---------------: | --------------: | -------------: |
| 0 | a | -1 | 0 | 0 | 0 | 1 | 1 |
| 1 | b | -1 | 0 | 0 | 0 | 2 | 2 |
| 2 | b | 1 | 2 | 2 | 2 | 1 | 1 |
| 3 | a | 0 | 1 | **2** | **1** | 2 | **3** |

At `right = 3`, the old `a` at index 0 is **outside** the window `[2, 3]` already. Without the `max`, `left` moves **backwards** to 1, the window becomes `"bba"` - which contains `b` twice - and the answer comes out `3`. The correct answer is `2`. `left` must never move left.

=== complexity ===
### Time

`right` visits each index once. In version 1 `left` also visits each index at most once over the whole run, so total pointer moves are at most `2n`. In version 2 `left` jumps in `O(1)`, so it is a single pass.

```text
O(n)
```

### Space

Version 2 uses a fixed `int[128]` - one slot per ASCII character - regardless of `n`. Version 1's set holds at most `min(n, sigma)` characters.

```text
O(sigma) = O(128) = O(1) for a fixed alphabet
```

### Comparison

| Approach | Time | Space | Pointer behaviour |
| :------- | ---: | ----: | :---------------- |
| Every substring, check from scratch | `O(n^3)` | `O(sigma)` | restart everything |
| Every start, stop at first repeat | `O(n * min(n, sigma))` | `O(sigma)` | `j` restarts at every `i` |
| Window + set, shrink one step at a time | `O(n)` (`<= 2n` steps) | `O(sigma)` | both forward only |
| Window + last index, jump | **`O(n)`** (one pass) | **`O(sigma)`** | both forward only, `left` jumps |

Version 1 is the one to reach for first in an interview - it is the general variable-window template and easy to argue. Version 2 is the refinement to offer once that is on the board.

=== implementation ===
```java
class Solution {
    public int lengthOfLongestSubstring(String s) {

        // last[c] = most recent index where character c was seen, -1 if never.
        int[] last = new int[128];
        Arrays.fill(last, -1);

        int left = 0;
        int best = 0;

        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);

            // If c's previous copy is inside the window, jump just past it.
            // max(): never move left backwards to a copy that already left.
            left = Math.max(left, last[c] + 1);

            last[c] = right;
            best = Math.max(best, right - left + 1);
        }

        return best;
    }
}
```

### The lines that matter

**1.**

```java
left = Math.max(left, last[c] + 1);
```

The whole algorithm. If `c`'s last copy is inside the window, `last[c] + 1` is the first index past it. If it is outside (or never seen, `-1 + 1 = 0`), `left` is already larger and stays put.

**2.**

```java
last[c] = right;
```

Updated **after** computing `left`. Update first and `last[c] + 1` becomes `right + 1`, collapsing every window to length 0.

**3.**

```java
best = Math.max(best, right - left + 1);
```

Inclusive window `[left, right]`, so the length has the `+ 1`. Recorded every step, because the window is valid after every step.

### The set version, as the general template

This is the shape every variable window in the next days follows - grow on the right, shrink on the left **while** invalid, then record:

```java
class Solution {
    public int lengthOfLongestSubstring(String s) {

        Set<Character> window = new HashSet<>();
        int left = 0;
        int best = 0;

        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);

            while (window.contains(c)) {        // invalid: shrink
                window.remove(s.charAt(left));
                left++;
            }

            window.add(c);                      // grow
            best = Math.max(best, right - left + 1);
        }

        return best;
    }
}
```

### Java notes

- `int[128]` indexed by a `char` works directly: `last[c]` widens the `char` to its code point. For full Unicode input you would use a `HashMap<Character, Integer>` instead.
- `Arrays.fill(last, -1)` is needed because Java zero-fills; leaving `0` would make every unseen character look like it was last seen at index 0. The alternative trick is to store `index + 1` and keep the zero-fill.
- `HashSet<Character>` autoboxes every `char`. Fine for clarity; the array version avoids it.

=== edgeCases ===
### Empty string

```text
""  ->  0
```

The loop never runs and `best` stays `0`.

### Single space

```text
" "  ->  1
```

A space is a character. `last[' ']` is slot 32 of the array; nothing special happens.

### All the same character

```text
"bbbbb"  ->  1
```

Every step `left` jumps to `right`, so the window is always length 1.

### All distinct

```text
"abcdef"  ->  6
```

`left` never moves. The whole string is the answer.

### The left-moves-backwards trap

```text
"abba"  ->  2
```

Without `Math.max`, the final `a` sends `left` back to 1 and the answer becomes `3`. See the table in the optimisation section.

### Another backwards trap, at distance

```text
"tmmzuxt"  ->  5
```

At the final `t`, `last['t'] = 0` but `left` is already `2` (moved there by the second `m`). With the `max`, `left` stays at `2` and the window `"mzuxt"` has length 5. Without it, `left` would drop to `1` and report `"mmzuxt"`, length 6 - which contains `m` twice.

### Repeat that is not adjacent

```text
"dvdf"  ->  3
```

At the second `d` (index 2), `left` jumps to 1, giving `"vd"`, then `"vdf"`. A tempting wrong approach - "restart from the repeat's position" - would restart at index 2 and find only `"df"`.

### Subsequence vs substring

```text
"pwwkew"  ->  3
```

Not `4`. `"pwke"` is not contiguous.

### Digits and symbols

```text
"a1!a"  ->  3
```

`"a1!"` (or `"1!a"`). All ASCII, all handled by the same array.

=== takeaway ===
> When you see **"longest substring such that ..."** with a condition about **what is inside**, think **variable sliding window**: grow `right` every step, shrink `left` only until the condition holds again.

### The core observation

When the new character collides with a copy at position `p`, every start up to `p` is hopeless - they all contain both copies. So the next useful start is `p + 1`, and everything already scanned between `p + 1` and `right` is still valid. Neither pointer ever needs to go back, which turns a nested loop into one pass.

### The pattern trigger

```text
             "longest / shortest contiguous ... such that ..."
                               |
                               v
         adding an element can only BREAK the rule,
         removing one can only FIX it?
                               |
                              yes
                               v
     for right in 0..n-1:
         add s[right]
         while window breaks the rule:  remove s[left], left++
         record right - left + 1
                               |
                               v
     need "is X inside?" fast -> set / count array / last-index array
```

### The common mistakes

**Letting `left` move backwards.** Setting `left = last[c] + 1` whenever `c` was seen before, without the `max`, passes `"abcabcbb"` and fails `"abba"`. `left` is monotonic; enforce it.

**Updating `last[c]` before using it.** The jump must read the **previous** position of `c`.

**Restarting instead of sliding.** On a repeat, resetting the window to empty and starting at `right` loses the valid suffix (`"dvdf"` returns 2 instead of 3).

**Confusing substring with subsequence.** If you find yourself skipping characters, you have changed the problem.

### What to remember in six months

> Variable window = grow right always, shrink left while broken, record when valid. The data structure inside just answers "is the window still valid?" in `O(1)`.

The same loop solves at most K distinct characters (LC 340), Fruit Into Baskets (LC 904), Max Consecutive Ones III (LC 1004), and - with a frequency array instead of a set - tomorrow's Longest Repeating Character Replacement.
