=== intro ===
Yesterday, BFS levels were minutes: ring 0 rotten, ring 1 a minute later, ring 2 after that. Today the same rings get a different meaning - not "when", but "which side".

And it ties back to Day 69. There, a cycle was the thing to detect. Today only one kind of cycle matters: an odd one.

> When a choice you make at one vertex forces the choice at its neighbours, you are not searching a space of options - you are propagating a single decision. Make it once, push it outward, and check for a contradiction.

=== problem ===
You get an undirected graph with `n` nodes `0` to `n - 1` as an adjacency list: `graph[u]` is the array of `u`'s neighbours. Return `true` if the graph is **bipartite** - if its nodes can be split into two groups `A` and `B` so that **every edge has one end in `A` and the other in `B`**.

```java
public boolean isBipartite(int[][] graph)
```

Another way to say it: can you colour every node with one of two colours so that no edge joins two nodes of the same colour?

### The example used all day

```text
graph = [[1, 2, 3], [0, 2], [0, 1, 3], [0, 2]]

edges: 0-1, 0-2, 0-3, 1-2, 2-3

      1 --- 0 --- 3
       \    |    /
        \   |   /
            2
```

| node | neighbours |
| ---: | :--------- |
| 0 | 1, 2, 3 |
| 1 | 0, 2 |
| 2 | 0, 1, 3 |
| 3 | 0, 2 |

Answer: `false`. Nodes `0`, `1`, `2` form a triangle. Put `0` on side `A`; then `1` must be on `B` and `2` must be on `B` - but `1-2` is an edge, and both ends are on `B`.

### The contrasting example

```text
graph = [[1, 3], [0, 2], [1, 3], [0, 2]]

edges: 0-1, 1-2, 2-3, 3-0      (a square)
```

Answer: `true`, with `A = {0, 2}` and `B = {1, 3}`. Every edge crosses.

### What the constraints promise

- `1 <= n <= 100`.
- No self-edges (`u` is never in `graph[u]`), no repeated neighbours, and the lists are symmetric: `v` in `graph[u]` exactly when `u` in `graph[v]`.
- The graph **may be disconnected**. Every piece must be two-colourable on its own.

### The fact under everything

A graph is bipartite exactly when it has **no cycle of odd length**. Walking around any cycle alternates sides `A, B, A, B, ...`; to return to the start you need an even number of steps. A triangle (3 steps) or pentagon (5 steps) cannot close up. The square (4 steps) can.

=== pattern ===
**BFS (or DFS) two-colouring** - a traversal that assigns a colour as it discovers each node.

The reframe: the colours are not really choices. In one connected piece, once you pick the colour of a single node, every other node's colour is **forced**:

- its neighbours must take the opposite colour
- their neighbours must take the original colour
- and so on outward

So a node's colour is just the **parity of its distance** from the start - even ring colour `0`, odd ring colour `1`. BFS produces exactly those rings. The only thing left to check is whether the forced colouring contradicts itself: an edge whose two ends were forced to the same colour.

```text
  start (colour 0)
     |
  ring 1  -> colour 1
     |
  ring 2  -> colour 0
     |
  any edge between two nodes of the SAME colour  ->  not bipartite
```

### Why a contradiction means an odd cycle

If `u` and `v` have the same colour and share an edge, their BFS paths back to the start have the same parity of length. Join the two paths through the edge `u-v` and you get a closed walk of odd length - which always contains an odd cycle. So the contradiction is not an artefact of the order we coloured in: no colouring could have worked.

### Recognising it

Reach for two-colouring when:

- the problem asks to split items into **two groups** with "these pairs must be in different groups" (Possible Bipartition, dislike lists, team splits)
- you see "two colours", "two sides", "alternating", or "no edge inside a group"
- the question is whether a graph has an odd cycle

The mental question:

> If I fix one item's group, are all the others in its piece forced? Then propagate the forced choice and look for a clash.

=== bruteForce ===
Without the forcing insight, the direct approach is to try every possible split. Each node is on side `0` or side `1`, so a split is an `n`-bit number: bit `i` is node `i`'s side. For every one of the `2^n` splits, check every edge; if some split has no edge inside a side, the graph is bipartite.

### Step logic

1. For `mask` from `0` to `2^n - 1`: node `i` has colour `(mask >> i) & 1`.
2. Walk the edges (`u < v` so each is checked once). The first edge with equal colours rejects this mask.
3. If a mask passes every edge, return `true`.
4. If no mask passes, return `false`.

### Dry run on the example

Edges in check order: `0-1`, `0-2`, `0-3`, `1-2`, `2-3`. Colours are written `c0 c1 c2 c3`.

| mask | c0 c1 c2 c3 | 0-1 | 0-2 | 0-3 | 1-2 | 2-3 | result |
| ---: | :---------- | :-- | :-- | :-- | :-- | :-- | :----- |
| 0 | 0 0 0 0 | same | | | | | reject at 0-1 |
| 1 | 1 0 0 0 | ok | ok | ok | same | | reject at 1-2 |
| 2 | 0 1 0 0 | ok | same | | | | reject at 0-2 |
| 3 | 1 1 0 0 | same | | | | | reject at 0-1 |
| 4 | 0 0 1 0 | same | | | | | reject at 0-1 |
| 5 | 1 0 1 0 | ok | same | | | | reject at 0-2 |
| 6 | 0 1 1 0 | ok | ok | same | | | reject at 0-3 |
| 7 | 1 1 1 0 | same | | | | | reject at 0-1 |
| 8 | 0 0 0 1 | same | | | | | reject at 0-1 |
| 9 | 1 0 0 1 | ok | ok | same | | | reject at 0-3 |
| 10 | 0 1 0 1 | ok | same | | | | reject at 0-2 |
| 11 | 1 1 0 1 | same | | | | | reject at 0-1 |

### Java

```java
class Solution {
    public boolean isBipartite(int[][] graph) {

        int n = graph.length;

        // Try every split of the n nodes into two sides. Only feasible for small n:
        // 2^n masks, and 1L << n overflows long once n reaches 63.
        for (long mask = 0; mask < (1L << n); mask++) {
            if (valid(graph, mask)) return true;
        }
        return false;
    }

    private boolean valid(int[][] graph, long mask) {
        for (int u = 0; u < graph.length; u++) {
            for (int v : graph[u]) {
                long cu = (mask >> u) & 1, cv = (mask >> v) & 1;
                if (u < v && cu == cv) return false;    // both ends on the same side
            }
        }
        return true;
    }
}
```

### Complexity

**Time:** `O(2^n * (n + E))` - **Space:** `O(1)` extra

For `n = 100` that is `2^100` masks - not slow, impossible.

### Where it hurts

Read the table's columns instead of its rows. Rows `0`, `3`, `4`, `7`, `8`, `11`, `12` and `15` all die on edge `0-1` for the same reason: `c0` and `c1` are equal. Eight of the sixteen masks were doomed by one fact, and each was built and tested separately.

The deeper waste: once `c0` is fixed, the edge `0-1` forces `c1`, edge `0-2` forces `c2`, edge `0-3` forces `c3`. In a connected graph there are only **two** colourings worth considering - pick `c0 = 0` or `c0 = 1`, and everything else follows. And those two are mirror images of each other: one works exactly when the other does. So there is really **one** colouring to try.

> Don't enumerate colourings. Fix one node, let the edges force the rest, and check whether the forcing ever contradicts itself.

=== optimization ===
### The plan

1. `color[]` all `-1` (uncoloured).
2. For each node `start` still uncoloured: give it colour `0`, put it in a queue.
3. Pop `node`. For each neighbour `next`:
   - uncoloured: give it `1 - color[node]`, push it
   - same colour as `node`: return `false`
   - opposite colour: fine, move on
4. If every piece finishes without a clash, return `true`.

### Dry run on the same example

| step | popped | neighbour | its colour before | action | `color` after (0..3) | queue after |
| ---: | :----- | --------: | :---------------- | :----- | :------------------- | :---------- |
| 0 | - | - | - | start at 0, colour 0 | `[0, -1, -1, -1]` | `[0]` |
| 1 | 0 | 1 | -1 | colour `1 - 0 = 1`, push | `[0, 1, -1, -1]` | `[1]` |
| 2 | 0 | 2 | -1 | colour 1, push | `[0, 1, 1, -1]` | `[1, 2]` |
| 3 | 0 | 3 | -1 | colour 1, push | `[0, 1, 1, 1]` | `[1, 2, 3]` |
| 4 | 1 | 0 | 0 | opposite of 1 - fine | `[0, 1, 1, 1]` | `[2, 3]` |
| 5 | 1 | 2 | 1 | **same as node 1 - return `false`** | - | - |

Five neighbour checks instead of sixteen masks. The clash is on edge `1-2`, and it is exactly the triangle: `1` and `2` are both at distance 1 from `0`, so both were forced to colour `1`, and they are joined by an edge. Distance 1 + 1 + the edge = a cycle of length 3.

### Dry run on the square

`graph = [[1, 3], [0, 2], [1, 3], [0, 2]]`

| step | popped | neighbour | its colour before | action | `color` after (0..3) | queue after |
| ---: | :----- | --------: | :---------------- | :----- | :------------------- | :---------- |
| 0 | - | - | - | start at 0, colour 0 | `[0, -1, -1, -1]` | `[0]` |
| 1 | 0 | 1 | -1 | colour 1, push | `[0, 1, -1, -1]` | `[1]` |
| 2 | 0 | 3 | -1 | colour 1, push | `[0, 1, -1, 1]` | `[1, 3]` |
| 3 | 1 | 0 | 0 | opposite - fine | `[0, 1, -1, 1]` | `[3]` |
| 4 | 1 | 2 | -1 | colour 0, push | `[0, 1, 0, 1]` | `[3, 2]` |
| 5 | 3 | 0 | 0 | opposite - fine | `[0, 1, 0, 1]` | `[2]` |
| 6 | 3 | 2 | 0 | opposite - fine | `[0, 1, 0, 1]` | `[2]` |
| 7 | 2 | 1 | 1 | opposite - fine | `[0, 1, 0, 1]` | `[]` |
| 8 | 2 | 3 | 1 | opposite - fine | `[0, 1, 0, 1]` | `[]` |

Queue empty, no other uncoloured node, return `true`. The final `color` array is the split itself: `A = {0, 2}`, `B = {1, 3}`.

Step 6 is the interesting one. Node `2` was coloured `0` through `1`, and the edge `3-2` arrives from the other direction - and agrees. That agreement is what an **even** cycle looks like from inside the BFS.

### Why one start colour is enough

Choosing `0` for the start is not a guess that might need undoing. If the forced colouring from `color[start] = 0` clashes, the one from `color[start] = 1` is its exact mirror and clashes on the same edge. No backtracking, ever.

=== complexity ===
### Time

Every node is coloured and pushed once. Every adjacency entry is examined once when its owner is popped - each undirected edge twice in total.

```text
O(n + E)
```

### Space

`color[]` and the queue are both at most `n`.

```text
O(n)
```

### Comparison

| Approach | Time | Space | Notes |
| :------- | ---: | ----: | :---- |
| Try every split | `O(2^n * (n + E))` | `O(1)` | hopeless past about `n = 25` |
| BFS two-colouring | **`O(n + E)`** | **`O(n)`** | no recursion |
| DFS two-colouring | **`O(n + E)`** | **`O(n)`** | recursion depth up to `n` |

=== implementation ===
```java
class Solution {
    public boolean isBipartite(int[][] graph) {

        int n = graph.length;
        int[] color = new int[n];
        Arrays.fill(color, -1);                     // -1 = not coloured yet

        // The graph may be disconnected: colour every piece separately.
        for (int start = 0; start < n; start++) {
            if (color[start] != -1) continue;

            color[start] = 0;
            Deque<Integer> queue = new ArrayDeque<>();
            queue.offer(start);

            while (!queue.isEmpty()) {
                int node = queue.poll();
                for (int next : graph[node]) {
                    if (color[next] == -1) {
                        color[next] = 1 - color[node];  // forced: the opposite side
                        queue.offer(next);
                    } else if (color[next] == color[node]) {
                        return false;                   // an edge inside one side
                    }
                }
            }
        }
        return true;
    }
}
```

### The lines that matter

**1.**

```java
color[next] = 1 - color[node];  // forced: the opposite side
```

The forcing rule. `1 - c` flips `0` to `1` and `1` to `0`. Colour is assigned when a node is **pushed**, so a node already in the queue is never re-coloured by a second neighbour.

**2.**

```java
} else if (color[next] == color[node]) {
    return false;                   // an edge inside one side
```

The only way to fail. A coloured neighbour with the opposite colour needs no action - it is either the node we came from or an even cycle closing correctly.

**3.**

```java
for (int start = 0; start < n; start++) {
    if (color[start] != -1) continue;
```

Disconnected pieces are coloured independently. Without this loop, a triangle in a second component is never seen.

### The DFS version

The same forcing, pushed down a recursion instead of a queue. Here colours are `1` and `-1`, so flipping is just negation and `0` can mean "uncoloured":

```java
class Solution {
    public boolean isBipartite(int[][] graph) {

        int[] color = new int[graph.length];       // 0 = uncoloured, 1 / -1 = the two sides
        for (int start = 0; start < graph.length; start++) {
            if (color[start] == 0 && !paint(graph, start, 1, color)) return false;
        }
        return true;
    }

    private boolean paint(int[][] graph, int node, int c, int[] color) {
        color[node] = c;
        for (int next : graph[node]) {
            if (color[next] == c) return false;
            if (color[next] == 0 && !paint(graph, next, -c, color)) return false;
        }
        return true;
    }
}
```

### Java notes

- `Arrays.fill(color, -1)` is needed because `new int[n]` starts at `0`, which is a real colour in the BFS version. The DFS version avoids the fill by using `1` / `-1` as colours.
- `graph[node]` is a plain `int[]` here, not a `List<Integer>` - LC 785 hands you `int[][]`, so iteration is over primitives with no unboxing.
- With `n <= 100` recursion depth is never a problem for the DFS version, but on large graphs the BFS version is the safe default.

=== edgeCases ===
### A single node

```text
[[]]  ->  true
```

No edges, nothing to violate.

### Isolated nodes only

```text
[[], [], []]  ->  true
```

Each node starts its own piece and gets colour `0`. No edge, no clash.

### One edge

```text
[[1], [0]]  ->  true
```

### An even cycle - the square

```text
[[1, 3], [0, 2], [1, 3], [0, 2]]  ->  true
```

### An odd cycle - the pentagon

```text
[[1, 4], [0, 2], [1, 3], [2, 4], [3, 0]]  ->  false
```

Length does not save it: `2` and `3` are both at distance 2 from `0`, both coloured `0`, and joined by an edge.

### A tree

```text
[[1, 2], [0, 3], [0], [1]]  ->  true
```

A tree has no cycles at all, so certainly no odd ones. Every tree is bipartite.

### The odd cycle is in another piece

```text
[[1], [0], [3, 4], [2, 4], [2, 3]]  ->  false
```

Nodes `0-1` are a lone edge; `2-3-4` is a triangle. BFS from `0` alone says `true`. The outer loop is what reaches the triangle.

### Complete bipartite

```text
[[2, 3], [2, 3], [0, 1], [0, 1]]  ->  true
```

Every node of `{0, 1}` joined to every node of `{2, 3}` - dense, but still bipartite, because no edge stays inside a side.

=== takeaway ===
> When you see **"split into two groups so that every pair/edge crosses"**, think **two-colouring by BFS**: fix one node's colour, force the opposite onto its neighbours, and fail on the first edge whose ends got the same colour.

### The core observation

Colours in a connected piece are not choices - one decision forces all the rest, because every edge says "opposite". So instead of trying `2^n` splits, propagate the single forced split and watch for a contradiction. A contradiction is an odd cycle, and an odd cycle makes every split fail, so finding one is proof.

### The pattern trigger

```text
       "two groups, every edge must cross"
                      |
                      v
       for each uncoloured start: colour 0, BFS
                      |
                      v
       neighbour uncoloured  -> opposite colour, push
       neighbour same colour -> false (odd cycle)
       neighbour opposite    -> fine
                      |
                      v
       all pieces done -> true
```

### The common mistakes

**Colouring only from node 0.** Misses every other component.

**Colouring at pop time.** A node can be pushed by two neighbours before it is popped, and the second push can overwrite a colour already relied on.

**Treating any cycle as fatal.** Day 69's lesson does not carry over: even cycles are fine. Only odd ones break bipartiteness.

**Backtracking on a clash.** There is nothing to try instead - the mirror colouring clashes on the same edge.

### What to remember in six months

> Bipartite = two-colourable = no odd cycle. BFS ring parity is the colour; an edge inside a ring parity is the odd cycle.

Possible Bipartition (LC 886) is this problem after building the graph from a dislike list. The same parity idea underlies matching problems (bipartite matching, assigning workers to jobs) and the BFS-layer reasoning shows up again on Day 74, where those rings become shortest-path distances.
