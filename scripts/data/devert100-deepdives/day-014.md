=== intro ===
Day 13 had two pointers walking the same direction - `read` ahead, `write` behind. Today's two pointers start at the **same place** and walk **away from each other**. It closes out week 2 and the Strings topic.

> A palindrome is defined from the outside in ("first equals last, then check the middle"), but it is cheapest to **find** from the inside out. Every palindrome has a center; start there and grow, and you stop the moment growth fails instead of rechecking from scratch.

=== problem ===
Given a string `s`, return its **longest palindromic substring** - the longest contiguous piece of `s` that reads the same forwards and backwards.

```text
s = "babad"   ->  "bab"     ("aba" is also accepted)
s = "cbbd"    ->  "bb"
```

### What the words mean

- **Substring** means contiguous. `"bab"` is a substring of `"babad"`; `"bbd"` (skipping the `a`) is not - that would be a subsequence, and a different problem (LC 516).
- **Palindrome** means `s[l] == s[r]`, `s[l+1] == s[r-1]`, and so on inward until the indices meet or cross.
- **Any** one of the longest answers is accepted.

### The example, every candidate of length 3 or more

| substring | indices | reversed | palindrome? |
| :-------- | :------ | :------- | :---------- |
| `bab` | 0..2 | `bab` | yes |
| `aba` | 1..3 | `aba` | yes |
| `bad` | 2..4 | `dab` | no |
| `baba` | 0..3 | `abab` | no |
| `abad` | 1..4 | `daba` | no |
| `babad` | 0..4 | `dabab` | no |

The longest palindromes have length 3, and there are two of them. Returning either is correct.

### Odd and even palindromes

```text
"bab"   - odd length, center is one character:   b [a] b
"bb"    - even length, center is the GAP between two characters:   b | b
```

This is the detail the whole problem turns on. A solution that only looks for one kind will return `"b"` for `"cbbd"` instead of `"bb"`.

### Constraints

`1 <= s.length <= 1000`, digits and English letters only. `n = 1000` means `O(n^3)` is around `10^9` operations - too slow. `O(n^2)` (`10^6`) is comfortable.

=== pattern ===
**Expand Around Center** - two pointers that start at a center and move **outward**.

It is the mirror image of the opposite-ends two pointers (Valid Palindrome, Two Sum II), where `l` starts at `0`, `r` at `n-1`, and both move inward. Here both start in the middle:

```text
         l <-- center --> r
   b  a  [b]  a  d
      ^       ^
      l       r      s[l] == s[r] -> keep growing
```

### Why it belongs to this pattern

A palindrome is **nested**: strip the first and last character from a palindrome and what remains is still a palindrome with the **same center**.

```text
"racecar"  ->  "aceca"  ->  "cec"  ->  "e"
```

Read the other way: every palindrome is built by starting at a center and adding one matching character on each side, over and over. So instead of asking "is this substring a palindrome?" for `n^2` substrings, ask:

> For each center, how far can I grow before the two sides stop matching?

The first mismatch ends the search for that center - every longer string with the same center contains the mismatch too.

### How many centers

A string of length `n` has `n` character centers (odd palindromes) and `n - 1` gap centers (even palindromes): `2n - 1` in total.

```text
s   =   b   a   b   a   d
odd     0   1   2   3   4          (i, i)
even      0   1   2   3            (i, i+1)
```

### Recognising it

Reach for expand-around-center when:

- the problem says **palindrome** and **substring** (contiguous)
- you need the longest, or need to count them (LC 647 is the same loop with a counter)
- `n` is in the low thousands, so `O(n^2)` is fine

The mental question:

> Does every valid answer grow symmetrically out of some center, so that a failure at one size rules out every larger size?

=== bruteForce ===
Pretend we have not noticed the nesting yet. The definition says: a substring is a palindrome if it reads the same both ways. So check every substring, and keep the longest one that passes.

### Step logic

1. For every start `i` from `0` to `n-1`, and every end `j` from `i` to `n-1`:
2. Check whether `s[i..j]` is a palindrome with two pointers moving inward from `i` and `j`.
3. If it is, and its length `j - i + 1` beats the best so far, record it.
4. Return the best.

### Dry run

```text
s = "babad"     n = 5     best starts empty (length 0)
```

`checks` is the number of character comparisons the palindrome test performed before it answered.

| i | j | substring | checks | palindrome? | length | best after |
| -: | -: | :-------- | -----: | :---------- | -----: | :--------- |
| 0 | 0 | `b` | 0 | yes | 1 | `b` |
| 0 | 1 | `ba` | 1 | no | 2 | `b` |
| 0 | 2 | `bab` | 1 | yes | 3 | **`bab`** |
| 0 | 3 | `baba` | 1 | no | 4 | `bab` |
| 0 | 4 | `babad` | 1 | no | 5 | `bab` |
| 1 | 1 | `a` | 0 | yes | 1 | `bab` |
| 1 | 2 | `ab` | 1 | no | 2 | `bab` |
| 1 | 3 | `aba` | 1 | yes | 3 | `bab` (not longer) |
| 1 | 4 | `abad` | 1 | no | 4 | `bab` |
| 2 | 2 | `b` | 0 | yes | 1 | `bab` |
| 2 | 3 | `ba` | 1 | no | 2 | `bab` |
| 2 | 4 | `bad` | 1 | no | 3 | `bab` |
| 3 | 3 | `a` | 0 | yes | 1 | `bab` |
| 3 | 4 | `ad` | 1 | no | 2 | `bab` |
| 4 | 4 | `d` | 0 | yes | 1 | `bab` |

Answer: `"bab"`. Fifteen substrings, `n(n+1)/2`. Here every check failed or succeeded after one comparison because `"babad"` is short and varied. On `"aaaa...a"` every substring is a palindrome, and every check walks the whole substring - that is where the third factor of `n` comes from.

### Java

```java
class Solution {
    public String longestPalindrome(String s) {

        int n = s.length();
        int bestStart = 0, bestLen = 0;

        for (int i = 0; i < n; i++) {
            for (int j = i; j < n; j++) {
                if (isPalindrome(s, i, j) && j - i + 1 > bestLen) {
                    bestStart = i;
                    bestLen = j - i + 1;
                }
            }
        }

        return s.substring(bestStart, bestStart + bestLen);
    }

    private boolean isPalindrome(String s, int l, int r) {
        while (l < r) {
            if (s.charAt(l) != s.charAt(r)) {
                return false;
            }
            l++;
            r--;
        }
        return true;
    }
}
```

### Why it works

It literally checks every candidate the problem allows, using the definition. Nothing can be missed. The strict `>` keeps the first longest palindrome found, which is why it returns `"bab"` rather than `"aba"`.

### Complexity

**Time:** `O(n^3)` - `n^2 / 2` substrings, each checked in up to `n / 2` comparisons. **Space:** `O(1)` extra (the returned substring aside).

### Where it hurts

Look at what the brute force learns and then throws away. Take `s = "yxabaxz"`. Among its 28 checks are these three, all centered on the `b`:

```text
"aba"        compares a==a                       -> palindrome
"xabax"      compares x==x, then a==a AGAIN      -> palindrome
"yxabaxz"    compares y vs z                     -> fails
```

The check for `"xabax"` re-verifies `a==a`, which the check for `"aba"` already proved. On a long palindrome every level repeats every level inside it.

Two kinds of waste:

1. **Rechecking the inside.** `s[i..j]` is a palindrome exactly when `s[i] == s[j]` and `s[i+1..j-1]` is a palindrome. The brute force never reuses the inner answer.
2. **Not stopping.** Once `"yxabaxz"` fails at its outer pair, every longer string with the same center would contain that failing pair too - in a longer input they could all be skipped, but the brute force tries every one. And it spends checks on substrings like `"xab"` or `"abaxz"` that are not even symmetric around anything that matched.

> If palindromes are nested around a center, build them **from** the center, and stop at the first mismatch.

=== optimization ===
Start at each of the `2n - 1` centers and expand outward while the two ends match.

### The observation

`s[l..r]` is a palindrome if and only if `s[l] == s[r]` **and** `s[l+1..r-1]` is a palindrome. So grow from the inside:

- Start with `l` and `r` on the center - `(i, i)` for odd, `(i, i+1)` for even.
- While `l >= 0`, `r < n` and `s[l] == s[r]`: the window is a palindrome; step `l--`, `r++`.
- The loop stops one step **past** the palindrome on each side. The palindrome is `s[l+1..r-1]`, length `r - l - 1`.

Each step does one comparison and gets one longer verified palindrome - nothing is rechecked. The first mismatch stops the center for good.

### Recovering where the palindrome starts

`expand` returns only the length. For a center at `i` with length `len`:

```text
start = i - (len - 1) / 2
```

| center | len | (len-1)/2 | start | palindrome |
| :----- | --: | --------: | ----: | :--------- |
| odd at 1 in `babad` | 3 | 1 | 0 | `bab` |
| even at (1,2) in `cbbd` | 2 | 0 | 1 | `bb` |
| even at (1,2) in `abba` | 4 | 1 | 0 | `abba` |

Integer division makes the same formula work for both odd and even lengths.

### Dry run on the same example

```text
s = "babad"     n = 5     start = 0, maxLen = 0
```

Each row is one center. "pairs compared" lists every `(l, r)` the loop looked at, with the reason it stopped last.

| i | center | pairs compared | stopped because | len | best after |
| -: | :----- | :------------- | :-------------- | --: | :--------- |
| 0 | odd (0,0) | (0,0) b=b | l = -1 | 1 | `b` (start 0, len 1) |
| 0 | even (0,1) | (0,1) b/a | mismatch | 0 | `b` |
| 1 | odd (1,1) | (1,1) a=a, (0,2) b=b | l = -1 | 3 | **`bab`** (start 0, len 3) |
| 1 | even (1,2) | (1,2) a/b | mismatch | 0 | `bab` |
| 2 | odd (2,2) | (2,2) b=b, (1,3) a=a, (0,4) b/d | mismatch | 3 | `bab` (3 is not > 3) |
| 2 | even (2,3) | (2,3) b/a | mismatch | 0 | `bab` |
| 3 | odd (3,3) | (3,3) a=a, (2,4) b/d | mismatch | 1 | `bab` |
| 3 | even (3,4) | (3,4) a/d | mismatch | 0 | `bab` |
| 4 | odd (4,4) | (4,4) d=d | r = 5 | 1 | `bab` |
| 4 | even (4,5) | none | r = 5 out of range | 0 | `bab` |

Return `s.substring(0, 3) = "bab"`. Count the comparisons: 13 in total, against the brute force's 15 substrings each with its own check. On a short varied string the gap is small; on `"aaaa...a"` it is `n^2` versus `n^3`.

Notice row `i = 2`: the expansion proved `"b"`, then `"aba"`, then failed on `b/d` - and that **one** failure ruled out `"babad"` and anything longer around index 2. The brute force needed a separate check for each.

### Dry run on the even case

```text
s = "cbbd"
```

| i | odd len | even pairs compared | even len | len = max | best after |
| -: | ------: | :------------------ | -------: | --------: | :--------- |
| 0 | 1 | (0,1) c/b | 0 | 1 | `c` |
| 1 | 1 | (1,2) b=b, (0,3) c/d | 2 | 2 | **`bb`** (start 1) |
| 2 | 1 | (2,3) b/d | 0 | 1 | `bb` |
| 3 | 1 | (3,4) out of range | 0 | 1 | `bb` |

Without the even centers the answer would be `"c"` - wrong.

### An intermediate step worth naming

The recurrence `pal[l][r] = s[l] == s[r] && pal[l+1][r-1]` also gives an `O(n^2)` **dynamic programming** table. It is correct, but it stores `n^2` booleans. Expand-around-center visits the same `(l, r)` pairs in the order the recurrence needs them, so it gets the same time with `O(1)` space. Mentioning the DP and then explaining why you do not need the table is a strong interview answer.

=== complexity ===
### Time

`2n - 1` centers. Each expansion runs at most `n / 2` steps.

```text
O(n^2)
```

Worst case `"aaaa...a"`: every center expands to the edge of the string. Typical strings stop after a step or two per center, which is why it is fast in practice.

### Space

A few integers. The returned substring is output, not extra space.

```text
O(1) extra
```

### Comparison

| Approach | Time | Extra space | Notes |
| :------- | ---: | ----------: | :---- |
| Every substring + check | `O(n^3)` | `O(1)` | rechecks the inside every time |
| DP table `pal[l][r]` | `O(n^2)` | `O(n^2)` | 10^6 booleans at n = 1000 |
| Expand around center | **`O(n^2)`** | **`O(1)`** | interview default |
| Manacher's algorithm | `O(n)` | `O(n)` | follow-up; reuses mirror palindromes |

Manacher's is the answer to "can you do it in linear time?". It is rarely expected to be coded in an interview; knowing it exists and that it reuses palindromes mirrored across a known larger one is usually enough.

=== implementation ===
```java
class Solution {
    public String longestPalindrome(String s) {

        int start = 0, maxLen = 0;

        for (int i = 0; i < s.length(); i++) {
            int odd = expand(s, i, i);        // center on a character
            int even = expand(s, i, i + 1);   // center on the gap after it
            int len = Math.max(odd, even);

            if (len > maxLen) {
                maxLen = len;
                start = i - (len - 1) / 2;
            }
        }

        return s.substring(start, start + maxLen);
    }

    // Grow outward while both ends match; return the palindrome's length.
    private int expand(String s, int l, int r) {
        while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) {
            l--;
            r++;
        }
        return r - l - 1;
    }
}
```

### The lines that matter

**1.**

```java
int odd = expand(s, i, i);        // center on a character
int even = expand(s, i, i + 1);   // center on the gap after it
```

Both centers, every index. Forgetting the second line is the single most common bug - `"cbbd"` then returns `"c"`.

**2.**

```java
while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) {
```

The bounds checks come **before** `charAt`. Java evaluates `&&` left to right and stops at the first `false`, so `charAt(-1)` is never called.

**3.**

```java
return r - l - 1;
```

When the loop ends, `l` and `r` have each gone one step too far. The palindrome is `l+1 .. r-1`, whose length is `(r - 1) - (l + 1) + 1 = r - l - 1`. For the even center `(4, 5)` on `"babad"`, the loop never runs and this gives `5 - 4 - 1 = 0` - an empty palindrome, which is correct.

**4.**

```java
start = i - (len - 1) / 2;
```

One formula for both shapes. Integer division absorbs the difference between an odd center (`len - 1` is even) and an even center (`len - 1` is odd).

### Java notes

- `s.substring(start, start + maxLen)` - the second argument is the **exclusive** end, so it is `start + maxLen`, not `start + maxLen - 1`.
- `s.charAt(i)` on a `String` is `O(1)`. Converting to a `char[]` first is a micro-optimisation, not a complexity change.
- `maxLen` starts at `0`, and since `s` has at least one character, the first center always sets it to at least `1`.

=== edgeCases ===
### Single character

```text
"a"  ->  "a"
```

Odd center `(0, 0)` gives length 1. Even center `(0, 1)` is out of range and gives 0.

### Two different characters

```text
"ac"  ->  "a"
```

No palindrome longer than one character. The strict `>` keeps the first one found.

### Two equal characters

```text
"bb"  ->  "bb"
```

Only the even center finds it. This is the minimal test for the gap center.

### All the same character

```text
"aaaa"  ->  "aaaa"
```

The worst case for time - the even center at `(1, 2)` expands to both edges. Even-length answer, start `1 - (4 - 1) / 2 = 0`.

### The whole string is a palindrome

```text
"racecar"  ->  "racecar"
```

The odd center at index 3 expands until both pointers fall off the ends.

### No repeated characters

```text
"abcde"  ->  "a"
```

Every center stops at length 1. The first is kept.

### Palindrome in the middle

```text
"forgeeksskeegfor"  ->  "geeksskeeg"
```

An even-length palindrome of length 10, centered on the gap between the two `s`s.

### The reverse-and-compare trap

```text
"abacdfgdcaba"  ->  "aba"
```

A tempting idea: reverse `s` and find the longest common substring of `s` and its reverse. Here that finds `"abacd"` (it appears in `s`, and `"dcaba"` reversed appears too) - which is not a palindrome. The common substring has to sit at **mirrored positions**, and checking that undoes the shortcut. Expand-around-center has no such trap.

=== takeaway ===
> When you see **"palindrome" + "substring"**, think **expand around center**: `2n - 1` centers, grow outward while the ends match, stop at the first mismatch.

### The core observation

Palindromes are nested around their center: strip the ends and you get a smaller palindrome with the same center. So every palindrome can be found by growing from its center one matching pair at a time, and the first mismatch rules out every larger candidate around that center. That turns "check `n^2` substrings at `O(n)` each" into "grow `2n - 1` centers at `O(n)` each".

### The pattern trigger

```text
          for each index i
                 |
       +---------+---------+
       |                   |
   odd center          even center
    (i, i)             (i, i + 1)
       |                   |
       +---------+---------+
                 |
                 v
   while in bounds and s[l] == s[r]:  l--, r++
                 |
                 v
     length = r - l - 1,  start = i - (len - 1) / 2
```

### The common mistakes

**Only odd centers.** Passes `"babad"`, fails `"cbbd"` and `"bb"`.

**Off-by-one on the length.** The loop overshoots by one on each side. `r - l + 1` is the classic wrong answer - it counts the two mismatched characters.

**`charAt` before the bounds check.** `s.charAt(l) == s.charAt(r) && l >= 0` throws on the first center at index 0.

**Reverse and find the longest common substring.** Fails on `"abacdfgdcaba"`.

### What to remember in six months

> Two pointers can move **inward from the ends** or **outward from a center**. For palindromes, outward wins - it builds each answer from the one inside it instead of rechecking it.

Change one line and the same loop solves Palindromic Substrings (LC 647): instead of tracking the longest, add `1` to a counter on every successful expansion step.
